# ゲート + 再投入はどこまで一般化するか（2026-08-14・gemma4 × aider）

未検証 4 点を追試で潰す。ハーネスは `worker_eval.py` に追加した 7 アーム
（T4min/T4gate/T4blind・T2noat/T2gate/T2blind・T3gate）。

## 問いと答え（先出し）

| 前回の未検証 | 答え |

| 他の定型でも「分解 + ゲート」の形になるか | **ならない。** T4・T2 は一発で天井（各 3/3）。ゲートは一度も発火しなかった |
| 「初回が決定的に同じ壊れ方」は humansize 固有か | **課題固有。** 同型トラップ（0 の単位を省く）の T4 は初回 9/9 で正解。ただし決定性そのものは T3 でも再現した（後述） |

## 新しい知見: 失敗には 2 族あり、ゲートが直せるのは片方だけ

**(a) 仕様の読み違い族**（humansize の KiB 止まり）— 真偽ゲート + 再投入で直る。
前回実測どおり再試行 1 回で 13/13 → 全通過。

**(b) 作業の丸ごと欠落族**（T3 の契約テスト）— **直らない。** T3gate は全 9 attempt が
同一の `C3 fail: 契約テストが追加されていない` で 0/3。診断文は「何が欠けているか」を
毎回明示しているのに、モデルは schema ファイル（C1）だけ作り直してテストを一度も
書かない。過去の一発版 T3（0/3）も 2/3 が同じ C3 fail で、失敗の決定性はここでも
成立している——決定的なのに、再投入では動かない。

ゲートの価値は族で変わる。(a) は**修復**装置として効き、(b) は**検知**装置としてだけ
効く——偽 done を止め、リトライ上限で「この tier では無理」を機械が宣告する。
statemachine 設計への含意: **リトライ上限到達は tier 昇格（クラウドへ回す）のシグナル**
として使う。9/9 が同形で揺れないので、上限は 1〜2 で足りる。

## 成功する課題でゲートは無料

T4gate/T4blind/T2gate/T2blind はすべて 1 call のまま通過した。検査（probe / pytest）は
呼び出し回数を増やさず、壁時計への上乗せは probe 実行の数秒だけ。**「検査を常設して、
落ちた課題だけ再投入」は成功側に課金しない。** 前回の「既に正しい成果物にも 2 倍払う」
懸念は、無条件やり直し方式にだけ当てはまる。

## 測り方

- T4 = `format_duration(n)`（秒 → '1h30m' 形式、0 の単位は省く）。humansize と同じ
  「省略規則トラップ + 仕様例の列挙」構造で、関数とバグ族だけ変えた新課題。
  課題文は `T4_IMPL_GOAL` の 1 本。
- T2 系はゲート付きアームから `--test-cmd/--auto-test` を外し、ハーネスのゲート
  （pytest + テスト改竄検査）だけを検査に残した。ズル検査はチェッカー `check_t2` と
  同じ 2 点を見る（C7）。
- T3gate の argv は一発版 T3 と同一（auto-test・map_tokens 込み）。差はゲートと
  再試行（max_retries=2）だけ。診断はチェッカーの C1/C3 fail 文そのもの。

## 限界

- 各アーム n=3。T4/T2 の「天井」は 3/3 の範囲でしか言えない。
- (b) 族の「直らない」は gemma4:e4b の観測。モデルを上げれば (b) が (a) へ移る
  可能性がある——gemma4:12b の同型比較を後続節で追記する。
- T4 が一発で通った以上、「(a) 族かどうか」は課題ごとに実測するしかない。
  定型を statemachine へ載せる前に 1 度この形で測り、ゲート要否を決める運用になる。

## gemma4:12b との比較

**本番既定の 600s では、12b はコード worker として成立しない。** wall 600 での実測
（`worker/ledger-2026-08-14-code-arms-gemma4-12b-wall600.jsonl`）:

| アーム | e4b | 12b (wall 600) |
|---|---:|---:|
| T4min / T4gate | 3/3・約 60s | 3/3・約 290s |
| T2noat | 3/3・129s | **0/3**（全滅・600s 超過） |
| T2gate | 3/3・145s | **0/3**（再投入 2 回でも各 call が超過） |
| T1（一発） | 1/3 | **0/3**（humansize.py が 0 バイト = 編集適用前に kill） |
| T1gate | 3/3 | **0/3**（5 call × 600s = 3000s 全焼） |

失敗の中身は「できない」ではなく「間に合わない」——T1 の成果物は空ファイル、T2 は
編集適用途中の壊れた関数ヘッダで、いずれも生成が壁時計内に収束していない。ゲートの
再投入は**時間切れ型の失敗には効かない**（同じ上限へ再び走って同じ場所で切られる）。
再投入が救うのは「速く間違える」失敗であって「遅く正しい」失敗ではない。

壁時計の延伸は許容する方針を得たので、wall 1800（`agents.worker.timeout_sec: 1800`
相当）で T2noat/T2gate/T1/T1gate/T3/T3gate を再測中。能力差と速度差の分離、および
e4b が 0/3 だった T3（作業の丸ごと欠落族）を 12b が超えるかはそこで判定する。
