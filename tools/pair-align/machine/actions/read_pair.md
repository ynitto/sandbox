## [read_pair: 相手を読み、前提・制約・自由に分ける]

`.pair-align/work/intent.md` の意図（こうしたい、という変更）を実現する前に、相手のリポジトリがそれについて
何を決めているかを読みます。`.pair-align/work/current.json` にこの側・相手の側・相手のパスが書かれています。

1. 意図に関係する語（機能名・画面や API の名前・用語・見出し）を 3〜8 個選び、相手のリポジトリを探してください。

   ```bash
   python3 .statemachine/pair_align/pair_align.py locate --term "語1" --term "語2"
   ```

   相手のリポジトリに graphify の知識グラフがあれば、コマンドがそれを使って関係するノードをたどります。
2. `.pair-align/work/candidates.md` の候補のうち、意図に関係する箇所を相手のリポジトリで開いて読んでください。
   読むのは候補の前後だけにし、相手のリポジトリ全体を読まないでください。相手のファイルは変更しないでください。
3. 読んだ結果を、`.statemachine/pair_align/templates/reading.md` をひな形に `.pair-align/work/reading.md` へ書いてください。
   見出しは名前も順番も変えず、コメントは本文に置き換えます。

   | 分類 | 入れるもの |
   |---|---|
   | **前提** | 相手が「すでにそうなっている」と定めている事実・決定・既存の振る舞い・用語。こちらはそれを土台にする |
   | **制約** | 相手が「こうしなければならない / してはならない」と課している条件（要件・上限・禁止・互換性・性能・順序） |
   | **自由** | 相手が決めていない、または任せている部分。こちらで決めてよい |

   - 1 項目 1 行の箇条書き。**各項目の末尾に根拠として相手のリポジトリからの相対パス**（`（根拠: docs/api.md#hello）` など）を書く
   - 意図に関係するものだけを書く。無い分類は「- なし」
   - 相手の実装と設計書が述べていることを書く。自分の意図や意見は書かない

**出力形式:** 書き終えたら第 1 行に `OK`、書けなかったら `FAILED` と理由。

この指示に従ってタスクを実行してください。
完了後、指定された形式で出力のみを返してください。次のステップは別途指示されます。
