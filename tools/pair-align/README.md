# pair-align

**実装のリポジトリと設計書のリポジトリを、交互に揃えていくためのステートマシン。**
こうしたい（意図）と伝えると、相手のリポジトリを読んで**前提・制約・自由**に分け、意図と合えば
自分のリポジトリをそのまま直す。合わなければ利用者に確かめ、相手を直す依頼文（そのままエージェントに
渡せるプロンプト）を作り、相手が直ったら波及として自分を直す。

> 設計: [`docs/designs/pair-align-design.md`](../../docs/designs/pair-align-design.md)

- 同じ定義を**両方のリポジトリに置く**。どちらの側か（実装 / 設計書）と相手のパスだけを設定で変える
- 実行は statemachine-use スキル（「pair_align のステートマシンを実行して」）。依存は python3 と git
- 相手のリポジトリを探すとき、[graphify](https://pypi.org/project/graphifyy/) の知識グラフがあれば使う。
  無ければ文字列検索だけで動く
- 相手のリポジトリには**書き込まない**。読むだけ。相手を直すときは依頼文を渡す

## 置き方

```bash
# 実装のリポジトリへ（相手 = 設計書）
python3 tools/pair-align/install.py ~/work/my-app --side impl --pair ../my-app-docs
# 設計書のリポジトリへ（相手 = 実装）
python3 tools/pair-align/install.py ~/work/my-app-docs --side design --pair ../my-app
```

`<リポジトリ>/.statemachine/pair_align/` に定義が入り、`pair.json` に設定が書かれる。
手で置くなら `machine/` の中身をそのフォルダへ写し、`pair.json` を直せばよい。

```json
{ "side": "impl", "pair_path": "../my-app-docs", "graphify": "auto" }
```

| 項目 | 値 |
|---|---|
| `side` | このリポジトリの側。`impl`（実装）か `design`（設計書） |
| `pair_path` | 相手のリポジトリのパス。相対パスはこのリポジトリのルートから。**置き場所が変わったらここを手で直す** |
| `graphify` | `auto`（あれば使う）か `off` |
| `check` | 任意。自分を直したあとに実行する検査コマンドの配列（例: `["python3", "-m", "pytest", "-q"]`）。通らなければ直し直す |

作業ファイル・送り箱・状態は `<リポジトリ>/.pair-align/` に置く（インストーラーが `.gitignore` に足す）。
マシン自身が graphify の索引に入らないよう、`.graphifyignore` にも 1 行足す。
もう一度 `install.py` を実行すると定義とスクリプトだけが新しくなり、`pair.json` はそのまま残る。

## 使い方

エージェントに「pair_align のステートマシンを実行して」と頼む。入れる値は次の 3 つで、どれも任意。

| 入力 | いつ入れるか |
|---|---|
| やりたいこと | 自分のリポジトリで何かを変えたいとき |
| 確認への答え | 前回の実行で確認を求められたとき（相手を直す / 意図を直す / やめる） |
| この版からの変更を見る | 伝える変更の範囲を変えたいとき |

### 相手を読んで、前提・制約・自由に分ける

実装であっても設計書であっても、意図を実現する前に相手の側を読み、関係する記述を 3 つに分ける。
各項目には根拠として相手のファイルのパスを付け、実在しないパスはスクリプトが検査で落とす。

| 分類 | 意味 | 意図とぶつかったら |
|---|---|---|
| 前提 | 相手が「すでにそうなっている」と定めている事実・決定・振る舞い。こちらはそれを土台にする | 利用者に確認 |
| 制約 | 相手が「こうしなければならない / してはならない」と課している条件 | 利用者に確認 |
| 自由 | 相手が決めていない・任せている部分 | こちらで決めてよい |

### 流れ

1. **合う**（前提を崩さず、制約を破らない）→ 自分のリポジトリをそのまま直してコミットする。
   そのあと、相手に伝えるべき変更（自由の範囲で決めたことなど）があれば、相手への依頼文を作る
2. **合わない** → ぶつかっている点・相手に頼むこと・波及してこちらで直すことをまとめて止まる。
   利用者が答えを入れてもう一度実行する
   - **相手を直す** — 相手の前提・制約を変えてもらう依頼文を `.pair-align/outbox/<ID>.md` に作り、反映を待つ
   - **意図を直す** — 直した意図で、相手を読み直す
   - **やめる** — 意図を取り下げる
3. 相手の側では、届いた依頼がそのまま意図になる。相手の側でも同じように自分の側（依頼を出した側）を読んで分け、
   合えば直してコミットする
4. 相手が反映したら、こちらでもう一度実行する。**波及**として、同じ意図で相手を読み直し、自分を直す

```
意図 ─→ 相手を読む ─→ 前提・制約・自由 ─→ 合う? ─ はい ─→ 自分を直す ─→（相手に伝える）
                                              └ いいえ ─→ 利用者に確認 ─→ 相手を直す依頼 ─→ 相手が反映
                                                                                       └→ 波及: 自分を直す
```

届いた依頼と波及を反映するコミットには、スクリプトが `Pair-Align: <ID>` の 1 行を付ける。この行が付いた
コミットは相手への依頼として戻らないので、往復はそこで止まる。手で反映するときも同じ行を付け、
反映と別の変更は**コミットを分ける**（行の付いたコミットは丸ごと数えないため）。

意図を入れずに実行すると、届いた依頼 → 相手の反映が済んだ波及 → コミット済みの変更を相手へ伝える、の順に見る。
相手からの依頼が残っているうちは、自分の変更を送らない（両側が同時に食い違いを抱えないよう、交互に片付ける）。
伝える変更は前回からのコミットで、初回は直前の 1 コミットだけを見る。コミットしていない変更は含めない。

### 手で使うコマンド

ステートマシンを使わずに、スクリプトだけを呼んでもよい（リポジトリのルートで実行する）。

```bash
python3 .statemachine/pair_align/pair_align.py status          # 設定・基準点・未処理の依頼・進行中の意図
python3 .statemachine/pair_align/pair_align.py collect         # 変更を集める（--since REV で範囲指定）
python3 .statemachine/pair_align/pair_align.py locate --term 語 # 相手側を探す（--refresh でグラフ更新）
python3 .statemachine/pair_align/pair_align.py ack <ID>        # 相手の依頼を反映不要として受け取る
```

## graphify を使う

相手のリポジトリで一度 graphify を実行して `graphify-out/graph.json` を作っておくと、
`locate` が語ごとに `graphify query` で関係するノード（見出し・関数・呼び出し元）をたどり、
候補のファイルを絞る。文字列検索も並べて行うので、グラフに入っていない文書も拾う。

- コードのグラフは `locate --refresh`（`graphify update`、LLM 不要）で更新できる
- 設計書の意味的な抽出（Markdown・図など）は graphify のスキルか `graphify extract` で作る
- graphify の導入はリポジトリの `install.py`（外部ツールのセットアップ）でも入る
