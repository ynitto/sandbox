# reverse-spec — 既存のソースから根拠つきの仕様書を起こす

このリポジトリは仕様書を書くための作業場です。ソースは `rspec.json` の `source` にあり、**読むだけで、変えません。**
仕様書を書く・直す依頼は、**必ず `.rspec/rspec.py step` で 1 段ずつ進めます。** ステートマシンの外で
`specs/` を書いたり、検査を飛ばしたりしません。読むだけの質問（どこに何が書いてあるか）にはそのまま答えてかまいません。

## 回し方

```bash
python3 .rspec/rspec.py step            # 今の段の指示を出す（何度出してもよい。会話を新しくしたら、まずこれ）
python3 .rspec/rspec.py step "OK"       # 今の段の出力を渡す（第 1 語は指示の末尾にある語。2 語目から理由を続けてよい）
python3 .rspec/rspec.py status          # 進み具合
python3 .rspec/rspec.py check           # 書いている単位の仕様書を検査だけする（状態は変わらない）
```

- 出た指示どおりに行い、終わったら出力を渡す。検査と遷移はスクリプトが行う
- 検査で落ちて同じ段に戻ったら、**指摘されたところだけ**を直す（最初からやり直さない）
- 単位の分け方の確認（confirm）と、止まったときの相談（stuck）では、利用者に見せて**答えを待つ**。推測して先へ進まない
- `END` が出たら終わり。結果は `extraction/report.md`

## 長い作業のために

- 状態はすべて `.rspec/state.json` と `extraction/` にあり、段を進めるたびにコミットされる。
  会話が長くなった・要約された・新しい会話になったときは、覚えていることに頼らず `step` で今の指示を出し直す
- 1 段で扱うのは 1 つの単位だけ。前の単位の中身を会話に持ち越さない（要るときは `[[SPEC-…]]` の仕様書を開く）
- 長いファイルは指示にある行数ずつ区切って読む。ファイルの全文やコマンドの長い出力を応答に貼らない
- `step` の中で検査が動くので時間がかかることがある。終わるまで待ち、重ねて起動しない

## 守ること

- 根拠はソースのフォルダからの相対パスで `` `パス:行` `` か `` `パス:行-行` `` と書く（バッククォートで囲む）
- 根拠の行から言えないことは書かない。分からないことは `UNKNOWN[blocking|deferred|out-of-scope|undecidable|partial]`
- 検査の結果を自分で覆さない。落ちたら指摘を直すか、`FAILED 理由` で相談の段へ進む
- 検証の段では、使えるなら検証用のサブエージェント `rspec-verifier` に用紙を渡す（書いた本人が判定しない）
- `.rspec/` の中身と `specs/index.md`・`specs/source-index.md`・`extraction/inventory*` は手で直さない
