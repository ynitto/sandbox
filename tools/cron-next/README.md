# cron-next

5フィールドの cron 式から次回の実行時刻を表示する CLI です。Dagu やタスクスケジューラのスケジュール確認に使えます。Python 3.9 以降の標準ライブラリで動作します。IANA タイムゾーンを使うには、実行環境から対応するタイムゾーンデータを参照できる必要があります。

## 使い方

```sh
python3 tools/cron-next/cron_next.py "<cron式>" [--count N] [--from "<ISO日時>"] [--tz <IANA名>]
```

- `--count N` は表示する件数です。既定値は 5 で、正の整数を指定します。
- `--from` は検索の起点です。既定値は現在時刻で、起点より後の実行だけを表示します。UTC オフセットを省略した日時は計算先のタイムゾーンで解釈します。オフセット付きの日時は指定された瞬間を起点にします。夏時間の切り替えで存在しない現地時刻を指定した場合は、移行前の UTC オフセットで解釈します（起点が多少前後することに注意してください）。
- `--tz` は計算と表示に使うタイムゾーンです。既定値はローカルタイムゾーンです。ローカルのゾーン情報を読み込めない環境では現在のローカル UTC オフセットを使います。

```sh
python3 tools/cron-next/cron_next.py "30 7 * * *" --from "2026-11-23T00:00:00" --tz Asia/Tokyo
python3 tools/cron-next/cron_next.py "0 9 * * MON-FRI" --count 3 --tz Asia/Tokyo
```

最初の例では `2026-11-23 07:30 (Mon)` から5日分を表示します。夏時間の切り替えで存在しない現地時刻は飛ばし、同じ現地時刻が2回現れる場合は両方を表示します。

## cron 式

フィールドの順番は「分 時 日 月 曜日」です。`*`、単一値、範囲 `a-b`、ステップ `*/n`・`a-b/n`、カンマ区切りのリストを使えます。月の `JAN`〜`DEC` と曜日の `SUN`〜`SAT` は大文字・小文字を区別しません。曜日番号は 0〜7 で、0 と 7 はどちらも日曜です。

「日」と「曜日」の両方が制限されている場合は OR 条件です。たとえば `0 9 1 * MON` は毎月1日と毎週月曜の9時に実行され、両方に該当する日は1回だけ実行されます。Vixie cron と同様、どちらかのフィールドが `*` で始まる場合（`*/n` を含む）は、両フィールドの展開結果に一致する日が対象です。なお `1-31` のような全範囲の指定は `*` とはみなされず「制限されている」扱いになるため、`0 9 1-31 * MON` は OR 条件になって毎日実行されます。全範囲でも AND 条件にしたい場合は `*/1` のように `*` で始めてください。

## 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 指定件数を表示した |
| 1 | 次の実行時刻が検索期間内に見つからなかった |
| 2 | cron 式またはコマンドライン引数が不正だった |

起点または直前に見つかった実行時刻から、次の1件につき約8年を探索します。これは、2100年のようにうるう年にならない世紀年をまたぐ場合にも2月29日を見つけるためです。途中で次の実行が見つからなくなった場合、表示済みの結果は標準出力に残り、理由を標準エラーに表示します。
