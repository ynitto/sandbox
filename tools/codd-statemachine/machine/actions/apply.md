## [apply: 計画どおりに変える]

利用者は 計画（docs/.plan/current.md）で進めることを承認しました。
**止まったときの利用者の答え（あれば、それに従って変え直す）:** {{choice}}

0. 変えるときに使うスキルを確かめてください。

   ```bash
   python3 .statemachine/codd/codd.py show --phase apply
   ```

   自分を変えるときは「自分」のスキルを、参照先を変えるときはその参照先のスキルを読み込み、その手順に従って変えます。
   計画の「使ったスキルと道具」で変えるときに使うと決めたリポジトリのスキル（`.agents/skills/` など）も使います。
   スキルは、変える前に `python3 .statemachine/codd/codd.py skill 名前`（参照先のものは `参照先の名前:名前` でも可）で
   読み込みます。`.codd/apply.md` に使ったと書いたスキルを、この段で読み込んでいないと検査で落ちます。
   道具（MCP・コマンド）が挙がっていれば実際に使います。スキルか道具が挙がっていれば、使ったものと何をしたかを
   `.codd/apply.md` に `- `名前` — 何をしたか` で書いてください（挙がっているのに無いと検査で落ちます）。
   計画の「守る決まり」に書いた決まりも守ってください。文書の書式（`.codd/formats.md` の見本と見出しの並び）も決まりです。
   文書を変えるときは今の見出しの並び・表の形・言い回しを保ち、新しく足す文書は見本と同じ書式で書きます。
1. 「自分の変更案」を、このリポジトリに適用してください。挙げたファイルはすべて変えます（変え残すと検査で落ちます）。
2. 「参照先の変更案」が「なし」でなければ、そこに挙げた参照先のリポジトリにも適用してください。
   挙げていない参照先には触れないでください。
3. 「影響範囲」に挙げた自分の箇所も、参照先の変更に合わせて直してください（「変更不要」としたものは直さない）。

4. 「テストの変更案」のテストを足し・直してください。コードや仕様書と同じく、挙げたテストはすべて変えます。
   単体テストも API テストもシナリオテストも、コード・仕様書と同じ整合を取る成果物です。ハーネスは実際の変更からも
   響くテストを測り直し、直していないテストがあれば落とします。テストのコマンド（設定の `test`）はハーネスが変えたあとに
   実行します。
5. 検査コマンドが作り直すファイル（仕様書の画像など）を計画に挙げていれば、ここで作り直してください。
   テストの結果を写した文書（`<!-- evidence: id -->` の印）を計画に挙げていれば、テストを動かしてから
   `python3 .statemachine/codd/codd.py evidence --write 文書のパス` で写し直します（参照先の文書は `名前:パス`）。
   目安（`max=`）を超えたときは実装を直します。
   文書に貼った画面の画像は差し替えません（変えたあとの検査でテストの画面が変わっていれば、ハーネスが前の画面を
   貼っている画像を見つけて差し替え、報告します）。

- 計画に無い変更はしない。変えてよいのは、自分は「自分の変更案」と「影響範囲」に挙げたファイル、
  参照先は「参照先の変更案」に挙げたファイルと、「テストの変更案」に挙げたテストだけ（それ以外を変えると検査で落ちる）。
  作業フォルダ（.codd）とこのマシンのフォルダは変えない
- 「今回やらないこと」に書いたものには手を付けない
- コミットはしない（変更の確認とコミットは利用者が行う）

変えたあと、ハーネスが `python3 .statemachine/codd/codd.py verify-apply` で「計画どおりのファイルだけが変わったか」と
設定された検査コマンドを確かめます。参照先を変えたときは、実際の変更から影響範囲を測り直し、
測ったファイルを直したか（または計画で「変更不要」としたか）も確かめます。名前を変えたときは、その名前の
呼び出し元と、その名前に触れている参照先も測ります。変えたファイルとパスでつながった相手の側のファイル、書き足したパスが
実在するか、消したファイルを指したままのところが無いかも確かめます。落ちたら、その指摘を直してください。
計画を変えないと直せない指摘（計画に無いファイルを変える必要がある・「変更不要」とする、など）は、ここで計画を
書き換えずに、直せるところまで直して終えてください。検査が止め、次の手（変え直す・計画を直す・戻す・やめる）を
利用者に提案して確かめます。

**出力形式:** 第 1 行に `OK`（変えた）か `FAILED` と理由。

この指示に従ってタスクを実行してください。
完了後、指定された形式で出力のみを返してください。次のステップは別途指示されます。
