この段では**どのリポジトリも変更しないでください**。読む量は必要な箇所だけに絞ります（下の「読み方」）。

0. **この側・参照先・守る決まり・使うスキルと道具を確かめる。**

   ```bash
   python3 .statemachine/codd/codd.py show --phase plan
   python3 .statemachine/codd/codd.py rule --all
   ```

   - 決まりのファイルは `rule --all` で読み込み、このやりたいことに効く決まりを「守る決まり」に書く。この回で読み込み済みで
     変わっていないものは出し直されない（読み込んでいない・読み込んだあとに変わったものがあると検査で落ちる）
   - 「決まりの候補」が挙がっていれば、関係しそうなものだけ読み、効くなら「守る決まり」に挙げる（設定は変えない）
   - 挙がったスキルは `python3 .statemachine/codd/codd.py skill 名前` で読み込んで従い、道具は実際に使い、
     何を得たかを「使ったスキルと道具」に書く。「リポジトリのスキル」は説明で判断し、関係するものだけ読み込む。
     関係しないものは「`名前` — 使わない: 理由」と 1 行ずつ書く。変えるときに使うスキルもここで決めて書く
   - 挙がっているのに計画に無いもの、使ったと書いたのに読み込んでいないスキルは検査で落ちる
1. **参照先を探す。** やりたいことに固有の語（機能名・API や画面の名前・用語）を 3〜8 個選んで実行します。
   ありふれた語は避けます（一致が増え、扱うファイルが増えるだけ）。

   ```bash
   python3 .statemachine/codd/codd.py explore --term "語1" --term "語2"
   ```

   **読み方:** `.codd/explore.md` には、一致した行がファイルと行番号付きで出ます。まずその行で関係を判断し、
   関係しそうなファイルだけ、その行の前後（見出し 1 つぶん程度）を行番号で範囲を指定して開きます。
   **ファイル全体は読まない**でください。見つかったファイルはすべて、根拠（前提・制約・その他・ずれ）か参照先の変更案に
   挙げるか、その他に `- 関係なし: パス:行, パス:行 — 理由` とまとめて書きます（探さずに書いた計画、扱っていない
   ファイルがある計画は、参照先ごとに検査で落ちる）。語を足して探し直したときは、そのぶんも同じく扱います。
2. **参照先を 3 つに分ける。** 前提（参照先が「すでにそうなっている」と定めていること）・制約（「こうしなければならない /
   してはならない」）・その他（決まっていないこと・任されていること・補足）。
3. **自分の現状と比べる。** 自分の該当箇所を読み、食い違うものを「ずれ」に挙げます。
4. **変更を練る。** 自分の変更案と、ずれがあれば参照先の変更案を書きます。変わる・使う名前（関数・API・用語・見出し）は
   `…` で囲みます。ハーネスはその名前と、変えるファイルとパスで指し合うファイル（注記 `coherence: doc=パス`、
   文書の `…` のパスやリンク）から、呼び出し元・参照先の関係ファイル・響くテスト・文書の書式の見本を測ります
   （`.codd/impact.md`・`trace.md`・`tests.md`・`formats.md`・`evidence.md`）。測ったファイルはすべて計画で扱います。
5. **計画を書く。** ひな形を置き（あれば今の計画を残す）、**見出しごとに**コメントを本文に置き換えます。見出しの名前と
   順番は変えません。1 回の書き込みで全文を書かないでください（応答の長さに上限があるエージェントでは途中で止まります）。
   練り直すときは、直す見出しだけを書き換えます。書いたら検査し、指摘を直します。

   ```bash
   python3 .statemachine/codd/codd.py draft
   python3 .statemachine/codd/codd.py verify-plan
   ```

   - 根拠は `パス:行`・`パス:行-行`・`パス#見出し` で読んだ箇所を指す（参照先が複数なら `名前:パス`）。
     指した行・見出しが無い、前提・制約・その他で `…` に囲んだ名前が根拠のファイルに無いと落ちる
   - 自分の変更案には変えるファイル（テストも）をすべて挙げる。ここと影響範囲に無いファイルは apply で変えられない
   - 影響範囲には測ったファイルをすべて挙げる。直さないものは「変更不要: 理由」
   - **テストもコード・仕様書と同じ成果物。** 足す・直すテストを「テストの変更案」に書く。測ったテスト（`.codd/tests.md`）
     はすべて挙げ、直さないものは「変更不要: 理由」。何かを変えるのに「なし」は認めない
   - **文書の今の書式は決まり。** 変える文書は今の見出しの並び・表の形・言い回しを、新しい文書は同じフォルダの見本の
     書式を守り、見本のパスと守り方を「守る決まり」に書く。見出しを変える・消すなら計画に `## 見出し` と書く
   - `show` に「変えたあとに実行するもの」があれば、その検査で作り直すファイルも挙げる（文書に貼った画面の画像は除く。
     ハーネスが差し替える）。テストで得たもの（`codd.py evidence`）を文書に写すときは `<!-- evidence: id -->` の印で写す
   - 当てはまるものが無い見出しは「なし」（ずれが「なし」なら参照先の変更案と影響範囲も「なし」）
   - **1 回で終わる大きさにする。** 変えるファイルが上限を超えると落ちる。絞って、残りを「今回やらないこと」に書く

**出力形式:** 書き終えたら第 1 行に `OK`、書けなかったら `FAILED` と理由。
