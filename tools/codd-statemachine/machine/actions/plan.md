## [plan: 参照先を読み、変更を練る]

**やりたいこと:** {{request}}
**前回の確認での答え（NG と指摘があれば、それを踏まえて練り直す）:** {{answer}}

この段では**どのリポジトリも変更しないでください**。

0. **この側・参照先・守る決まり・使うスキルと道具を確かめる。**

   ```bash
   python3 .statemachine/codd/codd.py show --phase plan
   ```

   参照先（実装なら設計書、設計書なら実装。いくつあってもよい）の名前とパス、受け持つフォルダ、守る決まりのファイル、
   計画を練るときに使うスキルと道具（MCP・コマンド）、1 回で変えるファイルの上限が出ます。
   - 決まりのファイルはすべて読み、このやりたいことに効く決まりを計画の「守る決まり」に書きます
   - 「決まりの候補」が挙がっていれば、それも読みます。決まりとして効くなら「守る決まり」に挙げます
     （設定に書くかは確認のときに利用者に訊きます。ここでは設定を変えません）
   - スキルが挙がっていれば読み込み、その手順に従って読んだり練ったりします。道具が挙がっていれば実際に使います。
     使った結果（何を得たか）を計画の「使ったスキルと道具」に書きます
   - どちらも、挙がっているのに計画に無いと検査で落ちます
1. **参照先を探す。** やりたいことに関係する語（機能名・API や画面の名前・用語・見出し）を 3〜8 個選んで実行します。
   すべての参照先を探します（`--ref 名前` で絞れる）。graphify があれば、グラフが古いときは自動で作り直してから引きます。

   ```bash
   python3 .statemachine/codd/codd.py explore --term "語1" --term "語2"
   ```

   `.codd/explore.md` の候補を参照先で開き、関係する箇所の前後だけを読んでください。
2. **参照先を 3 つに分ける。** 参照先がやりたいことについて述べていることを、前提・制約・その他に分けます。
   - 前提: 参照先が「すでにそうなっている」と定めている事実・決定・振る舞い・用語
   - 制約: 参照先が「こうしなければならない / してはならない」と課している条件
   - その他: それ以外の関係する記述（決まっていないこと・任されていること・補足）
3. **自分の現状と比べる。** 自分のリポジトリの該当箇所を読み、前提・制約・その他のうち、自分の現状とずれているもの、
   またはやりたいことを実現すると食い違うものを「ずれ」に挙げます。
4. **変更を練る。**
   - 自分の変更案: やりたいことを自分のリポジトリでどう実現するか（ファイルと変更の中身）
   - ずれがあれば、参照先の変更案（ずれを解消するために参照先をどう変えるか）を書きます。
     変わる名前（関数・API・用語・見出し）は `…` で囲んでください。
   - 参照先の変更案を自分のリポジトリに適用したときの**影響範囲はハーネスが測ります**。
     計画を書いたら次を実行し、測ったファイル（`.codd/impact.md` の候補）を影響範囲にすべて挙げてください。
     直すものは直し方を、直さなくてよいものは「変更不要: 理由」を書きます。

     ```bash
     python3 .statemachine/codd/codd.py verify-plan
     ```

5. `.statemachine/codd/templates/plan.md` をひな形に `.codd/plan.md` を書いてください。
   見出しは名前も順番も変えず、コメントは本文に置き換えます。
   - 前提・制約・その他・ずれの各項目は箇条書きにし、末尾に参照先のリポジトリからの相対パスを根拠として書く。
     参照先が複数あるときは `名前:パス`（例: `docs:api/hello.md`）で、どの参照先かを書く
   - 根拠は `パス:行`・`パス:行-行`・`パス#見出し` で、読んだ箇所まで指す。指した行や見出しが無ければ検査で落ちる
   - 前提・制約・その他で `…` に囲む名前は、根拠のファイルに書かれている語をそのまま写す（無ければ検査で落ちる）
   - 自分の変更案には、変えるファイルを（テストも含めて）すべて挙げる。ここと影響範囲に無いファイルは apply で変えられない。
     変わる・使う名前は `…` で囲む。ハーネスはその名前の呼び出し元（自分）と、その名前に触れている参照先のファイルを測り、
     計画が扱っていなければ落とす（参照先のファイルは、読んで根拠に挙げるか、その他に「関係なし: 理由」と書く）
   - 参照先の変更案の各項目も、変える参照先のパス（複数あるときは `名前:パス`）を書く
   - 影響範囲の各項目には、自分のリポジトリの相対パスを書く（測ったファイルが漏れていると検査で落ちる）
   - 当てはまるものが無い見出しは「なし」と書く（ずれが「なし」なら参照先の変更案と影響範囲も「なし」）
   - **1 回で終わる大きさにする。** 変えるファイル（自分の変更案・参照先の変更案・「変更不要」でない影響範囲）が
     上限を超えると検査で落ちる。そのときはやりたいことを絞り、残りを「今回やらないこと」に書く

**出力形式:** 書き終えたら第 1 行に `OK`、書けなかったら `FAILED` と理由。

この指示に従ってタスクを実行してください。
完了後、指定された形式で出力のみを返してください。次のステップは別途指示されます。
