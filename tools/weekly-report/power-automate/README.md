# Power Automate 配信レシピ

週次レポートツールは 2 つの下書きを生成し、GitLab のハブ issue にコメントして引き渡す。本番の配信フローは Outlook での通知メール受信から Teams 投稿と SharePoint 保存まで MS365 内で完結する。SharePoint の Markdown はレビュー用の下書きとして扱う。

## 1. Outlook の通知を受ける

1. ハブ issue の通知を有効にした受信用アカウントを用意する。GitLab が投稿者本人への通知を省くため、コメント用トークンの所有者と別のアカウントで受け取る。
2. Office 365 Outlook の「新しいメールが届いたとき (V3)」で受信トレイまたは専用フォルダーを監視する。GitLab の通知差出人とハブ issue の URL または件名で絞り込む。
3. メール本文から今回追加されたコメントの領域を取り出し、「HTML をテキストに変換」で照合用テキストを作る。実メールで、引用返信や署名より前に対象コメントを切り出せることを確認する。

## 2. 期間と文書を抽出する

先頭の空白を除いたコメントが `[weekly-report: ` で始まる場合だけ処理する。閉じ括弧までの値から開始日と終了日を抽出し、日付として検証する。終了日は集約対象に含まれない。

GitLab の HTML 通知では Markdown の見出しが HTML に変換される場合がある。実際のコメント領域でレベル 1 の見出し「週次レポート」と「リリースノート下書き」の位置を確認し、最初の見出しから次の見出しの直前までを Teams 用、次の見出しからコメント末尾までを SharePoint 用として抽出する。両方の見出しが順に見つかった通知を処理する。

SharePoint 保存用には Markdown の段落、見出し、箇条書き、リンクを維持する。Markdown 原文が届く構成なら該当部分をそのまま使う。HTML 通知なら、抽出したリリースノートの HTML から見出し・箇条書き・リンクを Markdown に戻す（例として `h1` を `# `、`h2` を `## `、`li` を `- `、`a` を Markdown リンクに対応させる）。抽出の境界や HTML の形は実環境から採取したメールに合わせて設定する。

## 3. Teams 投稿と SharePoint 保存

1. Microsoft Teams の「チャットまたはチャネルでメッセージを投稿する」で、週次レポート部分とハブ issue へのリンクを投稿する。HTML の場合はコメントから取り出した週次レポート部分を使用する。
2. SharePoint の「ファイルの作成」で、レビュー用ライブラリに `release-notes-<開始日>_<終了日>.md` を保存する。ファイル内容にはリリースノート部分を渡す。
3. 同じ通知の再処理に備え、ハブ issue と期間をキーに SharePoint の実行記録を検索し、Teams 投稿とファイル保存の成功をアクションごとに記録する。成功済みのアクションは再実行時にスキップする。重複した通知が並列で進まないよう、フローの同時実行数は 1 にする。

差出人の絞り込みと HTML 変換の設定例は既存の [GitLab 通知メールの Power Automate レシピ](../../gitlab-mail-teams/power-automate/flow.md) を参照。
