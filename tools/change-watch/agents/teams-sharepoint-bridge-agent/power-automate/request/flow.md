# 往路フローの組み方

> Power Automate の実機では未確認。動的コンテンツの名前と出力の構造は、自分の環境で確かめて [式](expressions.md) を合わせる。

## 1. Teams のトリガーを設定する

Microsoft Teams の「新しいチャネル メッセージが投稿された場合」で対象チームとチャンネルを指定する。このトリガーはスレッドの親投稿で起動する。[Teams コネクタの仕様](https://learn.microsoft.com/en-us/connectors/teams/#when-a-new-channel-message-is-added)

**トリガーの設定にある「トリガー条件」で、チーム・対象チャンネルと投稿者の許可リストを必ず照合する。** チャンネルの選択に加え、[トリガー条件の式](expressions.md#トリガー条件)を設定する。投稿者は表示名ではなくユーザー ID で照合する。条件で参照できるチャンネル ID と投稿者 ID を返すトリガーを使い、値が欠ける場合は条件を満たさないようにする。投稿文がそのまま Copilot へのプロンプトになるため、誰でも書けるチャンネルは対象にしない。

トリガーの同時実行制御を有効にし、並列度を 1 にする。同じ依頼フォルダに対するこのフローの検索と作成を直列にする。

## 2. 投稿を依頼データにする

| JSON の項目 | Teams の動的コンテンツと変換 |
|---|---|
| `request_id` | メッセージ ID から決定的に生成する |
| `team_id` | チーム ID（例 `channelIdentity.teamId`） |
| `channel_id` | チャンネル ID（例 `channelIdentity.channelId`） |
| `message_id` | メッセージ ID（例 `id`）。元の値を文字列で保存する |
| `author` | 投稿者の表示名（例 `from.user.displayName`）、または取得できる場合は UPN |
| `posted_at` | 作成日時（例 `createdDateTime`）を ISO 8601 に整える |
| `text` | メッセージ本文（例 `body.content`）をプレーンテキストにする |
| `target`（任意） | フローに設定した宛先名。省略時はエージェントの既定の宛先を使う |

本文が HTML の場合は「Html からテキスト」でタグを落とす。メンションは変換後の表示文字列だけを使い、Teams のメンション情報は JSON に渡さない。本文がすでにプレーンテキストならその値を使う。引用符・改行を含む本文も [JSON の組み立て式](expressions.md#依頼-json) にそのまま渡せる。必須項目が空、または本文が 2 万文字を超えるときは作成前に終了する。

`request_id` は例として `tm-` と SHA-256 の先頭 16 桁を連結できる。外部のハッシュ計算を使わない例では、数字だけのメッセージ ID に `tm-` を付ける。どちらも **同じ投稿からは必ず同じ ID とファイル名** を得る。使用する方式はフロー内で固定する。Teams のメッセージ ID は会話内の識別子として扱い、例のようにメッセージ ID 単独で生成する場合は依頼フォルダをそのチャンネル専用にする。

## 3. 同名ファイルを確認してから作成する

1. SharePoint の「ファイルの取得（プロパティのみ）」を `FindRequest` とする。サイトとライブラリを指定し、「フォルダーにエントリを制限」に依頼フォルダを指定する。「入れ子になった項目を含める」は「いいえ」、上位件数は 1、フィルター クエリは [ファイル名の照合式](expressions.md#ファイル名と同名ファイルの検索) を使う。
2. 検索が成功し、結果が 1 件以上なら作成済みとして終了する。検索の失敗時も作成には進まない。
3. 0 件のときだけ SharePoint の「ファイルの作成」を実行する。フォルダのパスは検索と同じ依頼フォルダ、ファイル名は `<request_id>.json`、ファイル コンテンツは [依頼 JSON の文字列](expressions.md#依頼-json) を指定する。

同じ投稿を再実行しても同名ファイルが 1 件であることと、対象外のチャンネル・投稿者からは依頼が作られないことを確かめる。
