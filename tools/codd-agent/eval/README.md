# 影響分析の評価

`impact_eval.py` は、codd-agent の影響分析を変更したときに、取りこぼしと判断の手間を固定した条件で比較する。
自然文の [impact-recall.md](../tests/scenarios/impact-recall.md) をもとに、印刷・プレビューの実装と設計書を固定している。
サンプルのファイルは `impact_eval.py` の `fixture_files()`、独立した正解は `impact_cases.json` に置く。

## 測るもの

初期計画には変更の起点となる 1 ファイルだけを書く。正解は「この依頼で追加の確認が必要なファイル」で、
必ず変更するファイルの一覧ではない。初期計画のファイルは分母から除く。

| 値 | 定義 |
|---|---|
| recall | 正解のうち、計画検査で候補に挙がったファイルの割合。取りこぼしたパスも保存する |
| noise_count | 候補のうち正解に無いファイル数。同じ名前でも意味が違うコードや、今回の変更では調べる必要の無い言及を含む |
| pending_rows | 検査が判断を求めた行の合計。6 ファイルをまとめた行なら 1 件 |
| pending_files | 判断を求めたファイルの重複を除いた数。まとめた行も各ファイルで数える |
| plan_checks | 最初の計画から検査を通過するまでの `verify-plan` の回数 |
| elapsed_seconds | 探索・決まりの読み込み・計画検査・固定した判断役の処理を始めてから、計画検査を通過するまでの秒数。サンプル作成・導入・モジュール読込は含まない |

候補は検査が実際に測った文字列・パス参照・テストの対象と、計画に追加した未判断の対象から集める。
正解のパスを最初から計画に書いて、拾ったことにはしない。ノイズはあくまで固定した依頼と正解に対する値で、
候補として出したこと自体を実装の不具合とは扱わない。

## 再生の条件

- 印刷の識別子の必須化、25 の呼び出し元を持つプレビューの戻り値追加、設計書の表記の確認の 3 ケース。
  最後のケースは実装の名前を変えないため、実装の候補 26 ファイルをノイズとして数える。
- 毎回新しい 2 つの git リポジトリを作り、本物の `init.py` と、配置した `machine/codd.py` の
  `explore` / `guide` / `verify-plan` / `judge` を使う。自分の作業リポジトリは変更しない。
- graphify は off。外部ツールの探索関数を評価プロセス内で無効にし、context-mode も呼ばない。
  モードは `text-and-path`。利用者の git 設定・ホームのスキルを持ち込まず、試行ごとにプロセスも分ける。
- 判断は固定した正解に従う。必要な参照先は根拠に移し、自分の影響先は変更案にし、不要候補は理由を付けて除外する。
  サンプルに無い候補、解決できない検査エラー、5 回以内に通過しない計画は評価の実行失敗とする。
- 検査回数と未判断行数は `.codd/work.json` と照合する。コードの変更・承認・変更後の検査は行わない。
  LLM が何回で正しい計画を書けるかや、人が読む時間は測っていない。

## 基準値と比べる

配布リポジトリのルートから実行する。

```bash
python3 tools/codd-agent/eval/impact_eval.py --output /tmp/codd-impact.json
# 速く確かめるときは各ケースを 1 回ずつ
python3 tools/codd-agent/eval/impact_eval.py --repeat 1
# 同じ環境で、時間が基準値の 1.5 倍を超えた場合も失敗させる
python3 tools/codd-agent/eval/impact_eval.py --max-time-ratio 1.5
```

既定は 3 回。時間だけ中央値を使い、それ以外の測定値・候補パスが試行で一致しなければ失敗する。
ケースごとに比較し、あるケースの改善で別のケースの悪化を相殺しない。基準値は `impact_baseline.json`。
結果の JSON には検出・未検出・ノイズのパス、実装のハッシュ、Python・git・実行環境も残す。

時間は実行環境で変わるので、既定では合否に使わない。時間の倍率を使うときは、比較する前後を同じ環境で測る。
終了コードは 0 が通過、1 が取りこぼし・基準値からの悪化、2 が実行失敗・条件不一致。

## 基準値を更新する

通常の実行やテストは基準値を書き換えない。意図した変更であると確認したあと、明示的に保存する。

```bash
python3 tools/codd-agent/eval/impact_eval.py --write-baseline
# 別ブランチとの比較用に、別の場所へ基準値を保存する
python3 tools/codd-agent/eval/impact_eval.py --write-baseline --baseline /tmp/codd-before.json
python3 tools/codd-agent/eval/impact_eval.py --baseline /tmp/codd-before.json --output /tmp/codd-after.json
```

サンプル・依頼・正解・評価モードが変わった基準値とは比較しない。変更した場合は、正解の妥当性を確認して作り直す。
取りこぼしがある結果は基準値として保存しない。既存の基準値から悪化した数値を更新で受け入れる場合は、差分の理由をレビューする。

## テスト

```bash
python3 -m unittest discover -s tools/codd-agent/tests -p test_impact_eval.py -v
```

3 ケースの再生と基準値との比較に加え、サンプルの呼び出し元から検索語を意図的に消して、計画検査が通っても
取りこぼしとして検出できることを確かめる。ノイズ・判断件数・検査回数・時間の悪化、比較条件の不一致も検査する。
このテストは通常の `unittest discover` と既存 CI に含まれる。
