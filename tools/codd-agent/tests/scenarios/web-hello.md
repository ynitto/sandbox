# 小さな Web 画面と e2e のケース

実装の変更が、単体テストだけでなく e2e のケース（画面の操作と期待を書いた YAML）にも響くかを見る。
2026-10-04 に通し、見つけた不具合を直した（PR #904）。

## サンプル

作業用のフォルダに 2 つのリポジトリを並べて作る。どちらも `main` で始め、作ったものをコミットしてから codd を入れる。

**impl（実装）**

- `src/app.py` — `def hello(): return 1`
- `src/page.js` — `renderHello()` が文字列の HTML `'<h1>Hello page</h1>'` を返す（JSX ではない）
- `tests/test_app.py` — `hello()` が 1 を返すことを確かめる
- `tests/e2e/hello.yaml` — 先頭に `# coherence: doc=docs/api.md` と書いた e2e のケース
- `tests/e2e/page.yaml`・`tests/e2e/top.yaml` — 注記の無い e2e のケース。`/hello` を開いて見出しの文言（`Hello page`）を期待する

**design（設計書）**

- `docs/api.md` — 見出し `## hello` と「hello は 1 を返す。」

`.gitignore` に `__pycache__/` を入れる。

**codd を入れる**: impl は `--side impl --ref ../design --test "python3 -m unittest"`、design は `--side design --ref ../impl`（`tools/codd-agent/init.py`）。

## 1. 新しい関数を足す

**頼むこと**（impl で）: `greet` を足して。

**エージェントの判断**（わざとこうする）: テストの変更案に「変更不要: テストが無い」と書く。

**期待**: 計画の検査が「新しく足す `greet` を確かめるテストが ## テストの変更案 にありません」で止める。
計画に無い公開の関数（`welcome` など）を変える段で足したら、変えたあとの検査が「新しく足した名前を確かめるテストがありません」で止める
（`_inner` のような内向きの名前は数えない）。advise は訊かずにやり直す（AUTO APPLY）。エージェントは `welcome` のテストを足すか、
要らなければ消す。

## 2. 画面の見出しを変える

**頼むこと**（impl で）: `renderHello` の見出しを `Welcome page` に変えて。

**エージェントの判断**: 計画には新しい文言 `Welcome page` だけを書く（古い文言は書かない）。

**期待**

- 注記の無い e2e のケースも、ファイル名が対になるもの（`page.yaml`）は計画の検査で「響くテスト」に挙がる（`.codd/tests.md` が「なし」にならない）
- 見出しの文言を変えたあと、その文言を期待している `top.yaml` が「文字列」で響くテストに挙がり、直すまで通らない。
  直せば、計画に無くても「計画に無いファイル」で止めずに通る（「追加」の申告も、利用者の承認も要らない）。報告には「直した」と出る

## 3. 設計書の側から説明を直す

**頼むこと**（design で）: `hello` の説明に補足を足して。

**期待**: 1 回目の計画の検査で、実装のテスト（`tests/test_app.py`・`tests/e2e/hello.yaml`）が「参照先のその他」ではなく
「テストの変更案」に「未判断」として入る。直すと決めたら、変えたあとの検査が実装の e2e のケースを変えたかを確かめ、
実装の側の `test` も動かす（直すときは `hello.yaml` のケースの題に補足を足す）。報告は、実装の側を「なし」と書かず、
テストだけ変えたと書き、テストに `impl:` を付ける。
