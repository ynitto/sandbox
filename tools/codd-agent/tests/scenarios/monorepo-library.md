# 1 つのリポジトリにコードと文書があるライブラリ

TypeScript のライブラリで、コード（`src/`・`tests/`）と文書（`docs/`）が同じリポジトリにある。広い改名の段分け、
機能の削除、途中でやめて戻す、受け持ちの外（CI の設定）に名前が出てくる場合を見る。

## サンプル

1 つのリポジトリを `main` で作り、コミットしてから codd を入れる。テストは node:test（`node --test`）で、TypeScript は
`tsc` を使わず、`.js`（ES モジュール）で書いてよい。

- `src/` — 日付と金額の小さな関数を 12 ファイルほどに分けて置く。どのファイルも共通の設定 `src/config.js` の
  `defaultLocale`（既定 `"ja-JP"`）を import して使う。`src/legacy/formatV1.js` は旧い呼び方の互換（`formatMoneyV1`）
- `tests/` — `src/` のファイルごとにテスト（`*.test.js`）。いくつかは `defaultLocale` を直接読む
- `docs/` — `docs/guide/*.md`（使い方。関数ごとに 1 本、`defaultLocale` を説明する）、`docs/adr/0001-locale.md`（決めたことの記録）、
  `docs/guide/migration.md`（旧い関数から移る案内。パスは書かず、名前 `formatMoneyV1` だけを書く）
- `.github/workflows/ci.yml` — `DEFAULT_LOCALE: ja-JP` を環境変数で渡す行と、`defaultLocale` に触れたコメント
- `CLAUDE.md` — 関数は 1 ファイル 1 つ。公開する関数は `docs/guide/` に書く

**codd を入れる**: `--side impl --scope src --scope tests --ref docs=. --ref-scope docs=docs --test "node --test tests/**/*.test.js"`
（node 22 は glob を自分で展開する。codd はシェルを通さずに動かす）。`codd.json` の `protect` に glob で `docs/adr/*.md` と `src/legacy/**` を書き、`no_doc` に `src/legacy/**` を書く（互換のコードは文書を名前でしか指さない）。

シナリオは順に流す（前のシナリオで変えてコミットした状態から続ける）。

## 1. 設定の名前を変える（広い改名）

**頼むこと**: `defaultLocale` を `fallbackLocale` に改めて。旧い名前は残さない。

**利用者の答え**: `docs/adr/` は変えない（決めた当時の記録なので）。`src/legacy/` の import も直してよい。

**期待**

- 変えるファイルが 10 を超え、段に分かれる。段ごとに `batch` がその段のファイルだけを示し、最後の段のあとに全体の検査とテストが動く
- ADR は（glob の `docs/adr/*.md` で）「人の承認が要るファイル」として確認に出る。退けたら「今回やらないこと」へ回す。ADR に旧い名前が残っても、
  消した名前の残りとして止めない（今回やらないことに挙げたので）
- import を改めただけのファイルと、ファイル名が対になるテスト（`src/formatMoney.js` と `tests/formatMoney.test.js`）は「未判断」として
  書き足される。広い改名ではまとめて「変更不要」と判断する（ファイル名の対は、仕様書とテストを対にしたい場面があるので残す）
- 既定値の `defaultLocale` を改めただけの関数（`formatMoney(amount, locale = defaultLocale)`）の名前で、題に関数の名前を書いただけの
  テストを響くテストにしない
- 受け持ちの外の `.github/workflows/ci.yml` のコメントに変わる名前が出てくることを、計画の検査が止めずに知らせ、確認（`summary`）にも出す
  （環境変数 `DEFAULT_LOCALE` は綴りが違うので当たらない）
- 文書の要らないコード（import を改めただけの `src/legacy/formatV1.js` に文書が無い）は、「今回やらないこと」にパスを書き、
  `no_doc` に足すことを勧めれば、文書を求めて止めない
- 報告は、同じリポジトリの参照先（docs）を「テストを動かしていない」と書かない（自分のテストで動いた）
- 確認で退けて「今回やらないこと」に挙げた ADR を、検査し直したときに「未判断」として書き足さない

## 2. 旧い互換の関数を消す

**頼むこと**: `formatMoneyV1` を消して（使っているところはもう無い）。文書とテストからも消す。

**利用者の答え**: `src/legacy/` を消すのは承認する。

**期待**

- 消すファイルも「変えるファイル」として計画に挙げ、承認したうえで消せる
- 計画で `docs/guide/migration.md` を挙げ忘れても、計画の検査が名前で当たった「未判断」として書き足すので、挙げ忘れたまま進まない。
  それを「関係なし」と判断して進めると、変えたあとの検査が、消した名前 `formatMoneyV1` をまだ書いていることで止まり、利用者に訊く。
  計画に挙げて消せば通る（消した文書が `…` で触れていただけの移る先 `formatMoney` を、変わった名前として測らない。消した文書の見出し `## ロケール` なども語にしないので、題に「ロケール」と書いたテストを響くテストにしない）
- 消すと書いた文書（`docs/guide/migration.md`）を、書式の見本として「従う手順」に書き足さない
- 「`src/legacy/formatV1.js` — ファイルを消す（`formatMoneyV1` を消す）」は、名前を添えてもファイルを消す行と読む（文書を求めない）

## 3. 途中でやめて戻す

**頼むこと**: 金額の丸め方を四捨五入から切り捨てに変えて。

`codd.json` の `batch_files` を 2 にして段に分ける。

**エージェントの判断**: テストの変更案に「`Math.floor` — 変更不要: 標準の関数で、`roundMoney` のテストで確かめる」と書く（理由に `…` を含む）。

**利用者の答え**: 変える段で 1 段目を変えたあと、気が変わったので止める（段の途中でも `decide STOP`）。変えた分は戻す（`rollback`）。

**期待**: 確認の段でやめたときは、報告が「利用者がやめた（まだ何も変えていない）」と書く。理由に `…` を含む「変更不要」の行も、変更不要と読む。`rollback` でこの回の変更だけが戻り、前のシナリオのコミットは残る。報告と計画の記録は「利用者がやめた（変えた分は戻した）」
と書き、やり直しを促さない。変えていないファイルもテストも「変えていない（やめた）」と書く。前の回の測定（影響範囲・響くテスト）を混ぜない。もう一度同じことを頼めば最初から計画できる。

### 3b. ステージした段を中止して戻す

2026-10-24 の再生で、3 の1段目を変えて `git add` したあと、`decide STOP` → `step "FAILED 利用者がやめた"` →
`rollback` → `step "STOP 変えた分は戻した"` と進める。

**期待**: 作業ツリーだけでなくステージも変える前へ戻る。`git diff --cached` に中止した段の変更が残らない。
計画の前からステージしていた内容と、未ステージの内容が別々なら、それぞれを保つ。作業ツリーの内容を変えずに
ステージだけを変えたファイルも戻す。同じリポジトリの `src/` と `docs/` の両方で確かめ、受け持ちの外のステージは触らない。
報告は「利用者がやめた（変えた分は戻した）」で、次の依頼を新しく始められる。

修正前は作業ツリーだけを戻し、`git status --short` に `MM` が残って、中止した変更がコミット可能だった。
変える前の印にステージのモードと blob を保存し、戻すファイルごとにその時点のステージへ復元するようにした。

## 4. 新しい関数を足す（全文検索）

参照先の変更案に「`docs:docs/guide/formatPercent.md` — … `docs/guide/formatNumber.md` に倣って書く」と書いても、変えるのは
`—` より前の `formatPercent.md` だけ（倣う見本の `formatNumber.md` を段に入れない）。

context-mode を入れた端末で、サンプルを作り直して流す（2026-10-18。PR #973）。

**頼むこと**: 割合を百分率で返す `formatPercent` を足して。

**期待**

- explore の詳細の「全文検索（context-mode）」に `docs/` の節だけが出る（自分の `src/`・`tests/` や `.statemachine/` は出ない）。
  同じリポジトリを scope で分けた自分と参照先は、別の索引になる
- impact では、自分の受け持ち（`src`・`tests`）に文書が無いので、全文検索の節を出さない（毎回「該当なし」を並べない）
- context-mode が無い、または索引を作れない（ネイティブの部品が壊れているなど）ときは、詳細だけでなく explore / impact の出力にも
  `全文検索:` の 1 行で知らせる。文字列検索だけで先へ進む

**続けて頼むこと**: `formatPercent` の小数を 1 桁にして（テストを 60 件足し、1 件だけわざと落とす）。

**期待**: 変えたあとの検査は落ちたテストの行と末尾だけを示し、全文は `.codd/logs/` に残す。示した 1 行のとおり
`context-mode search` で落ちたテストの節を引ける（語は `AssertionError` などの失敗の印）。同じテストが何度落ちても、索引に同じ節が重ならない。
落ちたあとにテストのほうを直すと、訊かずには進めず「検査が落ちたあとに、テストのファイルを変えています」で利用者に訊く。認めれば（`accept`）進む

## 5. 受け持ちの外のファイルを今回やらないことに回す

1 で、`.github/workflows/ci.yml` を「今回やらないこと」に書いてから `summary` を見る。2026-10-20 に通した。

**期待**: 確認（`summary`）に「受け持ちの外で、変わる名前が出てくるファイル」として、もう挙げない（計画で扱ったので）。

## 2026-10-24 に回し直して直したもの

- 3 で、段の途中で `decide STOP` してから `step "FAILED 利用者がやめた"` を渡すと、変えたあとの検査が「確かめていない計画で変えました」で
  止め、`PLAN` を勧めた。報告にも、やめた回に測った影響範囲と検査の回数が混じった → やめた答えがあれば変えたあとの検査は測らず、
  「変えた分を戻してやめる」「やめる」だけを示す
- 4 の続きで、同じテストが同じように落ちても、所要時間（`duration_ms`）が違うだけで別の指摘と数え、訊かずに 2 回目をやり直した
  → 所要時間と全文のログの名前を除いて比べる
- 振る舞いの変化: 新しい関数の仕様（この回で書く `formatPercent.md`）を根拠にできなかった → 変更案に挙げた文書は根拠にできる。
  node のテストは失敗の行にファイル名が出ず、変える前の中身で落ちても「確かめられなかった」になった → 入れずに動かした出力との差で見る。
  ファイルごと読み込めずに落ちたものを「落ちた」と言っていた → 読み込みの失敗は「確かめられなかった」

## 直していないもの

- 新しく作るファイルの行で `…` に囲んだ、使うだけの既存の名前（`fallbackLocale`）も、変わる名前として測る（計画の書き方が「変わる・使う名前」を囲むため）
- 響くテストは、変わる名前を書いているかで探す。import だけしていて変わる名前を書いていないテストは挙げない
  （そうしたテストが壊れても、変えたあとにテストを動かすので落ちて分かる。言語ごとに import をたどる仕組みは足さない）
- 「…に倣って書く」と挙げた見本の文書（`docs/guide/formatNumber.md`）も、前の回に見つけたつながりとして残り、次の回に「未判断」に出る
- 報告の「手間」の変えたあとの検査の回数は、段の途中で続きを返した回を数えない（途中でやめて戻すと 0 回と出る）

- 振る舞いの変化の根拠が、同じ回で消えた・見出しが変わったときに知らせない（記録の根拠が古くなる）
- 名前を消すだけの回の「確かめる」に向くテストが無いことがある（残った export を確かめるテストを挙げる）
