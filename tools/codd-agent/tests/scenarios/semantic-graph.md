# 文書の意味まで入れたグラフで影響を測る

LLM が読んだ文書のつながりを足したグラフで、取りこぼしが減り、ノイズ（要判断に出るもの）が増えすぎないかを見る。
2026-10-10 に、本物の graphify（0.9.84）と手で書いた束の結果で 1・2 の検査の部分を通した。0.85 と 30 の線は、このシナリオで
拾えた数と要判断の数を比べて決め直す。

## サンプル

作業用のフォルダに 2 つのリポジトリを並べて作る。どちらも `main` で始め、作ったものをコミットしてから codd を入れる。

**impl（実装）**

- `src/tax.py` — `def calc_tax(price):` 税込みの額を返す
- `src/app.py` — `calc_tax` を呼んで請求額を出す
- `tests/test_billing.py` — `app` の請求額を確かめる
- `docs/notes.txt` — 「請求の端数は税の計算のあとで丸める」とだけ書いた運用メモ（関数名は書かない）
- `e2e/checkout.yaml` — 請求画面の e2e のケース。金額の表示を期待する（関数名は書かない）
- `README.md` — すべてのファイルを並べた索引（つながりの多いノードになる）

**design（設計書）**

- `docs/tax.md` — 見出し `## 税の計算` と「`calc_tax` は税率を掛けて切り捨てる。」
- `docs/glossary.txt` — 用語集。「税」「請求」などの語が並ぶ

**codd を入れる**: impl は `--side impl --ref ../design --test "python3 -m unittest"`、design は `--side design --ref ../impl`。
どちらの `codd.json` も `"graphify": {"semantic": "session"}`、impl は `"subagent": true`。

## 1. 初めてグラフを用意する

**頼むこと**（impl で）: `calc_tax` の丸めを四捨五入に変えて。

**期待**

- plan の初めの `codd.py graph` が `PENDING` を返し、impl と design の文書を束に分けて出す。束は `codd-graph` に 1 つずつ渡り、
  codd の会話に文書の全文が積まれない。`graph --merge` が `OK` を返すまで、explore に進まない
- `graph` を飛ばして計画を書くと、計画の検査が「意味のグラフを、この回にまだ用意していません」で止め、訊かずにやり直す
- 計画の検査で、影響範囲は次のとおりに分かれる（`.codd/impact.md` の「グラフ（根拠の強さごと）」）
  - 明示: `src/app.py`・`tests/test_billing.py`、参照先の `design:docs/tax.md`（文書に `calc_tax` と書いてある）
  - 要判断: `docs/notes.txt`（LLM が「丸め」で `calc_tax` に結びつけた推定）。計画に無ければ「未判断」として理由付きで書き足される
  - 参考: `e2e/checkout.yaml`（推定の 2 歩目）、`docs/glossary.txt`（似ているだけ）。検査には出ない
- `README.md` は候補に挙がってもよいが、そこからほかのファイルへは広がらない

**エージェントの判断**: `docs/notes.txt` は「変更不要: 丸めの順は変わらない」とする。

## 2. 同じ名前をもう一度変える

**頼むこと**（impl で）: `calc_tax` に税率の引数を足して。

**期待**

- `graph` は、前の回から変わっていない文書を読み直さない（`OK` をすぐ返す）
- `docs/notes.txt` は、前の計画で「変更不要」とし、その後変わっていないので、要判断ではなく参考に下がる（「前の計画で判断済み」）
- 1 のあとで `docs/notes.txt` を書き換えてから頼むと、そのファイルだけが束に出て、要判断に戻る

## 3. 設計書の見出しを変える

**頼むこと**（design で）: `## 税の計算` の説明に、端数の扱いを足して。

**期待**: 変えたあとの検査が、変えた行に重なる見出しから辿り、実装の `src/tax.py` を明示として挙げる。
用語集に「税」があっても、そこからは辿らない（語ではなく変えた箇所から辿るため）。
