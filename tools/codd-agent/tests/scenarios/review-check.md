# 確かめる（codd-review）のケース

「チェックして」で本流ではなく確かめるステートマシン（`.statemachine/codd-review/workflow.yaml`）を回し、漏れ・矛盾・
設計の不備を項目と自由レビューで挙げ、何も直さないことを見る。次の計画を立てておき、本流が引き継げることを見る。2026-10-17 に `codd.py review` を順に動かして確かめた（PR #971）。

## サンプル

作業用のフォルダに 2 つのリポジトリを並べて作る。どちらも `main` で始め、作ったものをコミットしてから codd を入れる。

**impl（実装）**

- `src/app.py` — `def hello(): return 2` と、`def bye(name): return name`
- `tests/test_app.py` — `hello()` が 2 を返すことを確かめる（`bye` のテストは無い）。`tests/__init__.py` も置く（無いと `python3 -m unittest` が 1 件も見つけず落ちる）

**design（設計書）**

- `docs/api.md` — 見出し `## hello`、「`hello` は 1 を返す。`goodbye` もある。」、「実装は `src/app.py`。」

**codd を入れる**: impl は `--side impl --ref ../design --test "python3 -m unittest"`、design は `--side design --ref ../impl`。
入れたあと、impl の `src/app.py` で `hello` の戻り値を 2 に変えて、codd を通さずにコミットする。

## 1. 範囲を挙げずにチェックする

**頼むこと**（impl で）: 実装・テスト・文書に漏れや矛盾がないかチェックして。

**エージェントの判断**: 本流の計画は書かず、`codd-review` を `target` 空で回す。項目には `review next` で 1 件ずつ答える。

**期待**

- start で先に `graph` を回し（graphify が無ければその旨で先へ進む）、`lint` を動かし、直近 7 日に変わった両側のファイル（`src/app.py`・`tests/test_app.py`・`docs/api.md`）から項目を出す
- 項目に `hello` の矛盾（コード・文書・テストの箇所を並べて示す）、`bye` の漏れ（文書とテスト）、文書だけにある `goodbye` の漏れ、
  `src/app.py` の設計の不備、テストのファイルの確かめ漏れが入る
- 示されていない項目に先に答える・項目に無いファイルの行を根拠にする・問題に「やりたいこと」を添えない、のどれでも
  items の検査で止まり、指摘の行だけを直せば通る
- 設計の項目があるのに守る決まりを読んでいなければ止まる（守る決まりが無いサンプルでは止まらない）
- free で `## 自由レビュー` が無ければ止まる。無いなら「なし: 見た範囲と理由」で通る
- report が `hello` の戻り値を合わせるやりたいことを挙げ、「codd を通らずに入った変更を確かめたい」は本流に渡さない
  （このレビューで確かめたため）。どのファイルも変わっていない

## 2. 機能の名前でチェックする

**頼むこと**（impl で）: `bye` まわりの設計に不備がないか見て。

**エージェントの判断**: `impact --term bye` と `explore --term bye` で関係するファイルを探し、`--path src/app.py` で始める。

**期待**: 項目は `src/app.py` と、そのパスを書いた `docs/api.md` から出るものだけになる（テストは示す箇所に添えるだけ）。直してと言われたら、report の「やりたいこと」の行を依頼にして
本流（`.statemachine/codd/workflow.yaml`）を始める。

## 3. 次の計画を立てておき、あとで進める

**期待**（1 の回の続き）

- ahead が `hello` の戻り値を合わせるやりたいことから、計画を 1 つ `.plans/next/` に立てる（`draft --ahead`）。
  どちらに合わせるか利用者が決めるもの（「確かめる」と書いたもの）も、根拠の強いほうに合わせる案で立てる（確認で決める）。立てた計画は進めている計画にならず、
  `.codd/run-start.json` も残らない
- 同じ依頼をもう一度しても、同じやりたいことの計画は増えない（`next --verify` が重なりを止める）

**頼むこと**（impl で、あとから）: 次にやることは？ → 次の計画を進めて。

**期待**: `codd.py next` の一覧を見せる。進めると、本流の計画の段が `draft --next` で引き継ぎ、読み込み・探してから
検査に出し、確認を経てから変える。立てたあとに `src/app.py` を変えていれば、`draft --next` が「立てたあとに変わったファイル」に挙げ、
エージェントはそこを読み直して計画を直す（2026-10-17 の再生で、検査が何も言わずに通ったので足した）。

## 4. しばらく変更の無いリポジトリで確かめる

**サンプル**: 1 と同じものを、どちらの側も 60 日前のコミットだけにして作る（作業中のファイルも無い）。

**頼むこと**（impl で）: 手入れして。

**期待**: 直近 7 日・30 日には変わったファイルが無いので、90 日まで遡って項目を出す（`review start` の出力に「範囲: 直近 90 日に変わったもの」）。
期間を挙げて頼んだときは遡らず、見るものが無ければそう伝えて終える。
