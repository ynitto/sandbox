## [apply: 計画どおりに変える]

利用者は 計画（`.plans/` の、結果がまだ無い計画）で進めることを承認しました。
**止まったときの利用者の答え（あれば、それに従って変え直す）:** {{choice}}

**検査の指摘で戻ってきたとき（この指示の後ろに検査の出力が付いているとき）は、指摘されたところだけを直してください。**

0. 今の段で変えるファイルと、計画のそのファイルの項目・参照先の制約、変えるときに使う手順を確かめてください
   （`batch` が出します。計画のファイルは開かなくてよい）。

   ```bash
   python3 .statemachine/codd/codd.py batch
   ```

   `batch` が「サブエージェントに渡す」と示したら、その指示どおりに渡し、返った第 1 行を出力にして終えます（以下は行いません）。
   示さなければ、続けて `python3 .statemachine/codd/codd.py show --phase apply` を実行し、以下のとおり自分で変えます。

   **計画のファイルが多いときは、段に分けて変えます。** `batch` が示した今の段のファイルだけを、計画の該当する項目の
   とおりに変え終えてください（以下の 1〜5 も、今の段に入っているファイルについて行います）。前の段は変え終えています。
   あとの段のファイルにはまだ手を付けません。段を変え終えると、ハーネスがその段のファイルを変えたかを確かめ、
   次の段でこのアクションを呼び直します。テストと検査コマンドは最後の段のあとにまとめて動きます。

   自分を変えるときは「自分」のスキルを、参照先を変えるときはその参照先のスキルを読み込み、その手順に従って変えます。
   計画の「従う手順」で変えるときに使うと決めたリポジトリのスキル（`.agents/skills/` など）も使います。
   設定されたスキルと、変えるファイルに決められた手順は `batch` が出し、`.codd/apply.md` に手順ごとの行のひな形
   （名前と当たるファイル）を置きます。変えたら、その行の「（何をしたか）」を書き換え、「確かめること」の `- [ ] 項目` を
   `- [x] 項目 — 根拠` か `- 該当なし: 項目 — 理由` にします。それ以外のスキルは、変える前に
   `python3 .statemachine/codd/codd.py guide 名前`（参照先のものは `参照先の名前:名前` でも可）で読み込み、
   `- `名前` — 変えたファイル: 何をしたか` の行を足します。使ったと書いたスキルを、この回で読み込んでいないと検査で落ちます。
   道具（MCP・コマンド）が挙がっていれば実際に使い、`- `名前` — 何をしたか` を書きます
   （手順に従わなかったファイルがあると、手順と差分を並べた `.codd/skill-review.md` が作られて検査で落ちます。
   そのときは見比べて合わない箇所を直してから書きます）。
   計画の「従う手順」に書いた決まりも守ってください。文書の書式（`.codd/formats.md` の見本と見出しの並び）も決まりです。
   文書を変えるときは今の見出しの並び・表の形・言い回しを保ち、新しく足す文書は見本と同じ書式で書きます。
   計画で、文書の無いコードのために作る・足すとした文書には、本文にそのコードのパスを `…` かリンクで書きます
   （書かないと、コードと文書がつながらず検査で落ちます）。
1. 「自分の変更案」を、このリポジトリに適用してください。挙げたファイルはすべて変えます（変え残すと検査で落ちます）。
2. 「参照先の変更案」が「なし」でなければ、そこに挙げた参照先のリポジトリにも適用してください。
   挙げていない参照先には触れないでください。
3. 「影響範囲」に挙げた自分の箇所も、参照先の変更に合わせて直してください（内部の検査記録で変更不要と判断したものは直さない）。

4. 「テストの変更案」のテストを足し・直してください。コードや仕様書と同じく、挙げたテストはすべて変えます。
   単体テストも API テストもシナリオテストも、コード・仕様書と同じ整合を取る成果物です。ハーネスは実際の変更からも
   響くテストを測り直し、直していないテストがあれば落とします。新しく足した関数・型・見出しを確かめるテストが無くても
   落とします。テストのコマンド（設定の `test`）はハーネスが変えたあとに実行します。
   対応表があるときはケースと個別テストの対応も更新します。仕様変更は計画した根拠に合わせ、リファクタでは期待結果を変えません。
   プロジェクトが指定するケースの変換・点検・一覧生成を行い、生成物の入力元を保ちます。
   失敗を通すための期待値変更・削除・skip は行わず、仕様とテストのどちらが誤っているかを根拠から確かめます。
   静的な重複・統合候補を直す場合も、値の違うケースや別の検証層を自動で削除しません。
   表形式へ移した各行を個別のケースとして残し、計画した期待結果・対応・実行結果を確かめます。
5. 検査コマンドが作り直すファイル（文書に貼る図など）を計画に挙げていれば、ここで作り直してください。
   テストの結果を写した文書（`<!-- evidence: id -->` の印）を計画に挙げていれば、テストを動かしてから
   `python3 .statemachine/codd/codd.py evidence --write 文書のパス` で写し直します（参照先の文書は `名前:パス`）。
   目安（`max=`）を超えたときは実装を直します。
   テストが作ったファイルの写し（文書に貼ったものなど）は差し替えません（変えたあとの検査でテストの出力が変わって
   いれば、計画が見込んだ分だけハーネスが前の版の写しを見つけて差し替え、報告します）。

- 計画に無い変更はしない。変えてよいのは、自分は「自分の変更案」と「影響範囲」に挙げたファイル、
  参照先は「参照先の変更案」に挙げたファイルと、「テストの変更案」に挙げたテストだけ（それ以外を変えると検査で落ちる）。
- 変えていて計画と違うことになったら、計画は直さずに `.codd/apply.md` の `## 計画との違い` に 1 行ずつ書く:
  計画のファイルや響くファイルを変えなくてよいと分かったら `- パス — 変更不要: 理由`、計画に無いファイルも変える必要が
  出たら `- パス — 追加: 理由`（参照先のファイルは検査の出力と同じ書き方）。計画で挙げていないファイルの追加は、
  検査が利用者に確かめる。変えて使った名前が、関係の無いファイル（参照先・自分・テスト）にも同じ綴りで出てくるだけなら
  ``- `名前` — 関係なし: 理由``（ファイルごとなら `- パス — 関係なし: 理由`）。触れているファイルの該当行を読んでから書く
  作業フォルダ（.codd）とこのマシンのフォルダは変えない
- 「今回やらないこと」に書いたものには手を付けない
- 人の承認が要るファイル（`show` に出る）は、確認で承認された計画に挙げたものだけを変える。影響を受けると
  分かっても、計画に無ければ変えない（検査が止めて利用者に訊く）
- コミットはしない（変更の確認とコミットは利用者が行う）

変えたあと、ハーネスが `python3 .statemachine/codd/codd.py verify-apply` で「計画どおりのファイルだけが変わったか」と
設定された検査コマンドを確かめます。参照先を変えたときは、実際の変更から影響範囲を測り直し、
測ったファイルを直したか（または計画で「変更不要」としたか）も確かめます。名前を変えたときは、その名前の
呼び出し元と、その名前に触れている参照先も測ります。変えたファイルとパスでつながった相手の側のファイル、書き足したパスが
実在するか、消したファイルを指したままのところが無いかも確かめます。落ちたら、その指摘を直してください。
計画を変えないと直せない指摘（計画に無いファイルを変える必要がある・「変更不要」とする、など）は、ここで計画を
書き換えずに、直せるところまで直して終えてください。検査が止め、次の手（変え直す・計画を直す・戻す・やめる）を
利用者に提案して確かめます。

**応答:** `caveman` の full で短く（利用者が解除したら従う）。待機中の実況はしない。`summary`・`record` の出力と出力形式は省かず、変えない。
**待ち方:** 長いコマンドは終わるまで待つ（非同期なら最初 30 秒、以後 60 秒おき）。重ねて起動せず、終了コードで判断する（詳しくはエージェント定義の「長いコマンドの結果待ち」）。

**出力形式:** 第 1 行に `OK`（変えた）か `FAILED` と理由。
