## [confirm: 計画を利用者に確認する]

次を実行し、出た計画のパスを利用者に示して、開いて読んでもらい、この計画で進めてよいかを訊いてください。
計画の中身を要約したり貼ったりしません（読むのは利用者です）。利用者が見出しを指して訊いたときは、その見出しだけを答えます。

```bash
python3 .statemachine/codd/codd.py summary
```

「人の承認が要るファイル」が出たら、計画全体とは別に、そのファイルを変えてよいかをはっきり訊きます。
すべて認められたら `OK`。認められないファイルがあれば `NG` とし、指摘に「変えずに今回やらないことへ回す: パス」と書きます。
「受け持ちの外で、変わる名前が出てくるファイル」が出たら、一緒に直すかも訊きます。
「決まっていない振る舞い」が出たら、どうするかを訊きます。決まったら `NG` とし、指摘に利用者の決めたことを書きます（計画に書いて練り直す）。

**利用者が答えるまで待ってください。答えを推測したり、先へ進んだりしないでください。**

答えを受けたら、必ず控えます（指摘は利用者の言葉のまま）。OK を控えていない計画では、変える段が変え始める前に止まります。

```bash
python3 .statemachine/codd/codd.py decide OK
python3 .statemachine/codd/codd.py decide NG --note "利用者の指摘"
python3 .statemachine/codd/codd.py decide STOP --note "利用者の答え"
```

- 進めてよい → `OK`
- 直してほしい → `NG`。利用者の指摘をそのまま続けて書く（次の計画で踏まえる）
- やめたい → `STOP`（まだ何も変えていないので、そのままやめる）

**応答:** `caveman` の full で短く（利用者が解除したら従う）。待機中の実況はしない。`summary`・`record` の出力と出力形式は省かず、変えない。

**出力形式:** 第 1 行に `OK`・`NG`・`STOP` の一語だけ。NG なら第 2 行以降に利用者の指摘。
