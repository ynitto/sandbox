# codd — 実装と設計書の一貫性を保って変えるエージェント

このリポジトリでコードや文書を変える依頼は、**必ず codd のステートマシンで進めます。**
ステートマシンの外でファイルを変えたり、検査を飛ばしたりしません。読むだけの質問（どこに何があるか、など）には、
ステートマシンを使わずに答えてかまいません。変える必要があるとわかった時点で、ステートマシンを始めます。

## 回し方

`codd.py step` で 1 段ずつ回します。出た指示どおりに行い、終わったら出力を渡すと、codd.py が検査と遷移を行って次の指示を出します。

```bash
python3 .statemachine/codd/codd.py step --start "依頼"                       # 変える流れを始める
python3 .statemachine/codd/codd.py step --start "何を確かめるか" --review      # 確かめる流れを始める（何も直さない）
python3 .statemachine/codd/codd.py step "OK"                                 # 今の段の出力を渡す（第 1 行は指示にある語。2 行目から続けて書く）
python3 .statemachine/codd/codd.py step                                      # 今の指示をもう一度出す
```

- 計画の確認（confirm）と止まったときの相談（stuck）では、利用者に見せて**答えを待ちます**。推測して先へ進まない。
  ただし stuck で `codd.py advise` の第 1 行が `AUTO APPLY` なら、訊かずに `APPLY` を渡します
- 検査で落ちて同じ段に戻ったら、指摘されたところだけを直します（最初からやり直さない。前の指示は読み直さなくてよい）
- `END` が出たら終わり。最後の振り返り（retro）は利用者に訊かずに進めます
- codd.json の `subagent` が true なら、変える段は `batch` の指示どおり `codd-apply` サブエージェントに渡し、自分では変えません。
  `graph` が束を `codd-graph` に渡すと示したときも、自分では文書を読まずに 1 束ずつ渡します
- agent-herd のハーネスが段の指示を渡してくるときは、`step` を使わずにその指示に従います

## そのほかの依頼

- **「チェックして」「レビューして」「手入れして」「漏れや矛盾がないか見て」**: 確かめる流れを、何を確かめるか
  （ファイル・フォルダ・機能の名前・期間・「全体」。「見なかったところも」なら「続き」。無ければ空）を渡して始めます
- **「次にやることは？」**: `codd.py next` の一覧をそのまま見せます
- **「次の計画を進めて」**: 一覧から選んだ計画のやりたいことで変える流れを始め、計画の段で `codd.py draft --next ファイル名` を使います
- 確かめる流れの報告の「やりたいこと」の行を直すよう言われたら、その行で変える流れを始めます
- 変える流れの `record` の出力に `REVIEW` で始まる行があれば、流れが終わってから、確かめる流れを今回すかを尋ねます

## 始める前に

最初の応答前に `python3 .statemachine/codd/codd.py guide caveman` で `caveman` スキルを読み、会話中は full の短い応答を続けます。
利用者が解除したら従います。確認に必要な情報、終了コード、段の出力形式、`summary` / `record` の内容は省略・改変しません。
コード・計画書などの成果物の文章は通常の書式で書きます。
`caveman` と `graphify` は外部スキルです。無ければ、このスキル配布リポジトリのルートの `install.py --agent kiro` か
`install.py --agent copilot` で入れるよう伝えます（無い間も短い応答で進め、読んだとは書きません）。
グラフの作成・調査を直接頼まれたときだけ `python3 .statemachine/codd/codd.py guide graphify` を読みます。
ファイル・ログの読み方は、計画の段で出る「読み書きの手順」に従います。
**スキルは自分で選ばず、段の指示で `python3 .statemachine/codd/codd.py guide 名前かパス` で読み込みます**（読み込んでいないと検査で落ちます）。

## 長いコマンドの結果待ち

`step`（中で検査とテストが動く）・`graph`・`explore` は時間がかかることがあります。終わるまで待ちます。非同期なら最初 30 秒、
以後 60 秒おきに終了を確かめ、途中の出力を繰り返し読んだり報告したりしません。重ねて起動せず、進捗が見えないことを理由に止めません。
終了コードを取ってから結果を判断します。

## 守ること

- 検査（`step` が動かす `verify-plan` / `verify-apply`）の結果を自分で覆さない。落ちたら、指摘を直すか、相談の段へ進む
- 終わりの報告は `codd.py record` の出力をそのまま使う。自分の記憶でまとめ直さない
- コミットしない（利用者が内容を確かめてからコミットする）
- 計画は `codd.py draft --name 英語の短い名前` で置いた `.plans/日時-名前.md` に書く。同じ回の練り直しではこれを直す。
  終わった回の記録は書き換えない
- **1 回の応答を短くする。** ファイルの全文やコマンドの長い出力を貼らず、パスを示します（応答の長さに上限がある
  エージェントでは「the response hit the length limit」で止まります）。計画は見出しごとに書き、既にあるファイルは変える箇所だけを置き換えます
