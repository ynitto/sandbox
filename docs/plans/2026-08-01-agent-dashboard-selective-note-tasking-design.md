# Agent Dashboard: メモの部分選択タスク化設計

## 背景

現在のメモ機能は、`notes/*.md` へ新しいメモを追記し、利用者が明示的に「メモをタスクにする」を押したときだけ、全メモをまとめて `distill-notes` へ渡す。取り込まれたメモは `notes/archive/` へ移る。

この方式では既存メモを自由に編集できず、タスク化したい部分と残しておきたい部分を分けられない。メモを未確定の考えの置き場として保ちながら、必要な段落・箇条書きだけを選び、確認後にタスクへ追加できるようにする。

既存の「日常画面は簡潔にする」「詳細はダイアログで段階的に開示する」「人の明示操作なしにタスクを実行しない」という設計方針は維持する。

## 目的

- 既存メモを通常の文章として自由に編集・保存できる。
- 段落または箇条書き項目を複数選択し、その部分だけをタスク候補へ変換できる。
- AIが選択内容を1件以上のタスク候補へ分解し、人が確認・修正してから追加できる。
- タスク化後も元の文章を残し、タスク化済み状態と作成タスクへの導線を示す。
- タスクは既存フローどおり候補として追加し、承認されるまで実行しない。

## 対象外

- リッチテキストまたは汎用ブロックエディタの導入
- メモからの直接実行
- メモの共同リアルタイム編集
- メモの版管理、コメント、タグ、検索の追加
- 既存 `distill-notes` CLI の削除

## 検討した案

| アプローチ | 実装コスト | リスク | 保守性 | 自由編集 | 選択しやすさ | 学習コスト | 推奨度 |

## 採用設計

### 画面構成

既存のメモダイアログを、メモ一覧と選択中メモの作業領域を持つ広めのダイアログへ更新する。作業領域には「編集」「タスク化」の2モードを置く。

- **編集**: 既存のプレーンな `textarea` でMarkdown本文を編集し、明示的に保存する。
- **タスク化**: 保存済み本文を段落・箇条書き項目へ分け、各項目の先頭にチェックボックスを表示する。
- 下部の主要操作はモードに合わせて「保存」または「選択したN項目から候補を作る」へ切り替える。
- メモ名は自動生成されたファイル名を引き続き識別子に使う。名称変更やフォルダ分類は追加しない。

### ブロックの単位

- 空行で区切られた通常文章は1段落を1ブロックとする。
- Markdownの箇条書きは1項目を1ブロックとし、継続行は直前の項目に含める。
- 見出しは単独の選択対象にせず、配下の選択ブロックへ文脈として添える。
- コードフェンスや引用は途中で分割せず、まとまりを1ブロックとして扱う。
- 解析に失敗した場合も本文を失わず、通常段落として表示する。

### タスク化フロー

1. 利用者が「タスク化」へ切り替える。
2. 未処理の段落・箇条書き項目を1件以上選択する。
3. 「選択したN項目から候補を作る」を押す。
4. 既存の読み取り専用AI補助を新しい構造化モードで呼び、選択本文、見出し文脈、charter、既存タスクを渡す。
5. AIは重複を考慮し、1件以上の候補を返す。
6. プレビューで各候補の採否、タイトル、作業内容、完了条件を編集する。
7. 「選択したN件をタスク一覧へ追加」で、採用候補だけを既存のタスク追加経路へ送る。
8. タスクは候補状態で一覧へ入り、既存の承認操作を経るまで実行されない。

候補生成は助言に限定し、生成しただけではファイルやバックログを変更しない。現在の `distill-notes` のように全メモを読み込んだり、元メモをアーカイブしたりしない。

### タスク化済み表示

タスク追加を依頼したブロックは本文に残し、次の状態を表示する。

- **追加待ち**: タスク追加コマンドを送信済みで、タスクIDがまだ反映されていない。
- **タスク化済み**: 作成されたタスクIDへのリンクを表示する。複数タスクになった場合はすべて表示する。
- **追加失敗**: 本文と選択を保持し、同じ候補から再試行できる。

タスク化済みブロックは既定では再選択できない。ブロック本文を編集した場合は新しい内容とみなし、現在の表示上は未処理へ戻して再タスク化できる。既に作成済みのタスクは変更・削除しない。

### データと既存機能の再利用

- `notes/*.md` を本文の正典として維持する。
- 既存の `listNotes` と原子的ファイル書き込みの方式を再利用し、既存ファイルを上書き保存する最小の更新APIを追加する。
- ブロックのタスク化状態は `notes/.task-links.json` に、メモ名、正規化したブロック指紋、追加要求、タスクIDを記録する。本文へ制御用記法を混ぜない。
- 新しいAI生成基盤は作らず、既存 `agentTaskAssist` にタスク候補配列を返すモードを追加する。
- 確定時は既存のタスク追加コマンドを候補ごとに利用する。生成候補を直接実行経路へ渡さない。
- 既存 `distill-notes` CLI は互換性のため残すが、ダッシュボードの主要導線は部分選択方式へ置き換える。

ブロック指紋は正規化した本文を基準にする。文章を変更すれば別ブロックとして扱う単純な方式を採用し、編集追従のための独自差分アルゴリズムは導入しない。

### エラーハンドリング

- 保存失敗時は編集内容を消さず、入力欄の近くに原因と再試行方法を表示する。
- AI候補生成に失敗した場合は選択状態を保持する。
- 一部のタスク追加だけが失敗した場合は候補ごとに結果を表示し、失敗分だけ再試行できるようにする。
- メモが外部で変更された場合は無条件に上書きせず、再読み込みか現在内容での保存を選ばせる。
- `.task-links.json` が欠損または壊れていてもメモ本文の閲覧・編集は継続できる。状態表示だけを未処理へ倒す。

### アクセシビリティとレスポンシブ

- モード切替と選択状態は文字と `aria-pressed` / checkbox の両方で示す。
- すべての選択項目と主要操作に44px相当の操作領域を確保する。
- Tab順をメモ一覧、モード、本文、主要操作の視覚順に合わせ、可視フォーカスを維持する。
- 状態を色だけで表現せず、「追加待ち」「タスク化済み」「追加失敗」を併記する。
- 768px未満では左右配置を上下配置へ切り替え、横スクロールを発生させない。
- 候補生成中と追加中は対象ボタンを無効化し、処理中の文言を表示する。

## テスト

- 既存メモの読み込み、編集、原子的保存ができる。
- 通常段落、箇条書き、継続行、見出し、コードフェンスを期待するブロックへ分割できる。
- 選択したブロックだけがAI補助へ渡り、未選択本文は渡らない。
- AI候補は確認するまでタスク追加処理を呼ばない。
- プレビューで除外・編集した結果だけが既存タスク追加経路へ送られる。
- 追加待ち、タスク化済み、追加失敗が正しく表示され、タスク詳細へ移動できる。
- タスク化済み本文を編集すると未処理になり、既存タスクは変更されない。
- 保存、AI生成、部分的なタスク追加の各失敗で本文と選択が保持される。
- キーボード操作と375px、768px、1024px、1440px相当の表示を確認する。
- agent-dashboard と agent-project の既存テストが成功する。

## 既存スキルとの関係

- `ui-designer`: モード分離、段階的開示、フォーカス、操作領域、非同期フィードバックへ反映した。
- `webapp-testing`: 実装後の選択、編集、候補確認、失敗復旧、タスク詳細遷移、主要画面幅の確認に利用する。
- `react-frontend-coder`: 対象がプレーンElectronのため使用しない。

## 実装計画

1. メモ更新APIとブロック分割の純関数を追加し、最小の単体テストを付ける。
2. メモダイアログを一覧、編集、タスク化の2モードへ更新する。
3. 既存 `agentTaskAssist` に選択本文から複数タスク候補を返すモードを追加する。
4. 候補プレビューを既存タスク入力項目とタスク追加経路へ接続する。
5. `.task-links.json` の状態保存とタスク詳細リンクを追加する。
6. エラー復旧、キーボード操作、レスポンシブ表示を検証する。
7. agent-dashboard と関連する agent-project テストを実行する。
