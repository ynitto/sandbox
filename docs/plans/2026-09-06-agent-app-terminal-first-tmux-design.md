# agent-app ターミナル中心会話UI設計

## 背景

agent-app は複数の対話型CLIを共通の会話UIで扱っている。しかし、思考、回答、確認質問、承認待ち、進捗表示はCLIごと、さらに同じCLIのバージョンや状態ごとに表現が異なる。端末出力の文字列解析でこれらを共通メッセージへ変換すると、回答を取得できない、質問を表示できない、処理中のまま終了しない、といった誤判定が継続的に発生する。

そこで、CLI固有の対話はtmux画面を正として表示し、agent-appは送信受付、セッション管理、エージェント切替など、自身が確実に把握できる状態だけを表示する。

## 目的

- CLIの表示や入力待ちを欠落なくユーザーへ見せる。
- CLI固有の文言解析への依存を減らす。
- 現在の入力欄を維持しつつ、入力が受け付けられたことを明示する。
- エージェント切替前の画面を会話履歴として参照可能にする。
- tmuxセッションが無制限に増えないライフサイクルを定義する。
- Windows版agent-appとWSL上のtmuxを安全に連携させる。

## 非目標

- 各CLIの思考、回答、質問を意味解析して共通形式へ完全変換すること。
- tmux自体の全機能をagent-app UIとして再実装すること。
- 複数エージェントのライブ端末を同じ会話で同時維持すること。
- agent-app管理外のtmuxセッションを操作すること。

## 採用アプローチ

既存の `capture-pane` と `send-keys` によるtmuxミラーを会話画面の主表示へ昇格する「ターミナル中心ハイブリッド」を採用する。Electronからtmuxへ直接attachするのではなく、現在のWSL常駐プロセス経由の通信を維持する。

| アプローチ | 実装コスト | リスク | 保守性 | CLI再現性 | Windows対応 | 推奨度 |
|---|---:|---:|---:|---:|---:|---:|
| 既存tmuxミラーを主表示化 | 中 | 低 | 高 | 高 | 高 | ★★★ |
| node-ptyでtmuxへ直接attach | 高 | 高 | 中 | 最高 | 中 | ★★☆ |
| CLI別の構造化出力アダプター | 高 | 高 | 低 | 中 | 中 | ★☆☆ |

直接attachは端末として最も忠実だが、Electronのネイティブ依存、Windows向け配布、WSLとのPTY境界が増える。CLI別アダプターは今回問題になった出力形式の変化を引き続き追跡する必要がある。既存ミラー方式なら現在の資産を利用し、CLIの画面をほぼそのまま提示できる。

## 画面構成

会話の主領域を次の順序で構成する。

1. アクティブなエージェント、モデル、セッション状態を示すヘッダー
2. xterm.jsで描画するライブtmux画面
3. 過去エージェントの読み取り専用スナップショット
4. 現在の入力欄と送信状態

入力欄はCLIが処理中または質問待ちに見える場合でも利用可能にする。通常の文章は入力欄から送信し、矢印、Tab、Escape、Ctrl+Cなどの端末操作はライブ端末へフォーカスして入力する。

agent-appはCLIの文言から「思考中」「質問待ち」「完了」を推測しない。表示する送信状態は、agent-app自身が確認できる次の状態に限定する。

- `受付済み・<agent>を準備中`
- `✓ <agent>へ送信済み HH:mm:ss`
- `送信失敗・入力内容を保持しました`
- `セッション終了`

送信成功は、tmuxへの文字列送信とEnter送信の両方が成功した時点で確定する。失敗時は入力欄を消去しない。

## エージェント切替

1会話につきライブtmuxセッションを最大1個にする。エージェント切替時は次の順序で処理する。

1. 実行中なら停止確認を表示する。
2. 現在のpaneを最終キャプチャし、エージェント名、モデル、時刻とともに読み取り専用スナップショットとして保存する。
3. 現CLIプロセスを正常終了させ、必要なら期限付きで強制終了する。
4. 同じtmuxセッション内で新しいCLIを起動する。
5. 会話履歴の未共有部分を新CLIへ渡し、利用可能ならCLI固有のresume機能を使用する。
6. 会話履歴に `Cursor → Kiro` のような切替イベントを記録する。

切替前の端末はライブ状態では保持しない。スナップショットは折りたたみ表示とし、どのCLIの出力かを明示する。

## tmuxセッションのライフサイクル

### 所有単位

- セッションはメッセージ単位やエージェント単位ではなく会話単位とする。
- セッション名にはagent-app専用プレフィックスと会話IDを含める。
- agent-appが作成記録を持つセッションだけを管理対象とする。
- agent-app管理外のセッションは列挙できても変更・削除しない。

### 状態遷移

```text
未作成
  └─ 初回送信 → 起動中 → 利用中
                         ├─ エージェント切替 → スナップショット保存 → 利用中
                         ├─ pane終了 → 終了済み
                         ├─ 会話アーカイブ → 終了・回収済み
                         ├─ 会話削除 → 即時削除
                         └─ app終了 → 休止中 → 24時間以内なら再接続
                                           └─ 24時間超過 → 回収
```

### 作成と再利用

- 初回送信時に遅延作成する。
- 同じ会話の追加送信では既存セッションを再利用する。
- エージェント切替でもセッション自体は増やさず、内部のCLIプロセスだけを交換する。
- セッションが消失していれば再作成し、CLI固有のresumeを試す。

### 保持と回収

- agent-app終了後も、停止中セッションを最終利用時刻から24時間保持する。
- 24時間以内の再起動では既存セッションへ再接続する。
- 明示的な会話削除では対応セッションを即時削除する。
- 会話アーカイブではCLIを終了し、会話履歴とスナップショットのみ保持する。
- paneが終了した場合は最終画面を保存し、セッションを終了済みとして回収する。
- 起動時および一定間隔で管理対象セッションと会話DBを照合する。
- DBに存在しない、または保持期限を超えた停止中セッションを孤立セッションとして削除する。
- 実行中と確認できるセッションは保持期限だけで削除しない。

### 多重起動と安全性

各セッション記録に会話ID、セッション名、最終利用時刻、状態、所有インスタンス識別子を保持する。複数のagent-appが同じWSL環境を使用する場合、所有権を取得できたインスタンスだけが入力と回収を行う。所有権が不明なセッションは削除せず、次回照合対象に残す。

## データモデル

会話の永続データに、少なくとも次を追加する。

### terminal_session

- `conversation_id`
- `tmux_session_name`
- `agent_cli`
- `model`
- `state`: starting / active / idle / dead
- `owner_instance_id`
- `created_at`
- `last_used_at`
- `expires_at`

### terminal_snapshot

- `id`
- `conversation_id`
- `agent_cli`
- `model`
- `captured_at`
- `reason`: agent_switch / pane_dead / archive
- `screen_text`

スナップショットは端末画面の参照用であり、再実行用の構造化メッセージには使用しない。保存数または総容量に上限を設け、古いものから回収可能にする。

## WindowsとWSL

Windows版agent-appから `wsl.exe` を経由してWSL内のtmuxを操作する構成は成立する。tmux、シェル、CLI、ソケットはすべてWSL側に置き、Windows側は既存の常駐 `wsl.exe ... bash` プロセスの標準入出力を利用する。

注意点は次のとおり。

- Linux CLIを使う作業ディレクトリは可能ならWSLのext4領域へ置き、`/mnt/c` のI/O低下を避ける。
- WSL停止時にはtmuxも消えるため、再起動時の再作成とCLI resumeを通常経路として扱う。
- Windows、Electron、WSLでUTF-8と `TERM=xterm-256color` を統一する。
- CJK、絵文字、結合文字の表示幅をWindows実機で検証する。
- Windowsパス、`/mnt/c`、`\\wsl$` の変換を境界テストする。
- capture-paneのポーリング間隔と画面サイズはWSLへの負荷を測定して調整する。

## エラーハンドリング

- tmux作成失敗: 入力を保持し、WSL、tmux、CLIのどこで失敗したかを表示する。
- send-keys失敗: 送信済みにせず、再送可能にする。
- pane終了: 最終キャプチャを試み、失敗しても会話自体は利用可能に保つ。
- CLI終了不能: 猶予時間後に対象pane内のプロセスだけを終了する。
- WSL切断: セッション消失として扱い、再接続ボタンから再作成する。
- スナップショット保存失敗: 切替を中断するか、履歴を失うことを明示して再確認する。
- 清掃失敗: 次回へ延期し、管理外セッションを巻き込む可能性がある削除は行わない。

## テスト方針

### 単体テスト

- 会話ごとにセッションが1個だけ作成される。
- 追加送信とエージェント切替でセッション数が増えない。
- send-keys成功時だけ送信済みになる。
- 24時間未満は保持し、24時間超過の停止中セッションだけを回収する。
- 実行中、所有権不明、管理外のセッションを回収しない。
- 会話削除とアーカイブで異なる処理になる。
- 切替時に最終スナップショットと切替イベントが保存される。

### 結合テスト

- Cursor、Aider、Codex、Copilot、Kiro、Claudeで質問待ちを端末に表示し、入力欄から回答できる。
- CLIが終了、クラッシュ、再起動した場合の画面と状態を確認する。
- app再起動後24時間以内の再接続と、期限超過後の回収を確認する。
- 複数appインスタンスが同じセッションを同時操作しない。

### Windows/WSL実機テスト

- Windows版ElectronからWSL内のセッションを作成、送信、再接続、削除できる。
- 日本語、絵文字、ANSI色、画面リサイズを確認する。
- WSL停止、Windows再起動、ネットワーク切断後の回復を確認する。
- `/mnt/c` とWSL ext4上で応答時間とCPU負荷を比較する。

## 既存スキルとの関係

- `ui-designer`: ターミナル、送信状態、スナップショットの視覚的優先順位の調整に利用する。
- `systematic-debugging`: CLIごとの実際の入出力とセッション状態を観測し、誤動作を再現する。
- `webapp-testing`: Electronレンダラーの入力、切替、折りたたみ、状態表示をE2E検証する。
- `windows-app-automation`: Windows版agent-appとWSLの実機スモークテストに利用する。
