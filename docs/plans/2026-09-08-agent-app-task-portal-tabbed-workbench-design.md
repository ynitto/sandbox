# agent-app タスクポータルとタブ式ワークベンチ設計

## 背景

agent-app のタスク画面は statemachine-maker のワークベンチを埋め込んでいる。タスクを選んだ直後に編集・教示へ寄りやすく、利用者が最初に確認したい実行可否、直近結果、定期実行、要確認事項への入口が弱い。また、agent-app は領域をタブで切り替える一方、埋め込まれたエディターは「一覧へ戻る」で遷移するため、同じ画面内に二つのナビゲーション規則が存在する。

## 目標

- 定義済みタスクを開いた直後に、実行と状態確認のポータルを表示する。
- タスク内の主要操作をタブに統一し、戻る操作への依存をなくす。
- statemachine-maker の実行・保存・教示・履歴ロジックを再利用する。
- statemachine-maker 単体利用の既存ナビゲーションは維持する。

## 採用する画面構成

agent-app で定義済みタスクを選ぶと、タスク詳細を次のタブで表示する。

1. **概要**: タスクの説明、実行状態、手動実行、定期実行、進行ログを表示する。既存の「テスト・実行」後の画面をポータルとして利用する。
2. **手順**: 既存のステートマシン編集画面を表示する。編集用ヘッダーと保存操作は維持するが、「一覧へ戻る」は表示しない。
3. **AI相談**: 既存の教示・変更相談画面を選択中のタスクに紐づけて表示する。
4. **履歴**: 直近の手動実行・定期実行とログを表示する。

タスク選択時は常に概要を初期タブとする。ただし、同じタスク内で再描画した場合は現在のタブを維持する。実行開始後も概要タブ内で進行状況を更新する。

## ナビゲーション所有権

agent-app が次を所有する。

- 会話／タスク／ワークフローの領域切り替え
- リポジトリとタスクの選択
- 新規タスク作成の入口

statemachine-maker の埋め込みモードは、選択された対象の詳細表示だけを担当する。埋め込み時は maker 側のブランドヘッダー、フォルダ一覧、ホームタブ、「一覧へ戻る」を表示しない。単体モードでは従来のホーム画面と戻る操作を維持する。

## 実装方針

- 既存の custom element とホストAPIは維持する。
- 埋め込みモード用のタスク詳細シェルを statemachine-maker 側に追加する。
- 編集画面と教示画面を別ページとして複製せず、タブの内容として既存描画関数を呼び出す。
- タスクタブの状態は renderer の単一状態として管理し、選択タスクが変わったときだけ概要へ戻す。
- ARIA の `tablist`、`tab`、`aria-selected` を設定し、DOM順とキーボード移動順を一致させる。

## エラーと空状態

- 実行基盤に接続できない場合もタスク名とタブは残し、概要内にエラーを表示する。
- 定義のない下書きや新規タスクは AI相談を初期表示し、定義が生成された時点で通常のタスク詳細へ移行する。
- ステートマシン以外のタスクでは利用できない手順・AI相談タブを表示しない。
- タブ切り替えで未保存編集が失われる場合は、既存の変更確認ガードを利用する。

## テスト方針

- 定義済みタスクの初期表示が概要であること。
- 概要、手順、AI相談、履歴を戻るボタンなしで切り替えられること。
- タスクを切り替えると概要へ戻ること。
- 手順の保存、概要の実行、AI相談、履歴ログが従来どおり動くこと。
- statemachine-maker 単体版の一覧／編集遷移が維持されること。
- agent-app の Electron smoke test で埋め込みUIの表示と主要遷移を確認すること。
