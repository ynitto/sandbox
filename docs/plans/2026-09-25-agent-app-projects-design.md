# agent-app プロジェクト設計（agent-project からの移行）

- 日付: 2026-09-25
- 対象: `tools/agent-app`（0.37.0）、`schemas/agent-cli.schema.json`、`agents/{claude,codex,copilot}.json`
- 関連: [agent-project 設計](../designs/agent-project-design.md)（置き換え元）、[agent-app 設計](../designs/agent-app-design.md)

## 1. 何を作るか

Claude Projects に近い「プロジェクト」を agent-app に足す。1 つのプロジェクトに役割の違う複数の
リポジトリを束ね、そのうち 1 つをリポジトリ横断の**ナレッジリポジトリ**にする。プロジェクトを選んで
依頼すると、適切なリポジトリをカレントにして会話・タスク・ワークフローを始め、ほかのリポジトリと
ナレッジの場所を添える。会話の回答からは「ナレッジに保存」で、決まった置き場へ書く指示を送れる。

agent-project の考え方（リポジトリの役割・owns によるルーティング・rules / decisions / notes）は借りるが、
**常駐プロセスと状態専用リポジトリは持たない**。最終的に agent-project を廃止するため、状態フォルダを
取り込む手段を用意する。

## 2. 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| 定義の置き場 | ナレッジリポジトリの `projects/<フォルダ>/project.yaml`（1 プロジェクト 1 枚） | 利用者の指定。複数 PC で同じ定義を共有する |
| 定義の大きさ | 名前・リポジトリ（URL・役割・説明・owns）・短い指示だけ。16 KB を上限に読み書きで拒む | 利用者の条件「トータルのファイルサイズが大きくならない」。状態・履歴・ログは書かない |
| 更新の頻度 | 人が編集画面で保存したときだけ書き、そのファイルだけをコミットして push する | 利用者の条件「頻繁な更新が不要」。ブランチは指示・ナレッジとも main（利用者の決定） |
| 読み込み | 起動時・プロジェクトを選んだとき・編集を開いたときだけ。ファイル時刻と大きさが同じなら読み直さない | 利用者の条件「ポーリングが不要」。監視も定期 fetch もしない |
| 他の PC の変更 | 利用者がナレッジリポジトリを pull すれば、次に選んだときに反映。編集メニューに手動の「最新を取得」（`git pull --ff-only`） | アプリから勝手に取りに行かない |
| リポジトリの識別 | git の URL（scp 形式と https を同一視、資格情報と `.git` を落として比べる） | PC に依存しない。旧 repos.schema.json と同じ識別子 |
| この PC のフォルダ | `config.json` の `repoPaths`（URL → フォルダ）。登録リポジトリの origin から自動で結び、無いものだけ画面で選ぶ | ローカルパスを共有ファイルに書かない（agent-project の S3 と同じ理由） |
| 役割 | 主（1 つ）／作業／参照。ナレッジは定義を置いたリポジトリ自身 | 主 = 既定のカレント、作業 = 書いてよい、参照 = 読むだけ |
| どのプロジェクトを見るか | `config.json` の `knowledgeRepos`。リポジトリの管理メニュー「ナレッジリポジトリとして読む」で足す | 登録リポジトリ全部を探し回らない（明示） |

## 3. データ

### 3.1 `project.yaml`

```yaml
# agent-app のプロジェクト定義。画面の「プロジェクト」から編集する
version: 1
name: 受注システム
repos:
  - url: git@example.com:team/order-app.git
    role: main
    desc: Web アプリ本体
  - url: git@example.com:team/order-api.git
    role: work
    desc: API サーバ
    owns: [services/**]
  - url: git@example.com:team/spec.git
    role: reference
    desc: 仕様書（読むだけ）
instructions: ""          # 任意
```

正規化（`src/main/projects.js` の `normalize`）: 主は 1 つだけ（無ければ最初の作業、それも無ければ最初の 1 つ）。
同じ URL は 1 つにまとめる。リポジトリは 20 まで、説明 300 字・指示 2000 字まで。`version` が 1 以外なら読まない。

### 3.2 ナレッジリポジトリの中

```
<kb>/
  shared/                 全プロジェクト共通（「共通のメモとして保存」の置き場）
  projects/<フォルダ>/
    project.yaml          定義（人が保存したときだけ変わる）
    README.md             索引（作成時に雛形だけ置く。以後はエージェントが 1 行ずつ足す）
    rules.md              常に守ること
    decisions/            決めたこと
    notes/                メモ
```

アプリが書くのは `project.yaml` と README の雛形だけ。知識の中身はエージェントが書く。

### 3.3 `config.json`（PC ごと）

| キー | 意味 |
|---|---|
| `knowledgeRepos` | 定義を読みに行くナレッジリポジトリ（登録フォルダに限る。10 まで） |
| `repoPaths` | 正規化した URL → この PC のフォルダ |
| `lastProject` | 選んでいるプロジェクト（`<kb>#<フォルダ>`。`''` はプロジェクトなし） |

会話（`sessions/<id>.json`）には `project`（同じ鍵）を持たせる。作成時に、選んでいるプロジェクトに
そのリポジトリが入っているときだけ付く（`projectIpc.projectFor`）。

## 4. 動き

### 4.1 始めるリポジトリ（`projects.chooseRepo`）

新しい会話を送る直前に 1 回だけ決める。決定的で、LLM は呼ばない。

1. 依頼に書かれたパスが、書いてよい（主・作業）リポジトリの `owns` に**一意に**当たる → そのリポジトリ
2. 依頼が、書いてよいリポジトリの名前（URL の末尾）を**一意に**含む → そのリポジトリ
3. それ以外 → 主。参照リポジトリでは始めない

移ったときは入力欄の下に「order-api で始めます」と出す。移った後は、利用者がサイドバーで選び直せる。
振り分け（`agent-herd route`）へリポジトリを候補として渡す案は見送った。判定が当たらないときの
戻り先が無く、owns と名前の一致で足りる範囲から始める。

### 4.2 最初の依頼に添えるもの

- 共通指示のブロックに「## プロジェクト」の節（`projects.contextBlock`）: カレントの役割、ほかのリポジトリの
  パス・役割・説明、参照は読むだけにすること、ナレッジの場所と README / rules を先に読むこと、プロジェクトの指示。
  共通指示をオフにしていても添える
- プロジェクトの会話では、別のフォルダへの分岐（`@fork`）の作法は添えない。ほかのリポジトリへは直接書けるので、
  「外へは書かず分岐を頼む」という作法と矛盾する
- 添えるのは既存の規則どおり、その CLI の文脈がまだ持っていない最初の 1 回だけ

### 4.3 ほかのリポジトリへの書き込み（`add_dir_args`）

CLI 定義に `add_dir_args`（`{dir}` をフォルダ 1 つずつに展開）を足した。claude / codex / copilot は
`--add-dir {dir}`。プロジェクトの会話は、カレント以外の（この PC にある）リポジトリとナレッジリポジトリを
ヘッドレス・tmux の両方で渡す。宣言の無い CLI にはパスを本文で伝えるだけになる。スキーマに足したので、
定義を厳格に検査する agent-dashboard の許可リストにも足した。

### 4.4 ナレッジに保存

回答の下（「フォーク」の隣）の「ナレッジに保存」から 4 つを選ぶ: メモ / 決めたこと / 守ることに追記 /
共通のメモ。押すと `projects.knowledgePrompt` が組んだ指示を、入力欄に入れて同じ会話へ送る
（何を送ったかは会話に残る）。指示は置き場（`notes/<日付>-<名前>.md` など）、索引への 1 行、
ナレッジリポジトリの中だけをコミットして push すること、を決めて渡す。

### 4.5 タスク・ワークフロー

AI と作る会話（`kind: task / workflow`）も会話と同じ経路で起動するので、選んでいるプロジェクトに
そのリポジトリが入っていれば同じ節と `--add-dir` が付く。一覧はリポジトリごとのまま
（プロジェクトの全リポジトリをまとめた一覧は今回は作らない）。

### 4.6 ナレッジを貯める・使う

- 貯める: 自動では書かない（頻繁な更新をしない条件）。代わりに節で「回答の最後に、ナレッジに残す候補を
  1〜3 行で挙げる（自分では書かない）」と頼み、利用者が「ナレッジに保存」を押す
- 使う: 節で README / rules を先に読ませ、`rules.md` が 4 KB 以下なら中身を節に差し込む（大きいものは読む指示だけ）。
  ナレッジリポジトリは `--add-dir` で渡すので、エージェントは必要なときに検索できる

### 4.7 ブランチ

- ナレッジリポジトリ: 指示（`project.yaml`・`rules.md`）もナレッジも main へコミットして push する。アプリは
  ナレッジリポジトリのチェックアウト中の中身を読むので、長く生きる別ブランチには置かない
- コードのリポジトリ: 作業フォルダ（ブランチ）で動く会話では、節にそのブランチ名を書き、ほかの作業リポジトリも
  同じ名前のブランチを切ってから変えるよう伝える。main へ直接コミットせず、push と PR は頼まれたときだけ。
  作業フォルダを使わない会話は単一リポジトリのときと同じ扱い

## 5. 画面

| 部品 | 借りた形 |
|---|---|
| サイドバーのプロジェクト選択 | リポジトリと同じ `.repository-control`（select と ••• の管理メニュー）をリポジトリの上に 1 段。プロジェクトが 1 つも無い間は出さない |
| リポジトリの選択肢 | プロジェクトを選んでいればその中だけ、役割を添える（`order-app（主）`） |
| ホーム | 同じ選択欄を入力欄の下へ移す既存の仕組みのまま。プロジェクトを選んでいればリポジトリの選択欄は隠す（依頼から決まる） |
| 編集 | 作業フォルダ（`#wt-dialog`）と同じダイアログ。行は設定の `.setting-field`、リポジトリは `.wt-table.settings-table`、主ボタンは「保存」1 つ |
| ナレッジに保存 | 回答の下の `.message-action` と `.more-menu` の選択肢（「定型」と同じく上向きに開く） |
| ホーム（プロジェクトの入口） | 空状態の見出し → 1 行 → `.execution-card` の「指示」「ナレッジ」（「概要」の手動実行と同じカード）。主ボタンは入力欄の送信だけ |
| プロジェクトの会話一覧 | 既存の一覧の行。下の行にリポジトリ名を足す |
| 会話のプロジェクト名 | 分岐元を出している `#chat-origin` の小さい行 |
| プロジェクトに入れる | 会話の「•••」（`#chat-more`）の 1 項目 |

設計案では編集を設定画面の中に置く予定だったが、設定画面は下の「保存」が全タブ共通の主ボタンなので、
プロジェクトの保存（コミットを伴う）を同じ面に置くと主ボタンが 2 つになる。独立したダイアログにした。
保存の種類はポップオーバーのラジオではなく、既存の選択肢メニュー 1 段にした（押す回数が 1 回減る）。

## 6. agent-project からの移行

「新しいプロジェクト」の「agent-project から取り込む」、または
`node tools/agent-app/scripts/import-agent-project.js <状態フォルダ> --kb <ナレッジ>`（コミットはしない）。

| 旧 | 新 |
|---|---|
| `repos.{yaml,yml,json}`（あれば正）／`charter.md` の `## repos` | `project.yaml` の `repos`。owns あり → 作業、無し（または readonly）→ 参照、最初の作業 → 主。同じ URL の複数エントリ（モノレポのフォルダ別・ブランチ別）は owns を合わせて 1 つに |
| `~/.agents/agent-project.host.yaml` の `repos[].local` | `repoPaths`（この PC に実在するフォルダだけ。登録リポジトリにも足す） |
| `charter.md` / `rules.md` / `decisions/*.md` / `notes/*.md` | `projects/<フォルダ>/` へそのまま写し、README の索引にリンクを並べる |
| `backlog/` `needs/` `archive/` `inbox/` `commands/` `journal-archive/` | 移さない。件数だけ出す。旧フォルダは消さない |
| `charters/<版>.md`・`policy.md`・`project.json` など | 移さない（自律実行の制御層は持たない） |

## 7. このあとの作業（別 PR）

agent-project 本体の廃止は別にする。agent-app の agent-tools 自動更新が `agent-project update` に乗っており、
agent-dashboard も agent-project の状態を読んでいる。先に更新の担い手を移し、dashboard の読み先を決めてから消す。
