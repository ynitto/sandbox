# webui-test の設定生成と設計書側からの撮影

## 目的

手書きだった環境設定を明示的に生成できるようにし、codd-agent の設計書側から既存の撮影コマンドを使う手順を整える。

## 設計

- webui-test に `init [dir]` を追加する。接続先、任意の起動コマンド、検査ケースのパスを受け取り、YAML または JSON の設定だけを生成する。
- 既存の設定は上書きしない。ケース、アプリ、codd-agent の設定は生成しない。
- 設計書側の `check` に `webui-test capture` を設定する。撮影YAML、画像、文書は通常の計画対象にする。
- 設定内のパスと起動コマンドの作業ディレクトリは設定ファイルのフォルダ、撮影YAMLと出力先は実行時の作業ディレクトリを起点とする。
- 撮影失敗は既存の検査で止める。codd-agent の専用フックや必須依存は追加しない。
- `capture` は画像を生成する。`check` の evidence による既存画像の差し替えとは別に利用できる。
- 最新の evidence は既定で `results/webui-test-evidence.json` に書く。設定の `evidence` で保存先を変更でき、相対パスは設定ファイルを起点とする。codd-agent の既定 evidence は `[]` とし、利用者が `--evidence` で明示する。両ツールのコマンド・出力先の対応はプロジェクトの設定に置く。

## 実装・検証

1. 設定生成と CLI を追加し、読み込み互換性、パス、既存設定の保護、不正入力を検証する。
2. 両 README に初期化と設計書側の撮影手順を追加する。
3. webui-test の既存テストを含めて実行し、撮影連携を確認する。
