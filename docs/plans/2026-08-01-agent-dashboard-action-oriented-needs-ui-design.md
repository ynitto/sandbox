# Agent Dashboard 要対応画面の行動起点UI設計

## TL;DR

要対応画面を「何が起きたか、次に何をするか、判断根拠」の順に組み直す。

- 一覧、詳細、操作ボタンは同じ判断モデルを使う。
- blocked、review、plan-review、milestone ごとに操作欄を分ける。
- 過去の操作失敗と長い作業定義は、現在の状態より下へ移す。

文言と配置だけを直す案は却下した。状態判断が複数箇所に残り、今回と同じ矛盾が戻るためだ。
要対応画面を保守する人向けの設計であり、agent-project の状態契約は変更しない。

## 背景

現行画面では「次にすること」と「確認事項」が同じ内容を繰り返し、その後に長い作業定義が続く。
停止理由と操作欄は画面の下に離れている。さらに、最新 run が失敗してタスクが blocked でも、過去の
完了 run を根拠に「成果はできています」「承認して完了」を表示する場合がある。

利用者が最初に知りたいのは現在の状態で、その次が安全に取れる操作である。run ID、生ログ、過去の
操作失敗、作業の背景は判断根拠として残すが、先頭には置かない。

### 目標

- 詳細の先頭だけで、現在の状態と次の操作が分かる。
- 一覧、詳細、ボタンの状態判断が食い違わない。
- blocked では完了承認を出さず、review だけで検収操作を出す。

### 非目標

- agent-project や agent-flow の状態契約は変えない。
- 要対応の一覧と詳細という画面構造は変えない。
- 生ログ、成果物、診断機能は削除しない。

## 現在状態を一度だけ判断する

### 判断

`needDecisionViewModel` を追加し、一覧、詳細、操作欄が同じ結果を使う。

現在状態は、関連タスクと最新世代の run を先に見る。操作失敗は現在状態を上書きせず、別の通知として
保持する。過去世代の完了 run は成果物の所在には使えるが、完了承認の可否には使わない。

表示モデルは次を返す。

- 現在の状態を表す見出しと理由
- 利用者に勧める次の操作
- 主要操作と副操作
- 現在の注意、過去の操作失敗

### 却下案

各描画関数の条件分岐を個別に修正する案は変更量が少ない。ただし `taskCompletionHint`、一覧要約、
詳細文言、操作ボタンが別々に結論を出す状態が残るため却下する。

### トレードオフ

表示モデルへ既存条件を集める作業が要る。一方、状態契約や IPC は触らないため影響範囲は renderer と
テストに閉じる。

## 要対応の種類ごとに操作を分ける

### 判断

共通の「最終回答」をやめ、種類ごとに見出しと操作を変える。

| 種類 | 操作欄 | 主要操作 |
|---|---|---|
| blocked | 再開方法 | 指示を送って再開 |
| review | 成果の確認 | 承認して完了 |
| plan-review | 実行前の確認 | 承認して実行 |
| milestone | 完了の確認 | プロジェクトを完了として承認 |

blocked では「成果はできています」と完了承認を表示しない。入力なしの再実行、保留、検証コマンド変更は
副操作として残す。review のレビューコメントと成果確認は従来どおり使える。

### 却下案

全種類を同じ操作欄のまま文言だけ変える案は、無効なボタンが混ざる原因を残すため却下する。

## 先頭を状態と行動に絞る

### 判断

詳細は次の順にする。

1. 現在の状態と停止理由
2. 次にすることと主要操作
3. 判断根拠
4. 過去の操作失敗
5. 作業内容、成果物、生ログ

「次にすること」と「確認事項」は一つにまとめる。リスク値がない場合は「リスク未設定」を出さない。
長い目的、完了条件、成果物は折りたたみへ移す。一覧も同じ表示モデルから現在状態と次の操作を表示する。

### 却下案

工程別ウィザードは一件ずつ処理するには分かりやすいが、要対応を横断して確認する用途を妨げるため採らない。

## 実装

対象は `src/renderer/sections/needs.js` と要対応用 CSS、既存テストである。既存の
`taskCompletionHint`、`needFailureViewModel`、`needActionsHtml` はデータ取得に再利用し、表示判断だけを
`needDecisionViewModel` へ集める。

テストでは次を固定する。

- 最新 run が失敗した blocked に完了承認が出ない。
- 過去の操作失敗があっても、現在の停止理由を先に表示する。
- 4種類の要対応で見出しと主要操作が切り替わる。
- 一覧と詳細が同じ状態見出しと次の操作を使う。
- 既存の送信済み、コメント、成果確認、再実行を維持する。
