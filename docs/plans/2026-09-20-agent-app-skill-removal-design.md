# スキル画面からの削除

## 承認された仕様

「設定 > スキル」に「削除する項目を選ぶ」を追加する。削除モードは全件未選択で開始し、公開用の選択とは分離する。リポジトリ内と共通のスキルを選び、名前・保存先を確認して OS のゴミ箱へ移動する。処理後は一覧を再取得し、失敗理由を表示する。

## 実装

- 一覧と既存の設定用 UI 部品を再利用する。削除モードでは足元にキャンセルと削除ボタンを出す。リポジトリや AI の切り替え時は削除選択を破棄する。
- main が現在のカタログとファイルの実体から削除用キーを作る。renderer から任意のファイルパスを受け取って削除しない。
- スキルはフォルダ全体、コマンド形式は Markdown ファイルを対象とする。表示されていない同名の別コピーを巻き込まない。スキルの置き場がリンクで外部へ転送されている場合は削除を拒否する。
- main のネイティブ確認ダイアログに対象名と保存先を表示する。キャンセルを既定とし、承認後も対象の同一性を再確認する。
- `shell.trashItem` を使用する。失敗時に完全削除へ切り替えない。成功・失敗を項目ごとに返し、一覧を更新する。
- 公開先の Git リポジトリやスキルの設定値には変更を加えない。

## 選択肢

| 方式 | 復元 | 操作 | 判断 |
| --- | --- | --- | --- |
| 削除専用の選択 + ゴミ箱 | OS から復元できる | モード切替と確認 | 採用 |
| 公開用チェックを共用 + ゴミ箱 | OS から復元できる | 少ない | 既定で選ばれた公開対象を誤削除しやすいため不採用 |
| 完全削除 | 困難 | 少ない | 不採用 |

## 検証計画

実ファイルを使うユニットテストでスキルフォルダ・コマンド・共通の保存先、同名の別コピー、キャンセル、不正キー、リンク、確認後の差し替え、部分失敗を検証する。renderer テストで未選択開始・モード切替・連打防止・エラー・再読込を確認し、既存の公開と UI 整合性テストも実行する。Electron で画面と IPC の接続を検証する。
