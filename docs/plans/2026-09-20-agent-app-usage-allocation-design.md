# Agent App 設定の再デザイン

2026-09-20。ユーザーが試作を承認し、タブ名を実行制御へ戻して実装するよう指示。0.17.0で実装。

## 使用シーンと配置

| 見たい・したいこと | 入口と配置 |
|---|---|
| どのエージェント・モデルで実行するか決める | 設定の「実行制御」。使用方針、起動方針別のエージェントとモデル、ローカル優先時のモデルを一つの表と周囲の設定行に集約 |
| 利用枠が少ないので一時的にローカルを使う | 同じ「実行制御」の一時変更。期間を選び、保存後に使うAIを確認して保存。利用状況の「AI・配分を変更」も同じ欄へ移動 |
| 残量と復帰時刻を確認する | 「利用状況」の先頭。サービス別の表で比較。取得できないときは未取得と表示 |
| 残量の自動取得ができない | サービス行の「手動入力」。対象行の直下に入力欄を表示し、その場で記録。別モーダルは開かない |
| クラウドを何に使ったか調べる | 同じ利用状況の使用実績・内訳。期間と用途別／AI別／モデル別を切替。実測・推定・未計測を列で比較 |

## 決定事項

- ユーザー指示により評価の集計・平均点・成功率の表示を除外。改善課題も表示せず、受信箱への導線を追加しない。
- 自動評価の頻度などの動作設定は既存機能として「実行制御」に残す。評価機能自体の停止・削除は今回の変更に含めない。
- エージェント・モデル・配分の編集は「実行制御」のみ。利用状況には現在の使用方針と同じ編集場所へのリンクだけを置く。
- 通常の配分と期限付きローカル優先を区別し、変更後に使うAIを一行で確認できる。通常の設定を破壊しない。
- 設定の保存はダイアログ下部に統一。モデル専用保存ボタンや即時保存される配分セレクトを廃止する。タブ切替で未保存の入力を保持。
- 手動残量は観測値の記録なので、対象行に「記録する」を置く。通常設定の保存と混同させない。
- 使用量・内訳・モデル表を初期表示。折りたたみをレイアウトの整理手段に使わない。手動残量や指定時の判定モデルのように条件が成立した入力だけを表示。
- 既存の設定ダイアログ、設定行、ボタン、色トークン、表の作法を利用。比較する列に必要な幅を確保し、設定ダイアログの幅は960pxを上限にする。本文だけスクロールし、保存とタブを維持。
- 今の会話を別AIへ引き継ぐ操作は会話の既存フォーク操作を使い、全体設定からは外す。

## 実装時の状態の扱い

- 設定に保存済みの固定実行条件・直接指定・進行中の会話は、全体配分の変更で上書きしない。
- ローカルが利用不可ならその状態を表示し、利用できるように見せない。完全自動の残量対応は今回の手動設定と混同しない。
- 複数の利用枠があるサービスは期間ごとに表へ行を追加する。期間を省いた残量の合算はしない。
- 読み込み・未取得・期限切れ・手動申告・推定・未計測を区別。ローカル利用率は実行回数を分母とする。
- 使用実績は期間変更時に全項目を同じ期間へ更新する。設定ドラフトを更新処理で巻き戻さない。
- 設定の収集有効／無効と間隔の互換性を保持し、一つの収集間隔選択に対応付ける。

## ui-designer の適用

ui-designer スキル を読み、design-system、UX、html-tailwind の検索を実行。最初の検索のランディングページ向け提案は対象に合わず採用せず、SaaS／minimalで再検索した。比較しやすい表、ラベル、可視フォーカス、同一画面の操作、レスポンシブの原則を採用。色・フォントの新設やTailwindの導入は行わず、既存アプリのCSSを利用。

操作試作: index.html。実行制御と利用状況の切替、期間と集計軸の選択、一時変更、未保存入力の保持、試作内保存、手動残量記録を操作可能。その他の設定カテゴリは範囲外のため表示のみ。
