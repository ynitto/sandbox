# ホームから開始した会話の文脈引き継ぎ

## 確認した事実

2026-09-22 の会話 a3ab0e2f-921d-4f6b-94a8-c1295c5c3e8c は、
「今日の天気は？」→地域を確認する回答→「東京」の順に同じ会話へ保存されていた。
CLI は ollama、モデルは gemma4:e4b、transport は tmux。
12:17:57 の Ollama ログの user message には共通指示と「東京」だけが入り、
最初の天気質問と確認質問は含まれていなかった。

## 原因と修正

- app は同じ対話プロセスに送信済みの履歴を再送しなかった。しかし共通 TUI の
  Ollama / aider バックエンドは毎回独立したリクエストとして実行する。
- interactive.retains_context=false を両定義に宣言し、app はその場合に毎回
  保存済みの user / assistant 履歴を送る。端末への再接続でも同じ規則を適用する。
  用途の /ask 等は履歴より前に残す。既定は true で、履歴を保持する CLI の挙動は維持する。
- 応答が終了すると running が外れるため、返信にも新規会話用の準備画面を出していた。
  保存済みのやり取りがある会話では準備画面を出さず、会話と端末を表示し続ける。
  自動選択の判定条件自体は既存のまま（選択済みの会話では再選択しない）。

## 検証

- 修正前、Ollama / aider の継続・再接続4ケースと既存会話の準備表示が失敗。
- 修正後、3ターンの履歴送信、/ask の位置、通常CLIへの重複送信防止、準備表示の
  8ケースが通過。モデル選択の既存11テストも通過。
- Electron のホーム→会話→「東京」のテストが通過。同じ会話IDと選択済みモデルを保ち、
  返信時に準備画面を出さず、会話履歴を表示することを確認（モデル応答はスタブ）。
- tmux の単体・実プロセス統合テスト30件が通過（長い日本語の複数行送信を含む）。
- モデル自動選択の既存Electronテストも通過。実送信処理で選択がターン間で維持されることを確認。
- 周辺 app.test.js のワークフロー詳細タブと herd.test.js のワークフロー起動形式の検査が各1件失敗（どちらも今回未変更のコードに対する検査）。
  この修正で実モデルの応答品質や天気取得機能は検証・追加していない。

反映には agent-app の再起動が必要。別リポジトリや配布版では、上位の探索先に
古いエージェント定義がある場合、更新した agents/ollama.json・aider.json の配布も必要。
