# 分析・提案のモデル自動選択の修正（撤回）

ユーザーの方針に従い、このルールベースの候補制限と専用テストは撤回した。以下は撤回前の調査・実装記録。判定器の傾向を先に調べる。

## 確認した事象
セッション b92fc9bf-c72a-487b-b9ca-da408501dc47 の依頼は「agent-appの追加機能を提案してほしい」。
記録は振り分け未決定、modelSelection.stage=judge、ollama/gemma4:e4b。
設定のクラウド候補は Cursor・Codex・Claude。

## 原因
modelSelection はローカルを含む全候補を agent-herd select に渡し、
分析・提案の能力条件を設けていなかった。選択結果が候補に含まれれば受け入れていた。
agent-tools の判定文は能力が足りる最安候補を推奨するが、能力を必須条件にしていない。
判定不能時の audit 順位も、格付け等がなければ低コストを優先する。
今回の記録は judge 選択であり、audit フォールバックによるものではない。

## 修正
自動配分で明示的に分析・提案・設計・比較等を依頼する表現を検出し、
モデル別の relative_cost 定義を用いてローカルを候補から除く。
クラウド内の選択は引き続き agent-tools に任せる。
旧CLIフォールバックと戻り値検証にも同じ絞り込みを適用する。
クラウド候補が利用不能なら理由を返し、ローカルには降格しない。
選択理由を画面とセッションへ保存する。
手動選択や一時的なローカル優先は既存設定のまま。

これは明示表現への決定的な保護であり、任意の言い換えを意味理解する分類器ではない。
簡単な質問や「提案という単語を英訳して」はローカル候補を残す。

## 確認
同じ依頼文と実設定で選択処理だけを実行。候補 cursor/codex/claude、
結果 cursor、stage=audit、requirement=cloud-analysis。依頼の本処理は起動していない。
回帰テストで通常選択、分析・提案、クラウド枯渇、旧CLI、候補外応答、
モデル別コスト定義、理由の再読込を確認。
