# Agent Dashboard ワークフローエディタ UX 改訂

## 目的

既存の開始・終了、接続制約、手法ノード、標準パターン複製の実行契約は維持し、次の UX 問題を解消する。

- キャンバスが狭く、フロー全体を把握しにくい。
- 標準パターンが接続例として見えず、雛形を選ぶ判断材料がない。
- ノード種類が同列に並び、次に何を置けばよいか判断できない。
- フロー全体の実行手法が、どの工程へ何を追加するか分からない。
- 設定画面の定期更新が編集中の状態を壊す。

## 維持する契約

- 開始と終了を明示し、すべての実行ノードが開始から終了までの経路上にある場合だけ保存する。
- 自己接続、重複、循環、方向違反、split の静的後段を拒否する。
- ノードの tier と手法スナップショットを実行時へ固定する。
- agent-flow の標準パターングラフを正典とする。
- 新しいグラフライブラリは追加しない。

## 採用する画面構成

### 1. 雛形を最初の入口にする

設定画面の初期表示は標準パターンのギャラリーとする。各カードには次を表示する。

- `開始 → 工程 → 検証 → 終了` のような接続関係のミニグラフ
- 何に向くフローか
- 工程数
- 「プレビュー」

雛形を選ぶと、開始と終了を含む読み取り専用の全体プレビューを表示する。主操作は「この雛形から作る」とし、複製後にだけ編集可能にする。「空から作る」は右上の副操作に置く。

### 2. 編集時はキャンバスを主役にする

編集画面はフロー一覧とキャンバスの 2 ペインにする。常設の右プロパティペインは廃止し、ノード選択時だけ詳細ドロワーを開く。

- キャンバスに「全体表示」を常設する。
- フロー名、保存状態、保存操作は上部へ固定する。
- 詳細ドロワーを閉じても選択ノードは維持する。
- 接続中だけ有効な入力ポートと短い操作案内を強調する。

## ノード選択

ノード追加の主操作は、ノード右下の「＋」とする。接続元の種類から次に置く候補を最大 3 件へ絞る。

- 開始後: 作業、複数案の生成、分類
- 作業後: 次の作業、検証、終了
- 生成後: 選別、判定、統合
- 検証後: 修正作業、終了
- split 後: 終了のみ

候補には「何をするか」と「いつ使うか」を表示する。全ノードは「すべての工程」から選べるが、次の目的別に畳む。

- 作る
- 確かめる
- まとめる
- 流れを制御する

ドラッグ追加は副操作として残す。英語の kind ID は主要表示にしない。

## 実行手法の見せ方

実行手法を、作用範囲で明確に分ける。

- ノード用: 「この工程だけに追加するレシピ」
- 開始ノード用: 「フロー全体の実行ルール」

各手法には、説明だけでなく次を表示する。

- 適用先: 計画、作業、検証、評価、セッション
- 実際に追加される指示文
- tier や purpose などの適用条件がある場合は、その短い要約

フロー全体の手法は、run 専用 tuning により該当する役割と条件へ適用されることを画面上で説明する。内部ファイル名や tuning の保存先は表示しない。

## 更新と状態管理

設定画面では定期更新を行わない。設定画面は監視画面ではなく、現在はユーザー共通ファイルを Dashboard が管理するため、外部変更との常時同期は不要である。

- 設定データは初回表示時だけ取得する。
- 保存・削除後は API の応答でローカル一覧と編集中データを更新する。
- パターンや手法の再取得はアプリの次回起動時でよい。
- 実行状況画面だけが run 状態をポーリングする。
- 新規作成、別フロー選択、別雛形選択だけを明示的な編集状態の切替とする。
- 未保存の編集がある状態で切り替える場合は確認する。

キャンバス操作による局所的な再描画では、選択ノード、スクロール位置、全体表示倍率、開いている追加画面を維持する。

## エラー処理

- 保存できない理由は画面上部だけでなく、該当ノードの近くにも表示する。
- 接続不可は色だけでなく、短い理由文と無効記号で示す。
- 雛形や手法が取得できなくても、保存済みカスタムフローの編集は継続する。
- 雛形の複製に失敗した場合、読み取り専用プレビューは維持する。

## テスト

1. 標準パターンカードが開始から終了までの接続例を表示する。
2. プレビューは読み取り専用で、複製後だけ編集できる。
3. 接続元ごとに推奨ノードが変わり、全ノード一覧も利用できる。
4. 手法ごとに適用先、指示文、適用条件が表示される。
5. 設定タブを開いたまま定期更新が走っても、設定 API と描画を呼ばない。
6. 保存・削除後は API 応答だけで一覧が更新される。
7. ノード選択や接続操作後もキャンバスのスクロールと選択状態が維持される。
8. 実行状況画面のポーリングは従来どおり継続する。
9. 1024px と 1440px で主要なフロー全体を確認できる。

## 既存スキルとの関係

- `ui-designer`: 情報階層、クリック対象、レスポンシブ、アクセシビリティの確認に利用する。
- `systematic-debugging`: 再描画と状態消失の根因確認、回帰テストに利用する。
- `webapp-testing`: 雛形、ノード候補、状態保持を実画面で確認する。
