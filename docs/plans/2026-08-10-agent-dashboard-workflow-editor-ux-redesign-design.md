# Agent Dashboard ワークフローエディタ UX 改訂

## 目的

既存の開始・終了、接続制約、手法ノード、標準パターン複製の実行契約を維持し、次の UX 問題を解消する。

- 雛形カードの説明がはみ出し、固定高さによって一覧が間延びする。
- 空のワークフローを作る入口と、保存済みワークフローを編集する入口が弱い。
- 雛形を選んだ後も一覧ペインと複製確認が残り、編集開始までの操作が多い。
- 計画・評価などのシステム処理と、全体ルールが適用される工程・タイミングが分からない。
- 全体ポーリングによる再描画が、編集中の入力とキャンバス状態を壊す。

## 維持する契約

- 開始と終了を明示し、すべての実行ノードが開始から終了までの経路上にある場合だけ保存する。
- 自己接続、重複、循環、方向違反、split の静的後段を拒否する。
- ノードの tier と手法スナップショットを実行時へ固定する。
- agent-flow の標準パターングラフと役割別の手法適用条件を正典とする。
- 新しいグラフライブラリやカードコンポーネント依存は追加しない。

## 採用する画面構成

### 1. 選択画面と編集画面を分離する

ワークフロー設定の初期表示を、一つのライブラリ画面にする。

- 「保存済み」には既存ワークフローをカード表示し、選択すると直接編集する。
- 「新しく作る」の先頭に「一から作る」カードを置き、その後へ標準の雛形を並べる。
- 雛形を選ぶと、その場で未保存のコピーを作成して編集画面へ移動する。
- 読み取り専用プレビューと「この雛形から作る」は設けない。接続例はカード内のミニフローで確認する。
- 保存済みがない場合も「新しく作る」は常に表示する。

カード全体をボタンとし、クリック可能な見た目、ホバー、可視フォーカスを持たせる。説明は最大 3 行で省略し、全文は `title` ではなくアクセシブルな名前・説明へ残す。カードと説明欄の固定最小高さは廃止し、グリッド項目を上揃えにして内容の少ないカードを引き伸ばさない。

### 2. 編集時はキャンバスだけを主役にする

編集画面に保存済み・雛形の左ペインを残さない。

- ヘッダーに「ワークフロー一覧へ戻る」、名前、説明、全体表示、保存を置く。
- 保存済み、雛形、一から作るのどの入口でも同じ編集画面を使う。
- 未保存の変更がある状態で一覧へ戻る場合だけ、破棄確認を出す。
- 常設の右プロパティペインは置かず、ノード選択時だけ詳細ドロワーを開く。
- キャンバス操作による局所再描画では、選択ノード、スクロール位置、倍率、追加画面を維持する。

## ノード選択

ノード追加の主操作は、ノード右下の「＋」とする。接続元の種類から次に置く候補を最大 3 件へ絞る。

- 開始後: 作業、複数案の生成、分類
- 作業後: 次の作業、検証、終了
- 生成後: 選別、判定、統合
- 検証後: 修正作業、終了
- split 後: 終了のみ

全ノードは「すべての工程」から選べる。ドラッグ追加は副操作として残し、英語の kind ID は主要表示にしない。

## 全体ルールとシステム工程の可視化

全体ルールの選択契約は維持するが、開始ノードの設定だけに隠さない。選択中のルールを実行時の役割と条件へ展開し、実際の適用先をグラフ上へ表示する。

- 対象となる通常ノードへルール名のバッジを表示する。
- ノード編集欄に「この工程に適用されるルール」を設け、役割、条件、追加される指示を表示する。
- 条件不一致や対象ノード不在のルールは「このフローでは適用されません」と明示する。
- planner、evaluator など通常ノード外で実行される処理だけを、実行順に沿った非編集の「システム工程」として表示する。
- システム工程は破線、鍵アイコン、「自動」ラベルを使い、接続端子、ドラッグ、削除操作を持たせない。
- ユーザー定義グラフによって planner を通らない場合は、工程を追加せず「このグラフを使用するため計画を省略」と表示する。
- verify が通常ノードとして存在する場合はシステム工程と重複表示しない。最終検証など別契約で実行される検証だけをシステム工程として扱う。

適用先の判定は Dashboard 独自の説明文から推測せず、agent-flow の role・purpose・条件と同じ語彙で決める。表示と実行結果が一致しない場合はルールを適用済みに見せない。

## 更新と状態管理

設定画面は監視画面ではないため、定期更新で取得・再描画しない。

- 設定データは初回表示時だけ取得する。
- 表示済みの設定画面に対する共通ポーリングの `render` 呼び出しは何もしない。
- 保存・削除後は API 応答でローカル一覧と編集中データを更新する。
- 新規作成、保存済み選択、雛形選択、一覧へ戻る操作だけを明示的な編集状態の切替とする。
- 実行状況画面だけは run 状態のポーリングを継続する。

現行コードでは設定タブ自身の `refresh` は無効だが、共通の `refreshAll` が表示中のフィーチャータブを再度 `render` している。設定タブの描画入口を初回マウント後は冪等な no-op とし、ノード操作で使う局所的な `renderSettings` は維持する。

## エラー処理

- 保存できない理由は画面上部と該当ノードの近くへ表示する。
- 接続不可は色だけでなく、短い理由文と無効記号で示す。
- 雛形や手法が取得できなくても、保存済みワークフローの編集を継続する。
- 雛形の複製に失敗した場合はライブラリに留まり、他のカードを選べる状態を保つ。
- ルールの適用先を判定できない場合は「不明」とせず「適用なし」として安全側に表示する。

## テスト

1. 初期画面に保存済み、「一から作る」、雛形カードが表示される。
2. 保存済みカードは直接編集を開き、雛形カードは未保存コピーの編集を直接開く。
3. 編集画面に左ペインと「この雛形から作る」が存在しない。
4. 雛形カードの説明が最大 3 行に収まり、短いカードが固定高さで引き伸ばされない。
5. 全体ルールが対象ノードのバッジと編集欄へ表示される。
6. planner・evaluator の実行有無と順序が、非編集のシステム工程または省略表示として一致する。
7. 設定画面を開いたまま定期更新が走っても DOM、入力値、選択ノード、スクロール位置が変わらない。
8. 保存・削除後は API 応答だけで一覧が更新される。
9. 実行状況画面のポーリングは従来どおり継続する。
10. 1024px と 1440px でカードと主要なフロー全体を確認できる。

## 既存スキルとの関係

- `ui-designer`: 段階表示、カード密度、クリック対象、フォーカス、レスポンシブの確認に利用する。
- `systematic-debugging`: 共通ポーリングから設定画面が再描画される根因と回帰範囲を確認する。
- `webapp-testing`: ライブラリから編集への遷移、ルール表示、入力保持を実画面で確認する。

## 実装計画

1. `adhoc-flow.js` の初期画面を保存済みと新規作成のカードライブラリへ変更し、雛形選択時のプレビュー状態と複製確認を削除する。
2. 編集画面から `libraryHtml` と左ペインを外し、一覧へ戻る操作と未保存確認をヘッダーへ移す。
3. 既存の手法スナップショットと role 情報から、対象ノードのバッジ、編集欄、非編集システム工程を生成する。
4. 設定画面の初回マウント後は共通ポーリングによる描画を無視し、保存・削除・局所操作の描画だけを残す。
5. 既存の `adhoc-flow.test.js` と UI 契約テストへ遷移、適用先、非ポーリング、カード構造の回帰確認を追加する。
6. ローカル画面で 1024px・1440pxのカード密度、キーボード操作、入力保持を確認する。
