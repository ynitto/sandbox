# agent-app 作業再利用の設計

## 決定

2026-09-13、利用者の「まとめてやってみて。タスク・ワークフローをどっちがいいか判断して定型化」を受け、5案を既存の作成・実行画面へ組み込む。新しいナビゲーションは追加しない。

- 定型化は既存の読み取り専用AI支援に `routine` モードを追加する。会話本文と訂正、参照ファイル名を渡し、`kind/reason/purpose` のJSONを検証する。不正応答は既存の1回修復を使う。種類は利用者が変更可能。手順の多さだけではworkflowにしない。
- 検討には既存CLIを追加で1回呼ぶ。従来の「常時の追加LLM呼び出しを持たない」方針に対し、利用者が明示した定型化操作に限定した例外とする。自動作成・実行はしない。
- 10万文字を超える会話は拒否し、黙って訂正を切り捨てない。3万文字を超える作成依頼、不正な種類、理由や手順の欠落も拒否する。回答品質の保証はしない。
- 手動の1セッション実行は `userData/run-history/<rootのSHA256>.json` に最大100件記録する。ハーネス・定期実行はagent-loopの正典へparametersを追加する。再利用は入力欄への復元だけで、過去の定義の再現ではない。
- `@date:today/yesterday/month/previous-month` は固定文字列の明示的な予約値。UIは解決後の値と日本語の選択肢を表示する。手動はmain、定期は実行時のagentcoreの関数で解決する。設定ロード時には解決しない。実行ホストのローカル日付を使う。
- 実行設定はconfigの `runPresets` に最大20件。保存フィールドを正規化し、repo/worktree/添付は持たない。既存の `run-settings` 内で名前入力を必要時だけ表示する。
- 成果物は相対Markdownリンクまたは行頭の `@artifact relative/path` を明示的な所在として読む。外部URL・絶対パス・親ディレクトリ参照は除外し、開く際は既存main側の境界検査を通す。存在しないファイルのエラーを表示する。作成時のバージョンの保管はしない。

## CI修正

Actions run 34747047126の失敗は、接続失敗時の履歴タブを無効化する旧テストだった。現在の仕様（保存済み履歴を見せ、再取得可能）にテストを合わせる。Electronの共有入力テストも、既存CLIを引き継ぐ実装に合わせて「どれでも」を明示選択して検証する。

## スキルと保存先の選択

知識・判断を再利用するものはスキル、入力から1つの仕事を完了するものはタスク、複数担当の引き渡しを管理するものはワークフロー。工程数だけで分類せず、主な再利用対象と提案理由を示す。ユーザーが種類・内容を修正できる。

保存先は毎回ユーザーが選ぶ。既存のフォルダ追加を利用できる。同一・別リポジトリとも既存の session:create で新しい会話とCLIセッションを作成し、元の会話へ origin を残す。既存のタスク編集セッションを再利用しない。作成は書き込み可能・操作確認ありで開始する。検討と実際の作成を分け、定型化した仕事の実行は含めない。送信失敗時は作成済みの新規会話で依頼を再送できる。
