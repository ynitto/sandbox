# Agent Dashboard ワークフロー実行管理・実行時選択設計

## 背景

ワークフロー画面は、Git リポジトリを対象に `agent-flow` を起動し、カスタムフローの工程ごとに
tier を保存できる。一方、実行時だけ役割・機能別の tier または agent/model を指定する入口、
複数 run の進捗を継続して追う左ペイン、未回答の human interaction を横断して扱う画面、
履歴保持日数の設定がない。

本設計は既存の `adhoc-flow` feature、agent-flow bus、project 実行画面の情報階層を再利用し、
別の実行基盤や名前付き実行プロファイルを追加せずに不足する管理面を補う。

## 採用方針

| アプローチ | 実装コスト | リスク | 保守性 | 拡張性 | 学習コスト | 推奨度 |
|---|---|---|---|---|---|---|
| A. 既存 `adhoc-flow` と run 契約を拡張 | 低 | 低 | 高 | 高 | 低 | ★★★ |
| B. 名前付き実行プロファイルを追加 | 中 | 中 | 中 | 高 | 中 | ★★☆ |
| C. 新しい実行管理基盤を並設 | 高 | 高 | 低 | 高 | 高 | ★☆☆ |

案 A を採用する。実行時指定は run ごとの一時設定とし、投入時に解決結果をスナップショットへ
固定する。再実行は同じスナップショットを引き継ぐが、設定として保存・再利用する機能は作らない。

## 画面構成

ワークフロー領域のタブを次の 4 つにする。

1. **実行** — 新規実行と、選択した run の概要・工程・履歴
2. **要対応** — 未回答の human interaction の集約と回答操作
3. **編集** — 現行「設定」のワークフローライブラリ／エディタ
4. **設定** — 履歴保持日数

現行 `workflow-settings` の内部 ID は移行コストを避けるため維持してもよいが、表示名と責務は
「編集」とする。新しい設定ペインは保持日数だけを持つ。

### 左ペイン

ワークフロー領域を選択したとき、左ペイン下部の既存 `#tree` 領域へ run 一覧を表示する。
他領域のプロジェクト／作業フォルダ一覧と同じコンテキスト一覧の位置を再利用し、全領域へ
run 一覧を常設しない。

各行は次だけを表示する。

- 依頼の先頭またはフロー名
- 状態と進捗
- 更新時刻
- 未回答数（ある場合だけ）

新しい順に並べ、選択中 run を明示する。未回答の run には文字とバッジを併記する。選択すると
実行タブへ移動し、右ペインにその run を表示する。一覧と選択中の概要は定期更新するが、工程詳細と
履歴本文は選択時に取得する。

### 実行タブ

新規実行フォームは上部に置き、選択中 run の詳細を下部へ表示する。右ペイン内に重複する run
一覧は廃止する。詳細は project 実行画面と同じ情報階層を使う。

- **概要** — 状態、進捗、実効 agent/model/tier、主要操作、成果
- **工程** — 既存 bus parser と `renderTaskFlow` によるグラフ、選択工程の入出力
- **履歴** — run event の時系列

既存の再実行、中止、削除は概要へ残す。回答操作は要対応タブを正規の入口とし、概要には
「要対応を開く」導線を出す。

## 実行時の選択

実行フォームへ `自動` と `詳細指定` の 2 モードを置き、既定は `自動` とする。

- `自動`: 現行どおり agent-control / agent-flow が決定する。
- `詳細指定`: 役割または機能ごとに `自動`、`実行レベル`、`エージェント・モデル` を選ぶ。

役割は planner、worker、evaluator、verify を基本集合とし、機能は agent-flow が公開する kind
カタログを使う。行は初期状態で折りたたみ、変更された行だけ要約へ表示する。実行レベルの候補は
既存 `flow-tiers.js` の適格性を使い、agent/model は agent-profiles の利用可能候補から選ぶ。
モデル空欄は選択した agent の既定を意味する。

解決順は次とする。

1. 今回の run の機能別指定
2. 今回の run の役割別指定
3. 編集タブで保存された工程の固定指定
4. agent-control / agent-flow の自動決定

run 指定が保存済み工程設定を上書きすることを詳細指定パネル内に明記する。human は agent を
呼ばないため対象外とする。固定 tier で候補が無い、機能の適格範囲外、agent/model が利用不能な
場合は投入前に失敗させ、下位 tier や別 agent へ黙って切り替えない。

## 実行スナップショット契約

Dashboard は投入時に詳細指定を解決し、inbox へ加算的な `execution_overrides` を保存する。
既存リーダーは未知キーを無視できるため、契約追加中も従来 run を壊さない。

```json
{
  "execution_overrides": {
    "version": 1,
    "roles": {
      "planner": {
        "tier": "large",
        "agent_cli": "codex",
        "model": "gpt-5",
        "source": "run-role",
        "pinned": true
      }
    },
    "kinds": {
      "verify": {
        "tier": "medium",
        "agent_cli": "claude",
        "model": "",
        "source": "run-kind",
        "pinned": true
      }
    }
  }
}
```

Dashboard が symbolic tier を `{agent_cli, model}` へ解決し、agent-flow は run ごとの宣言を
planner、evaluator、静的／動的ノードの実行直前に適用する。lifecycle と hard budget は固定指定でも
迂回しない。実効 tier、agent、model、source、pinned は既存 result/status 台帳へ記録し、画面は
設定から再推測しない。

カスタム plan の静的ノードには既存 per-node `agent` / `tier` を使い、動的に作られるノードと
planner/evaluator には `execution_overrides` を使う。再実行は旧 inbox を複製する既存経路により
同じ指定を引き継ぐ。

## 要対応

要対応タブは保持対象 run の `interactions` から未回答・未期限切れの項目だけを集約する。
各カードは run、工程、確認内容、対象、期限と、interaction mode に応じた次の操作を持つ。

- approval: 承認／却下と任意コメント
- choice: 選択肢と任意コメント
- input: 自由入力

回答は既存 `writeInteractionResponse` を唯一の書き込み口として使う。送信中は二重操作を防ぎ、成功後は
一覧と run 詳細を再取得する。回答済み・期限切れは操作不可で、履歴側からのみ確認できる。

ワークフロー領域と該当 run 行に未回答件数を表示する。要対応タブを開いたときは未回答を最初に映し、
件数だけ光って対象が見えない状態を作らない。

## 履歴保持

`adhocFlow.retentionDays` を追加し、既定 30 日、入力範囲 1〜3650 日とする。設定タブには日数入力と
保存だけを置く。

Dashboard 起動時とワークフロー概要の更新時に、前回掃除から 24 時間以上経過している場合だけ
掃除を行う。対象は次をすべて満たす run とする。

- done / failed / cancelled の終端状態
- 未回答 interaction がない
- 最終更新時刻が保持期限より古い

run ディレクトリ、対応 inbox、run 専用 tuning を同じ対象集合で削除する。実行中、停止中、人待ち、
時刻を判定できない run は削除しない。1 run の削除失敗で残りを止めず、失敗件数を設定画面へ短く
表示する。`lastRetentionSweepAt` を config に保存し、画面ポーリングごとの走査を避ける。

## エラー処理

- 詳細指定の未知 role/kind/tier、候補なし、適格範囲外は投入前に入力箇所へ表示する。
- run 一覧の取得失敗は既存一覧を保持し、一覧領域だけで再試行できるようにする。
- 詳細取得失敗で新規実行フォームと選択状態を消さない。
- interaction の競合回答は「回答済み」として再取得し、重複レスポンスを作らない。
- 保持掃除は終端・未回答なしを再確認してから削除する。

## アクセシビリティ

- 左一覧、内部タブ、詳細指定行、要対応操作をキーボードだけで利用できるようにする。
- 選択、進捗、要対応、失敗は色だけで表さない。
- 操作領域を 44px 相当とし、`focus-visible` を維持する。
- 非同期操作はボタンを無効化し、結果を `aria-live` / `role=alert` で通知する。
- 狭幅では左ペインと詳細を既存のマスター／詳細切替へ載せ、横スクロールを増やさない。

## テスト

最小の回帰確認を次へ置く。

1. Dashboard main: 詳細指定の検証・解決・優先順・inbox スナップショット
2. agent-flow: role/kind override、動的ノード、実効値と source/pinned の記録
3. Renderer: 4 タブ、左 run 一覧、概要／工程／履歴、詳細指定、要対応回答
4. Retention: 終端の期限超過だけを削除し、実行中・未回答・時刻不明を残す
5. 再実行: execution_overrides を引き継ぐ

## 非目標

- 名前付き実行プロファイルの保存・共有
- run ごとの override を既存ワークフローファイルへ書き戻すこと
- agent-flow とは別の実行エンジン／状態ストア
- human interaction 以外の新しい承認プロトコル
- 無期限保持や高度なアーカイブ検索

## 実装計画

1. `execution_overrides` の正規化・解決と agent-flow の適用契約を追加する。
2. Dashboard の overview / submit / resubmit へスナップショットを接続する。
3. 左ペインへワークフロー run 一覧と要対応バッジを追加する。
4. 実行詳細を概要・工程・履歴へ分け、既存 bus parser / graph renderer を再利用する。
5. 実行フォームへ自動／詳細指定を追加する。
6. 要対応タブを追加し、既存 interaction response へ接続する。
7. 現行設定を編集へ改称し、保持日数だけの設定タブと期限掃除を追加する。
8. 境界テストと Dashboard の lint/test を実行する。

## 既存スキルとの関係

- `ui-designer`: 段階表示、左マスター／右詳細、フォーカス、操作領域、状態表現へ反映する。
- `contract-driven-development`: `execution_overrides` と result/status の加算的契約に利用できる。
- `webapp-testing`: 左一覧、4 タブ、詳細指定、回答操作、狭幅表示の実画面確認に利用できる。
- `failure-driven-development`: 保持掃除、候補枯渇、競合回答の失敗境界に利用できる。
