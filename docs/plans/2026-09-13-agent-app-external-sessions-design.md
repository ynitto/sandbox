# agent-app 外部セッション検索・引き継ぎ案

状態: ユーザー承認済み、実装済み。2026-09-13。

## 導線・UIの改訂案

2026-09-13追記: 利用者の指定により、Windows/WSLは内部で横断する。検索条件・結果バッジ・転送設定にはOSやディストリビューションを出さない。内部の取得元識別と実行先判定には保持する。

### 一般的なアプリから借りる操作

| 事例 | 確認した操作 | agent-appへの適用 |

### 入口の決定

サイドバーのアプリ名直下、主要メニューとリポジトリ選択より上に、虫眼鏡と文字の「会話を検索」を常時表示する。タスクやワークフローを開いているときも同じ位置から起動できる。現在の会話の「その他」には入れない。検索範囲は選択中リポジトリに依存せず、すべてのリポジトリを初期値とする。

外部専用の検索とアプリ内検索を別々に増やさず、agent-appの既存会話も同じ結果へ含める。これに伴い現在のサイドバーの「名前で絞り込み」は統合検索へ置き換える。現在のリポジトリに絞る操作は検索内のリポジトリ条件で行う。新しい会話の＋は今までどおり空の会話を作る。

補助導線として、新規会話の空画面に「過去の会話から始める」を小さく表示し、同じ検索画面を開く。入口ごとに別の検索実装は作らない。ショートカットは既存の端末操作との競合を調査してから追加し、端末入力を奪わない。

```text
Agent App
[虫眼鏡 会話を検索]  ← 主な入口

会話
タスク
ワークフロー
共有

リポジトリ [選択 v]
会話                  ＋
  最近の会話…
```

### 検索画面

検索は中央の専用画面に開く。長い会話の比較・プレビューが主目的なので小さなポップアップにはしない。サイドバーは保持し、右上の「閉じる」で直前の画面と入力中の文章へ戻る。元セッションの実行を停止しない。

```text
会話を検索                                      [閉じる]
[会話のタイトル・内容を検索                          ]
[エージェント v] [日付 v] [リポジトリ v] [絞り込み]
------------------------------------------------------
会話一覧                         | 会話のプレビュー
月次集計の修正                   | 月次集計の修正
Copilot · VS Code                | report-repo · 9/13 10:42
report-repo · 9/13 10:42          | 利用者: ...
一致した文章の抜粋…              | AI: ...
                                 |       [ここからfork]
API設計の検討                    |
Claude · CLI                     |
api-repo · 9/12 18:20             | [新しいセッションに引き継ぐ]
[さらに表示]                     |
```

- 空の検索では最近更新された会話を表示。日付の初期値は「指定なし」に改訂し、表示件数だけを段階的に増やす。古い会話を黙って期間外にしない。
- 入力後は短い待ち時間で検索し、Enterで即時反映する。明示的な検索ボタンは置かない。処理中の表示とキャンセルを用意し、古いリクエストの結果で上書きしない。
- 基本条件はエージェント、日付、リポジトリ。追加の「絞り込み」に取得元（すべて/agent-app/CLI/VS Code）、元モデル、アーカイブを置く。条件は選択したものだけ強調し、一括解除できる。
- 結果行はタイトル・エージェント・アプリ・リポジトリ名・更新日時・一致箇所。通常表示にOSや実行環境は出さない。タイトルとリポジトリ名が同じ結果は詳細内の保存先パスで識別できる。
- 内部で同一のネイティブ会話と分かった結果は一つにまとめる。agent-appで管理している会話はその会話として扱う。
- 一回クリックでプレビュー。外部会話の選択だけではセッション作成・AI呼出し・転送をしない。
- 主操作は「新しいセッションに引き継ぐ」。完了応答ごとに補助操作「ここからfork」を置く。キーボードフォーカスでも表示する。agent-app内の結果には補助操作「元の会話を開く」も出す。
- 狭いウィンドウでは一覧→プレビューの1列表示に切り替え、戻る操作で検索条件と位置を保持する。

### 転送設定

操作に応じたタイトルを持つ既存ダイアログの構造を借りる。方法を前の画面で選ぶため、同じ選択をここで繰り返さない。

```text
新しいセッションに引き継ぐ                       [閉じる]
元の会話: 月次集計の修正
保存先        [リポジトリを選択 v] [フォルダを追加]
エージェント  [既存の選択コントロール]
モデル        [既存の選択コントロール]
引き継ぐ内容  [目的・決定事項・進捗・未解決事項を編集]
追加の依頼    [任意]
[詳細な実行設定 v]                [新しいセッションで開始]
```

forkではタイトルを「ここからfork」、元の会話の下に分岐地点の発言抜粋を表示する。モデルは転送先エージェントに連動し、利用可能な候補を既存コントロールで表示。OS・WSL・実行環境欄は作らない。保存先選択から内部で解決する。必要な実行手段が見つからない場合だけ「このフォルダでは選択したエージェントを起動できません」と対処可能なエラーを出す。

借りる作法: 既存サイドバーのアイコン＋ラベル、会話一覧の行、既存会話表示、実行設定のエージェント・モデル・権限選択、リポジトリ選択とフォルダ追加、定型化ダイアログのヘッダー・本文・操作行。色・余白・ボタンは既存の共通スタイルを使う。

## 引き継ぎとforkの意味

- 引き継ぎ: 最新の完了した応答までを対象に、目的・制約・決定・変更と検証・未解決・次の作業を整理して渡す。追加依頼が空なら新規セッションを起動して次の指示を待つ。
- fork: 選択した完了応答までの会話を対象に分岐する。選択地点より後の訂正や結果を含めない。別の依頼を入力でき、同じフォルダも別フォルダも選べる。
- 両方とも新しいagent-appセッションとネイティブCLIセッションを作る。異なるエージェント間では会話から文脈を移す方式であり、元製品の内部状態・キャッシュを複製するネイティブforkではない。この違いは方法選択時に短く示す。
- 元の会話を停止・削除・編集しない。会話のforkはGitブランチやファイルの複製を意味しない。既存のworktree選択を詳細設定で利用できる。
- 元の作業フォルダと参照パスを保持し、転送先のパスと区別する。ファイルや未コミット変更は自動転送しない。Windows/WSL間の解決可能なパスのみ既存変換を使い、存在確認する。
- 検索・プレビューはLLM不要。選択後に既存の要約処理で引き継ぎ案を生成する。要約用AIは選択した転送先のエージェント・モデルを読み取り専用で利用し、確定した内容だけを新規セッションへ送る。

## 検索と一覧

既定は全エージェント・全取得元・全リポジトリ・日付指定なし。Windows/WSL等の環境条件は内部で統合する。期間は今日/昨日/過去7日/過去30日/すべて/範囲指定。既定の日付基準は最終更新日時。詳細条件で作成日時へ切り替え可能。UIのローカル日付をUTCの半開区間へ変換する。

キーワードはタイトル・会話本文の部分一致。詳細条件に作業フォルダ、モデル、取得元（CLI/VS Code）、アーカイブを置く。初期実装は1件選択とし、複数会話の混合要約を避ける。

一覧にはタイトル（なければ最初の利用者発言）、エージェント、取得元、環境、最終更新、作業フォルダ、本文の一致箇所を表示。元モデルが記録されていなければ「不明」。同じ会話を複数の取得元で発見した場合、確認できたネイティブIDで統合し、タイトルだけでは統合しない。agent-app管理済みのものはアプリ内の会話として統合し、重複表示しない。

件数上限・カーソル・検索キャンセルを用意する。メタデータを先に読み、本文検索は対象を絞った後に行う。詳細は選択時に遅延取得する。巨大履歴は段階表示し、検索途中の件数を総件数と誤表示しない。

## 取得対象と環境

| 取得元 | 現状の足場 | 提案 |
|---|---|---|
| Codex / Claude Code | agents定義とagent-auditのJSONL reader | 既存readerを共用。カスタム保存先とアーカイブの検出を拡張 |
| Kiro | agent-auditのSQLite reader | 読み取り用の安全なスナップショット経由で取得 |
| Copilot CLI | 現在のcopilot定義にsession_logなし | 対象バージョンの保存形式を調査し専用reader追加 |
| VS Code内Copilot | VS Code本体に会話保存・JSONエクスポート機能 | CLIとは別の取得元。専用readerと公式JSON取り込み |
| Windowsネイティブの履歴 | agent-appの既存CLI実行経路とは別 | Windowsユーザープロファイルのストアを読み取る |
| WSL内の履歴 | host.jsがディストリビューション別に対応 | 利用可能なディストリビューションを内部で横断検索 |

VS Codeは通常版/Insiders、プロファイル、カスタムuser-data-dir、ワークスペースなしの履歴を区別して検出する。Windowsの標準ユーザーデータ領域を候補にするが、保存先を固定1箇所にはしない。Remote WSLの会話もUI側とリモート側を決め打ちせず、ストアの由来とworkspace URIを保持する。

Windows版agent-appではWindows側と利用可能なWSL側を内部で横断検索する。ユーザーによる環境選択は要求しない。現在の起動処理はWindows上ではWSL経由なので、WindowsのVS Code会話からWSLのCLIへ引き継ぐ構成が既存機能で実現する。WindowsネイティブCLIを転送先として起動する機能は別の拡張として明示し、今回の検索対応と混同しない。

macOSから別PCのWindows履歴は自動取得できない。別PCも対象にする場合は、ユーザーが指定した履歴フォルダまたはエクスポートファイルの取り込みを入口とし、遠隔実行・同期基盤は別途設計する。

VS Codeの内部保存形式は公開連携APIとは見なさない。バージョンごとのJSON/JSONLと更新差分の復元をfixtureで検証する。未対応形式は「0件」にせず、対応状況とJSON取り込み導線を表示する。インライン提案など保存されていない内容まで取得できるとは表示しない。

## 既存実装の流用と必要な拡張

- `tools/agent-audit/agent_audit/sessions.py`: CLI・時間窓・cwdの検索が既存。日付基準、キーワード、カーソル、取得元、環境を追加する。
- `readers.py`: 現在の形式はjsonl-dirとkiro-sqlite。Copilot CLI/VS Codeのreaderをここに集約する。Electron側に同じパーサーを複製しない。
- 既存sessionsコマンドは本文を8000字で切り、agent別cleanルールにも切り詰めがある。表示用抜粋と引き継ぎ用本文取得を分離する。本文の省略・欠損・復元不能を契約として返し、抜粋を全文として要約しない。
- `sessionHandoff.js`: 分割要約・統合要約と引き継ぎプロンプトを再利用。転送用の選択範囲を先に確定し、要約は表示して編集可能にする。
- `session:create` / `session:fork` / `guardedRunTurn`: 新しい起動エンジンを増やさず、外部の出典・選択した実行設定を受け取る共通作成処理へ整理する。現行forkはアプリ内ID必須・別repo限定・元CLI/model固定なので、そのまま外部向けには呼べない。
- 外部出典は既存内部originと分離した `externalOrigin`（source/provider/host/profile/nativeId/境界/取得時刻/要約方式）で保存する。外部IDを内部UUIDとして扱わない。参照元が消えても、新規会話に保存した引き継ぎ内容は読めるようにする。
- host.jsのWindows/WSLパス変換・環境判定と既存のエージェント設定・モデル候補取得を再利用する。

取得層の契約案: discoverSources、searchSessions(query, cursor)、readConversation(sourceKey, boundary)。返却は正規化メタデータ、安定したメッセージID、role/text/time、完全性、取得状態。sourceKeyには環境・ストア・プロファイルを含めて衝突を防ぐ。

検索結果は読み取り専用。検索時の全履歴をagent-appへ複製せず、転送に使った内容と出典だけを新規会話に保存する。既存の資格情報除去は共用し、表示用パスのマスクと実際のローカルフォルダ解決を分離する。

## 失敗時の動作と確認項目

- 該当なし / 保存先なし / 未対応形式 / 読取権限なしを区別。1取得元の失敗で他の結果を消さない。
- 実行中会話は最後に保存済みの完了応答まで取得し、取得時刻を表示。本文読取中に更新されたら再取得して一貫した境界を確定する。
- 長文は省略せず分割要約。読めなかった部分があれば箇所を示し、成功扱いにしない。
- 送信前に転送先の存在・環境・エージェント・モデルを検証。二重クリックで新規会話を重複作成しない。送信失敗後は同じ新規会話へ再送できる。
- fixture: 各CLI、VS Code JSON/JSONL、プロファイル、空ウィンドウ、壊れた末尾、SQLite更新中、日時不明、モデル変更、長文、重複。
- Electron: 検索条件→選択→本文→範囲→転送先エージェント/モデル変更→新規起動、キャンセルと戻る、元セッション不変。
- Windows実機: Windows Copilot履歴とWSL履歴の横断検索、Unicode/空白パス、複数ディストリビューション、Windowsの履歴→WSL CLIで新規起動。

## Decision Record

提案: 既存readerを共用した統合検索と、選択した文脈からの新規起動。理由: 検索・会話理解・起動の責務を分け、異なるエージェント間でも同じ操作にできる。承認状態: 未承認。トレードオフ: 外部ストア形式の保守が必要で、元製品の内部状態を完全再現するforkではない。再評価条件: Windowsネイティブ起動や別PCへの直接接続が必須となった場合。

## 改訂判断

ユーザー確定事項: Windows/WSLの明示は不要。内部で横断検索する。

## 実装記録

サイドバーの統合検索入口、プレビュー、境界を指定したfork、保存先と実行設定の選択、新規セッション起動を追加。JSON取り込みと追加保存先は設定に保持する。本文検索はプロセス内の走査で行い、永続的な全文索引は追加していない。巨大ファイル・時間上限は明示的な取得エラーとする。ネイティブストアの完全複製ではなく、取得可能な会話本文の要約を移す方式。
