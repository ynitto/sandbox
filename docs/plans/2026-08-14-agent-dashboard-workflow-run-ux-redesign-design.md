# Agent Dashboard ワークフロー実行画面 UX 再設計

## 背景

現在のワークフロー画面は、新規実行フォームと選択中 run の詳細を同じ縦長画面へ配置している。
左ペインで実行中のワークフローを選んでも画面全体は切り替わらず、下部の詳細だけが更新されるため、
左の選択対象と右画面の主題が一致しない。

また、画面内でコントロール、カード、文字、余白の寸法体系が統一されていない。小さすぎる入力や
ボタンと、情報量に対して大きすぎるカードが混在し、視認性と操作性を損なっている。
`codd-gate` は本来ほかの作業手法と同列の作業ルールだが、新規実行フォームで専用チェック項目として
扱われ、必要以上に特別な機能に見える。

本設計では、ワークフローの作成と run の監視を別画面へ分離し、プロジェクト実行画面と同じ
「左で対象を選ぶと右側全体が対象画面になる」情報構造へ統一する。

## 採用方針

| アプローチ | 実装コスト | リスク | 保守性 | 拡張性 | 学習コスト | 操作性 | 推奨度 |
|---|---|---|---|---|---|---|---|
| A. 作成画面と run 詳細画面を分離 | 中 | 低 | 高 | 高 | 低 | 高 | ★★★ |
| B. 同一画面内で作成・詳細モードを切り替え | 低 | 中 | 中 | 中 | 中 | 中 | ★★☆ |
| C. run 詳細を別ウィンドウにする | 高 | 高 | 低 | 中 | 高 | 中 | ★☆☆ |

案 A を採用する。ワークフロー領域の初期表示を作成画面とし、左ペインで run を選んだ場合は
右ペイン全体を独立した run 詳細画面へ切り替える。新しいウィンドウや実行基盤は追加しない。

## 情報構造

### ワークフロー作成画面

ワークフロー領域を選び、run が選択されていないときに表示する。

- 新規実行の依頼入力
- 設計セッション
- フロー選択
- 今回だけの実行方針
- 実行操作

選択中 run の概要、工程、履歴はこの画面へ表示しない。実行開始に成功した場合は、作成された run を
左ペインで選択状態にし、その run の詳細画面へ遷移する。

### run 詳細画面

左ペインの実行履歴を選んだときに表示する。新規実行フォームと設計セッションは表示しない。

上部はプロジェクト実行画面と同じ情報階層に揃える。

- run の依頼名または短い要約
- 状態、進捗、経過時間、最終更新
- 使用中のフローと実効実行方針
- 再実行、中止、削除などの主要操作
- 作成画面へ戻る「新しく実行」導線

本文は以下の内部タブで構成する。

1. **概要** — 現在の状態、成果、失敗理由、実効 agent/model/tier、未対応の有無
2. **工程** — 既存の工程グラフ、選択工程の状態・入力・出力
3. **履歴** — 選択中 run のイベント時系列

左ペインの選択状態、右画面の見出し、取得する run ID を常に一致させる。詳細取得に失敗した場合も
選択は維持し、右画面内に再試行操作を表示する。古い run の内容を別の選択対象として見せない。

### 左ペイン

run 行は最小限の情報に絞る。

- 依頼の先頭またはフロー名
- 文字を伴う状態表示
- 進捗
- 更新時刻
- 未対応件数（存在する場合のみ）

行全体を選択操作にし、44px 以上の操作領域を確保する。選択すると `workflow-run` タブへ移動し、
run 詳細画面を描画する。ワークフロー領域そのもの、または「新しく実行」を選ぶと run 選択を解除し、
作成画面へ戻る。

## codd-gate の位置づけ

新規実行フォームにある `codd-gate` 専用チェック項目を廃止する。`codd-gate` は、ほかの手法と同じ
作業ルールカタログの項目として扱う。

- 同じカードまたは一覧行
- 同じ選択操作
- 同じ説明、適用条件、反映元の表示
- 同じ保存・実行時解決経路

`codd-gate` に必要な verify コマンドや完了条件は作業ルール側の契約から run へ解決する。
専用の強調色、独立セクション、常設チェックボックスは設けない。適用中であることは、実行概要の
「適用された作業ルール」の一項目として確認できるようにする。

## 寸法と視覚階層

ワークフロー画面内の局所的な数値指定を整理し、既存テーマへ共通寸法トークンを追加する。

| 対象 | 基準 |
|---|---|
| 通常ボタン、入力、select | 高さ 44px 以上 |
| アイコンボタン | 44×44px 以上 |
| 隣接する操作 | 8px 以上の間隔 |
| カード内余白 | 標準 16px、密な補助領域 12px |
| 本文 | 14〜16px、行高 1.5 以上 |
| 補助文 | 12〜14px。主要情報には使わない |
| セクション間 | 24px を基本 |
| 主要コンテンツ幅 | 作成・詳細で同一の max-width |

主要操作と通常操作の差は色と強調度で表し、無秩序な高さの差では表さない。カードは意味のある
情報単位にだけ使用し、ラベル一つのために大きなカードを作らない。クリック可能な要素には hover、
pointer cursor、`focus-visible` を持たせる。状態と進捗は色だけに依存せず文字を併記する。

## レスポンシブ

広幅では左ペインと右詳細を同時表示する。狭幅では既存のマスター／詳細切替へ載せ、run 選択後は
詳細を前面に表示し、明示的な戻る操作で一覧へ戻れるようにする。横スクロールは工程グラフや
コード出力など本質的に幅を必要とする領域へ限定する。

375px、768px、1024px、1440px を確認幅とする。固定幅の入力やカードによって画面全体に
横スクロールを発生させない。

## 状態遷移

```text
ワークフロー領域を開く
        ↓
作成画面（run 未選択）
   ├─ 実行開始成功 ─→ 作成した run の詳細画面
   └─ 左の run 選択 ─→ 選択した run の詳細画面

run 詳細画面
   ├─ 左の別 run 選択 → 別 run の詳細画面
   ├─ 新しく実行 ───→ run 選択解除・作成画面
   └─ 削除成功 ─────→ run 選択解除・作成画面
```

選択状態は renderer の単一状態を正とする。タブのクリック、左ペインのクリック、実行成功、削除成功の
各経路が同じ画面切替関数を呼ぶようにし、部分描画の組み合わせで画面状態を作らない。

## エラー処理

- run 詳細の読み込み失敗時は対象名と選択状態を維持し、詳細領域で再試行できるようにする。
- 左一覧の更新失敗時は既存一覧を消さず、一覧領域に更新失敗を表示する。
- 実行開始中、再実行中、削除中は該当操作を無効化し、二重送信を防ぐ。
- 削除後に同じ run を表示し続けず、作成画面へ戻す。
- 定期更新では入力中の作成フォームや現在の内部タブを失わない。

## テスト

1. 左ペインで run を選ぶと、作成フォームが消え、選択 run 専用画面になる。
2. 選択 run を変更すると、見出し、詳細、操作対象が同じ run ID に切り替わる。
3. 「新しく実行」で選択が解除され、作成画面へ戻る。
4. 実行開始後は作成された run の詳細画面へ遷移する。
5. run 削除後は作成画面へ戻り、削除した run が選択状態に残らない。
6. `codd-gate` 専用チェック項目がなく、通常の作業ルールとして選択・解決される。
7. ボタン、入力、select、左ペイン行が 44px 以上の操作領域を持つ。
8. キーボード操作、可視フォーカス、状態の文字表現が維持される。
9. 375px、768px、1024px、1440px で画面全体の不要な横スクロールがない。
10. 既存の概要／工程／履歴、再実行、中止、削除、interaction が回帰しない。

## 非目標

- agent-flow の実行基盤や bus 契約の刷新
- run 詳細用の別 Electron ウィンドウ
- ワークフローエディタそのものの機能追加
- 作業ルール全体の保存形式変更
- 新しい配色やブランドデザインへの全面変更

## 実装計画

1. 作成画面と run 詳細画面の renderer 状態・描画関数を分離する。
2. 左ペイン選択、実行成功、削除、「新しく実行」を単一の画面遷移へ接続する。
3. run 詳細ヘッダーと概要／工程／履歴をプロジェクト実行画面の情報階層へ揃える。
4. `codd-gate` 専用入力を削除し、作業ルールの通常選択・解決経路へ統合する。
5. 共通寸法トークンを追加し、ワークフロー領域のボタン、入力、カード、余白を置き換える。
6. 狭幅のマスター／詳細遷移と戻る操作を整える。
7. renderer の境界テスト、既存テスト、ESLint、実画面のレスポンシブ確認を行う。

## 既存スキルとの関係

- `ui-designer`: 44px 操作領域、視覚階層、フォーカス、レスポンシブ基準へ反映した。
- `webapp-testing`: 画面遷移、選択一致、狭幅表示の実画面検証に利用できる。
- `systematic-debugging`: run 選択で画面が切り替わらない既存挙動を修正する際の原因追跡に利用できる。
- React 系スキルはプレーン Electron renderer のため対象外とする。
