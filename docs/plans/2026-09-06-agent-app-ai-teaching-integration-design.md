# agent-app AI教示タスク統合設計

> 作成日: 2026-09-06  
> 対象: `tools/agent-app`、`tools/statemachine-maker`

## 背景と目的

statemachine-maker に実装したAI中心の教示機能を、agent-app の既存の「会話 / タスク / ワークフロー」構造へ統合する。独立した作成画面や設定を増やさず、通常の会話で見つけた反復可能な依頼を、その文脈を保ったまま再利用可能なタスクへ変換できるようにする。

画面上の概念名は両アプリで「タスク」に統一する。内部互換のため `machine`、`workflow`、`teaching` などの識別子と保存形式は変更しない。

## 採用する接続

```text
通常の会話
  └─ この依頼をタスクにする
       ↓ 依頼・添付・リポジトリ・AI設定を引き継ぐ
タスク > AI教示
  └─ 質問 → 必要時だけ見本 → 試運転 → 結果確認
       ↓
既存のタスク詳細 > 実行・定期実行・履歴
```

- agent-app の「新しいタスク」はAI教示画面を開く。
- 会話中の利用者メッセージから「この依頼をタスクにする」を選べる。
- 引き継ぐのは選択した依頼本文、明示された添付、リポジトリ、現在のAI実行設定だけとし、会話全体や思考ログは渡さない。
- 教示完了後は同じタスクを選択した詳細画面へ遷移し、既存の実行、定期実行、履歴を利用する。
- 既存タスクの変更も最初にAI教示を開き、工程編集は「高度な編集」へ残す。
- statemachine-maker の教示モデル、保存、承認、試運転、AI契約を共通実装として利用し、agent-app 独自の複製を作らない。

## UIと用語

通常画面では次の語彙を使う。

| 変更前 | 変更後 |
|---|---|
| 仕事 | タスク |
| 新しい仕事を教える | 新しいタスクを教える |
| 仕事を教える | タスクを教える |
| 変更したいことをAIへ伝える | タスクの変更をAIへ伝える |

agent-app の主要ナビゲーションは引き続き「会話 / タスク / ワークフロー」の3領域とする。AI教示を第4領域や別ウィンドウにはしない。タスク領域の中央だけを、一覧、教示、詳細、高度な編集の状態で切り替える。

## データとイベント境界

会話からの引き継ぎは一時的な `task teaching intent` として親画面から埋め込み画面へ送る。

- `root`: 登録済みリポジトリ
- `purpose`: 選択した利用者メッセージ
- `attachments`: 利用者がその依頼へ明示した添付の参照
- `agent` / `model`: 現在の実行設定
- 一回限りの `intentId`

埋め込み画面はintentを受け取ったら教示セッションを作成し、同じintentの再送では重複作成しない。教示セッションの保存後は既存の一覧更新イベントを親へ返し、利用可能化されたら選択中タスクを正式なmachine IDへ切り替える。

rendererはファイルへ直接書かない。すべて `api.automation.*` と登録済みリポジトリ検査を通す。秘密値の除去、重要操作の承認、分離試運転はstatemachine-maker側を正典とする。

## エラーと回復

| 状態 | 回復 |
|---|---|
| リポジトリ未選択 | タスク化を無効にし、リポジトリ選択を案内する |
| iframe未準備 | intentを親に保持し、準備完了通知後に一度だけ再送する |
| 教示セッション作成失敗 | 元の会話を維持し、再試行できる通知を出す |
| AI・記録手段不足 | 教示画面で不足した準備だけを案内する |
| 試運転失敗 | 候補を正式保存せず、結果をAIへの追加証拠に戻す |
| 完了通知の欠落 | タスク一覧再読込で保存済み定義を復元する |

## 検証

1. 会話内の利用者メッセージからタスク化し、同じリポジトリ・本文で教示が始まる。
2. 「新しいタスク」から空の教示を始められる。
3. intentの再送で下書きが重複しない。
4. 教示完了後にタスク一覧と詳細が更新され、そのまま実行できる。
5. 両アプリの通常画面に「仕事」が残らない。
6. 既存の会話、タスク実行、ワークフロー、高度な編集が回帰しない。
7. Electron実機で親画面とiframe間の遷移、フォーカス、横スクロール、コンソールエラーを確認する。

## 検討した案

| アプローチ | 実装コスト | リスク | 保守性 | 拡張性 | 学習コスト | 推奨度 |
|---|---|---|---|---|---|---|
| A. タスク領域へ統合し会話から引き継ぐ | 中 | 低 | 高 | 高 | 低 | ★★★ |
| B. タスク領域だけに教示を埋め込む | 低 | 低 | 高 | 中 | 低 | ★★☆ |
| C. agent-app独自に教示機能を再実装する | 高 | 高 | 低 | 高 | 中 | ★☆☆ |

## 既存スキルとの関係

- `statemachine-use`: 完成したタスクの実行形式と構成検査を担う。
- `playwright-cli` / `windows-app-automation`: 必要な場合だけ操作の見本を取得する。
- `test-driven-development`: 親画面、iframe、IPCを通る垂直スライスを固定する。
- `risk-driven-development`: 状態同期と既存実行導線の回帰を先に検証する。
