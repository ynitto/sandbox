# Agent Dashboard から旧プロジェクト状態を移行する

このガイドでは、`verification_plan` / `receipt.json` 導入前から残っている未完了タスクを、
agent-dashboard から新しい実行へ積み直す。完了済みタスクと過去の実行記録は移行しない。

## 対象を判断する

次のすべてに当てはまるタスクだけを移行する。

- agent-project の backlog に残っている。
- 関連する旧 run がある。
- 旧 run に検証計画または検証結果がなく、タスクを完了にできない。
- 同じ成果を新しい検証方式で再実行する必要がある。

次のデータはそのまま利用できるため、移行しない。

- `archive/` へ移動済みの完了タスク
- `DELIVERY.md` の納品記録
- 完了済みrunの成果物、イベント、グラフ
- 旧形式の `verify`、`accept`、`acceptance`
- 旧表記の `canceled` run

旧形式の完了条件は、次の新しい実行を始めるときに agent-project が
`verification_plan` へ読み替える。状態ファイルを直接編集する必要はない。

## 5分で移行する

### 1. 実行エンジンを確認する

agent-dashboard で対象プロジェクトを選び、**実行**タブを開く。
画面上部が **実行エンジン: 稼働中** であることを確認する。

停止または応答なしの場合は、先に agent-project の常駐体を復旧する。
停止中でも移行指示は保存されるが、新しい実行は常駐体の復旧後に始まる。

### 2. 対象タスクを開く

1. **タスク**タブを開く。
2. backlog に残っている対象タスクを選ぶ。
3. 詳細の **タスクを修正** を開く。

アーカイブ側の同名タスクではなく、未完了のbacklogタスクを選ぶ。

### 3. 新しい実行へ積み直す

**変更してほしいこと**へ、次の文面を入力する。

```text
旧runを継続せず、verification_plan/receipt方式の新しい実行として再実行する。
```

タスク名、受入基準、検証コマンド、依存関係は変更せず、**修正を送信**を押す。

この操作は既存の `revise` 契約を使う。agent-project は次を自動で行う。

1. 実行中の旧runを中止してタスクから切り離す。
2. 旧runを履歴として残す。
3. タスクの `rev` 世代を上げる。
4. 旧 `verify` などを新しい `verification_plan` へ読み替える。
5. 新しいrunを開始し、検証後に `receipt.json` を受け取る。

## 移行結果を確認する

agent-dashboard を再読み込みし、次を確認する。

- **タスク**: 対象タスクが `ready` または `doing` になっている。
- **実行**: 旧runが中止済みとして残っている。
- **実行**: 同じタスクに新しい試行が追加されている。run IDには通常 `-v1` 以降の世代が付く。
- **要対応**: 新しい検証に失敗した場合は、新しいrunに対する判断待ちが表示される。
- **成果**: 完了時は新しい検証結果を根拠に成果を確認できる。

指示を送信してもタスクが変わらない場合は、プロジェクトの実行エンジンと
`commands` の処理結果をagent-dashboardの技術情報で確認する。

## 再開操作と使い分ける

移行では、次のボタンを使わない。

- **そのまま再実行**
- **失敗した工程だけやり直す**
- **同じ内容でやり直す**

これらは既存runの `resume-run` を行い、完了済み工程を温存するための操作である。
旧runに `verification_plan` がない場合は、旧契約もそのまま温存される。

| 状況 | agent-dashboard の操作 |
|---|---|
| 旧runを新しい検証方式へ移す | **タスクを修正** → 指示を入力 → **修正を送信** |
| 現行方式のrunで一部工程だけ失敗 | **そのまま再実行** または **失敗した工程だけやり直す** |
| 検証コマンド自体を変更する | **要対応** → **検証コマンドを変更** → **変更して再実行** |
| 完了済みタスクを閲覧する | 移行せず **成果を確認** |

## 現在の sandbox-project を移行する

今回確認した対象は次の1件である。

- プロジェクト: `sandbox`
- タスク: `enq-20260718-163827`
- 旧run: `req-48d24769-enq-20260718-163827-r1`

agent-dashboard で **タスク** → **enq-20260718-163827** → **タスクを修正** と進み、
上記の移行文面を入力して **修正を送信**する。

旧runの **中止** ボタンでも実行中タスクは `revise` 経路へ送られるが、移行理由を判断記録へ
明示できるため、通常はタスク詳細から送信する。

## 他のプロジェクトへ適用する

移行はプロジェクト単位ではなく、未完了タスク単位で行う。

1. 完了済みデータは変更しない。
2. 検証結果がない旧runに紐づく未完了タスクだけを選ぶ。
3. タスク詳細から同じ移行文面を送る。
4. 新しいrunと検証結果を確認してから次のタスクへ進む。

一括変換スクリプトは使用しない。既存の読み取り互換と `revise` の自動変換で足りるため、
状態ファイルの直接書換えは不要である。

## 問題が起きた場合に戻す

- 旧runやarchiveは削除しない。監査記録と成果物を残す。
- 誤った指示は、対象タスクの **タスクを修正** から再度修正する。
- 新しいrunを途中で止める場合は、**実行**タブで対象runを開き、**中止**を押す。
- プロジェクト全体のリセットは使わない。charter以外の履歴と成果まで削除される。

## 実装上の対応関係

| agent-dashboard | 内部操作 | 結果 |
|---|---|---|
| **修正を送信** | `revise` | 旧runを切り離し、新しい `rev` 世代へ積み直す |
| **そのまま再実行** | `resume-run` | 同じrunを継続し、失敗・未実行工程だけ再実行する |
| **中止** | `cancel` + 実行中タスクの `revise` | runを終端化し、backlogタスクを新しい試行へ戻す |
| **変更して再実行** | `revise` + `fields.verify` | 検証コマンドを置換して新しい試行を作る |
