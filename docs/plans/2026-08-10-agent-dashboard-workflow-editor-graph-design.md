# Agent Dashboard ワークフローエディタ改訂

> 2026-08-09 のワークフロー画面設計を補強し、実行経路、接続操作、ノードの意味、雛形編集を明確にする。

## 目的

- 無関係なノードを置いても実行対象へ紛れ込まないよう、開始と終了を明示する。
- 接続の始点、方向、接続可否、解除方法を操作中に理解できるようにする。
- ノード名だけでなく、実行内容、種類、tier、実行手法をキャンバス上で判別できるようにする。
- 実行手法を具体的なノード雛形として利用する。
- agent-flow の標準パターンを複製可能な編集雛形として提供する。

## 前例から採用する要素

- n8n: Trigger を最初に選ばせ、ノード上へ説明を表示し、雛形を複製して編集する。
- Node-RED: 左入力／右出力ポート、ドラッグ接続、クリック代替、線選択と削除。
- React Flow: 接続中に共通バリデータで接続可否を判定し、有効な接続先だけを強調する。

n8n の暗黙的な終了は採用しない。agent-flow のカスタム plan は配置された DAG 全体を実行するため、明示的な終了と経路検証の方が意図しない実行を防げる。

## 採用設計

### 開始と終了

各フローに構造ノード `開始` と `終了` を 1 個ずつ持たせる。両者はエディタにだけ存在し、agent-flow の plan には含めない。

- 開始: 入力なし、複数出力可。plan 上のルートノードだけへ接続できる。
- 終了: 複数入力可、出力なし。plan 上の末端ノードだけから接続できる。
- 保存条件: 全実行ノードが開始から到達でき、終了へ到達できること。
- 既存 version 1 フローは、ルート群を開始へ、末端群を終了へ接続して version 2 として読み込む。

保存形式では実行ノードの `deps` を正典とし、開始の接続先を `entry`、終了の接続元を `exit` に保存する。

### 接続操作

- 入力ポートを左、出力ポートを右へ常時表示する。
- 出力ポートから入力ポートへドラッグすると追従線を表示する。
- 接続中は接続可能な入力だけを強調し、不可能な入力は無効表示にする。
- 無効な場所へ落とした場合、自己接続、重複、循環、開始／終了の向き、split 制約のいずれかを短文で示す。
- 出力ポートをクリックしてから入力ポートをクリックするキーボード代替を残す。
- 接続線を選択して Delete / Backspace で解除できるようにする。
- 出力横の追加ボタンからノードを選ぶと、配置と接続を一度に行う。

接続制約は agent-flow が実際に持つ契約だけを表現する。

- 出力から入力への一方向のみ。
- 自己接続、重複、循環は禁止。
- `split` の後段は実行時に動的生成されるため、通常実行ノードへの静的接続は禁止。終了へは接続できる。
- 現行 agent-flow に型付きデータポートはないため、見かけだけの型制約は追加しない。

### ノード表示

ノードカードには次を表示する。

- 表示名
- 実行内容の先頭 2 行
- 日本語の種類名
- tier
- 実行手法名

右ペインでは表示名、安定 ID、実行内容、種類、tier、手法の説明を編集・確認する。種類の英語 ID だけを主要表示にしない。

### 実行手法

既存の実行手法カタログを再利用し、パレットに `基本工程` と `実行手法` を分けて表示する。

- worker / verify / evaluator の fragment を持つ手法は、対応する kind と指示を持つ実行ノードとして追加する。
- 手法の ID、説明、fragment、source をノードへスナップショット保存する。
- planner / session 専用手法は偽の実行工程にせず、開始ノードの `フロー全体の手法` として選択する。
- ノード手法の fragment は当該ノードの goal にだけ反映する。フロー全体の手法は既存の run 専用 tuning snapshot を使う。

### 標準パターン雛形

agent-flow を標準パターングラフの正典とする。パターン一覧 API に編集用の標準グラフを含め、Dashboard 側で再実装しない。

- 設定画面の一覧に `標準パターン` と `カスタム` を分けて表示する。
- 標準パターンは読み取り専用でプレビューする。
- `複製して編集` で新しいカスタムフローを作り、以後は独立ファイルとして保存する。
- 複製時に開始／終了と自動レイアウトを付与する。

## エラー処理

- 保存時と接続時は同じグラフバリデータを使う。
- 孤立ノードと無効接続は色だけで示さず、ノード上の短い状態文と `aria-live` で通知する。
- パターン雛形や手法カタログが読めない場合も、基本工程と既存カスタムフローの編集は継続できる。

## テスト

1. version 1 フローの開始／終了移行と version 2 の往復。
2. 孤立、自己接続、重複、循環、split 後段を保存前に拒否する。
3. 構造ノードを plan から除外し、entry / exit が実行ノードの deps を変えない。
4. 手法ノードの role→kind 変換、fragment snapshot、フロー全体手法 snapshot。
5. 標準パターン雛形を複製してカスタムフローとして保存できる。
6. ドラッグ接続、クリック代替、線削除、有効先強調、ノード追加＋自動接続を Playwright で確認する。
