agent-app / statemachine-maker · UI案 2026-09-06

既存タスクは「実行できる画面」を先に出す

statemachine-use スキルでチャットから作った .statemachine/<名前>/ は、それ自体が完成した実行物です。今の画面はそれを「教示の途中」として開くため、編集中のように見え、実行までの道が遠くなっています。案は「利用可能なものは実行画面から始め、AIとの変更は明示操作で開く」の一点です。

A. 現状と提案

同じタスク「リリース確認」を開いたとき

左が現状、右が提案。サイドバーは agent-app のもので、中央が共有ワークベンチ。

  • 1見出しが「タスクを教える」で、状態が「下書き」。定義は揃っているのに未完成に見える。
  • 2進行バーの先頭が点灯し、「まだ4段階中1段目」と読める。既存定義には無関係な情報。
  • 3会話欄と「AIの理解（すべて なし）」が画面の大半を占め、何をすればいいか迷う。
  • 4提案では名前の横に「利用可能」を1つだけ置く。変更を頼む操作は副操作として右に寄せる。
  • 5「実行」がカードの主ボタン。定義があるものは、開いた直後に実行できる。
B. 提案の3つの状態

状態は「定義があるか」と「AIとの変更が進んでいるか」の2軸で決まる

画面に出す状態語は4つだけ（利用可能／下書き／試運転待ち／確認待ち）。定義があるものは常に「利用可能」で、変更の進み具合は別の印として添える。

C. 「AIに変更を相談」を押したあと

既存タスクの教示画面は「変更を相談する場」として開く

状態は引き続き「利用可能」。進行バーはAIが候補を作ってから出す。いつでも「実行画面へ戻る」で戻れる。

D. ステート条件

表示と実行可否を決める条件

判定は main 側の1関数に置き、standalone の statemachine-maker と agent-app の埋め込みで同じ結果になる。

表示条件実行最初に開く画面
利用可能workflow.yaml がある。teaching.json が無い、または status が readyできる実行詳細
利用可能 変更中 · 下書き / 試運転待ち / 確認待ちworkflow.yaml があり、teaching.json の status が ready 以外できる（今の版）実行詳細 + 変更中バナー
下書きworkflow.yaml が無く、候補（generation）も無いできない教示
試運転待ちworkflow.yaml が無く、候補はあるが成功した試運転が無い試運転のみ教示
確認待ちworkflow.yaml が無く、成功した試運転がある「期待どおり」で公開教示
E. 検討した案

3案の比較

採用

1. 実行詳細を先に出し、教示は明示操作

既存の実行画面（概要／手順／履歴）を入口にし、「AIに変更を相談」で教示を開く。追加する画面は無く、状態語も既存の4つで済む。

見送り

2. 教示画面に実行カードを埋め込む

画面は1つになるが、会話・理解・実行・定期実行・履歴が縦に積まれて長くなる。狭い幅で横スクロールか折りたたみが増える。

見送り

3. 教示画面のラベルだけ直す

「下書き」を「利用可能」にするだけでは、会話欄が主役のままで「編集中に見える」根本は残る。
