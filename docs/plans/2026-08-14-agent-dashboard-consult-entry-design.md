# Agent Dashboard 共通 AI 操作の再設計

## 背景と目的

Agent Dashboard の「AIに相談」は領域によって表示場所と対象フォルダの決め方が異なり、
ワークフロー詳細やミッション詳細では操作自体が見つからない。前回案は入力フォーム内へ
個別にボタンを差し込み、設定値を `control.json` へ保存していたため、画面間の一貫性と
「全体設定 ＞ アプリ設定でカスタマイズする」という要件を満たしていなかった。

本設計では、プロジェクト・ワークフロー・ミッション・定常業務の全画面で、現在の対象と
「AIに相談」を同じ位置、同じ見た目、同じ挙動で提供する。また、Agent Dashboard が独自に
起動する AI のエージェントとモデルをアプリ設定から一括上書きできるようにする。

## 対象範囲

設定の対象は Agent Dashboard 自身が直接行う次の AI 呼び出しに限定する。

- プロジェクトの下書き・推敲
- 作業ルールと受入条件の下書き
- Doctor、項目別診断、対話診断
- タスク補助と計画調整
- 外部 CLI で開く「AIに相談」

`agent-project`、`agent-loop`、`agent-flow`、`agent-audit`、`agent-amigos` など、各エンジンへ
実行を委譲するときのエージェント選択、工程別指定、役割別指定は変更しない。

## 検討したアプローチ

| アプローチ | 実装コスト | リスク | 保守性 | 拡張性 | 学習コスト | 操作性 | 推奨度 |
|---|---|---|---|---|---|---|---|
| A. 全画面共通のコンテキスト操作バー | 中 | 低 | 高 | 高 | 低 | 高 | ★★★ |
| B. フォルダ入力・選択欄の横へ個別配置 | 中 | 中 | 中 | 中 | 中 | 中 | ★★☆ |
| C. アプリ共通ヘッダーの一個から対象を推測 | 低 | 高 | 中 | 低 | 低 | 低 | ★☆☆ |

案 A を採用する。案 B は詳細画面のように入力欄がない画面で配置規則が崩れ、案 C は画面遷移後に
古い対象が残る誤操作を再発させる。共通操作バーなら、対象解決だけを領域別アダプターへ分離し、
表示と起動処理を一つに保てる。

## 情報設計とレイアウト

各画面のページ見出し直下に、共通の「AI操作バー」を一つ置く。

- 左側にラベル「対象」と現在のフォルダを表示する。
- プロジェクト領域だけは、選択中プロジェクトの `repos.json`（互換入力として既存の
  `repos.yaml` / `repos.yml` も読み取り可）から解決したフォルダ候補を同じ場所に表示する。
- 右側に主操作「AIに相談」を常時表示する。
- 対象が未確定または利用不能でもボタンを消さない。無効化し、直下に理由を文字で示す。
- エージェント名やモデル名は通常表示へ追加しない。ボタンの `title` とアクセシブルな説明で
  実効値と決定元を確認できるようにし、画面の情報密度を増やさない。
- 768px 未満では対象と操作を縦積みにする。ボタンと選択 UI は最低 44px の操作領域を持つ。

相談ボタンの名称は全画面で「AIに相談」に統一する。「この作業を相談」「CLIチャット」などの
実装由来の名称は画面へ出さない。Doctor の項目別「AIに相談」は、対象が個別項目であることを
明示する補助文を付け、共通バーとの違いを判別できるようにする。

## 対象フォルダの解決

対象解決は、表示中画面の記録を唯一の入力とする。相談専用の選択状態は持たない。

| 領域 | 一覧・入力画面 | 詳細画面 |
|---|---|---|
| プロジェクト | 選択中プロジェクトの `repos.json` から選択したローカルフォルダ | 同じ選択を維持 |
| ワークフロー | 実行フォームへ入力または履歴から選択したフォルダ | run に記録された cwd / workspace |
| ミッション | 依頼フォームへ入力または履歴から選択したフォルダ | mission に記録された workspace |
| 定常業務 | 左ペインで選択中の作業フォルダ | 選択中の作業フォルダ |

記録が WSL パスの場合は、既存の WSL／ホスト変換処理を使って起動可能な cwd へ正規化する。
変換または実在確認に失敗した場合は、別のフォルダへ暗黙にフォールバックせず理由付きで無効化する。

プロジェクトの候補はレジストリに登録されたリポジトリだけに限定する。このノード上のローカル clone を
既存のノード別リポジトリ宣言から照合し、見つからない候補も一覧から消さず理由付きで無効表示する。

## Dashboard AI のアプリ設定

全体設定 ＞ アプリ設定へ「Dashboard AI」を一組追加する。

- エージェント: 「実行方針に従う」または利用可能な Agent CLI
- モデル: 空欄で実行方針に従う、入力時だけ上書き
- 待ち時間: 既存の Dashboard AI 呼び出し用タイムアウト

保存先は Agent Dashboard のアプリ設定（既存の `config.agent`）とする。`control.json` へは書かない。
解決順は次のとおりとする。

1. アプリ設定で明示した `config.agent.cli` / `config.agent.model`
2. `workload: dashboard` の実行方針（purpose 別指定を含む）
3. 対象プロジェクトの設定
4. Agent Dashboard の既定値

CLI とモデルは独立して解決する。例えばモデルだけをアプリ設定で指定した場合、CLI は実行方針で
選ばれたものを使い、モデルだけを上書きする。この解決器は Agent Dashboard 独自の IPC ハンドラー
だけから利用し、各エンジンの起動経路へ流用しない。

## コンポーネントとデータフロー

1. 表示中の領域と画面状態を領域別 target adapter へ渡す。
2. adapter が `{ cwd, choices, disabledReason }` を返す。
3. 共通 AI 操作バーが対象表示、候補、ボタン状態を描画する。
4. 押下時に現在の対象を再解決し、表示時の対象と一致することを確認する。
5. main process が Dashboard AI 設定と実行方針からエージェント／モデルを解決する。
6. lifecycle、利用上限、CLI 定義、cwd の実在を検証して外部対話セッションを開く。

領域切替、タブ切替、詳細選択、フォルダ入力変更のたびに対象を再解決する。前画面の対象を保持した
まま起動しない。外部セッションのキーは既存どおり CLI と正規化済み cwd を基準にし、同じ対象なら
再 attach できるようにする。

## エラー処理

- 対象未選択、パス変換失敗、実在しないフォルダはボタン近傍へ理由を表示する。
- `repos.json` の読み取り失敗はプロジェクト自体へ暗黙に切り替えず、候補取得エラーとして示す。
- 設定した Agent CLI の定義が見つからない場合、別 CLI へ黙ってフォールバックしない。
- lifecycle が停止中、または利用上限到達時は理由を示して起動しない。
- 起動中はボタンを無効化して二重起動を防ぐ。
- 外部ターミナル起動失敗には対象フォルダとエージェント名を含める。

## テスト

1. 4 領域の一覧・入力画面と詳細画面で共通 AI 操作バーが表示される。
2. 各画面の現在対象が起動 cwd になり、画面切替後に古い対象が残らない。
3. プロジェクトでは `repos.json` の候補だけが並び、ローカル clone がない候補は理由付きで無効になる。
4. ワークフロー run と mission の詳細記録から cwd を復元できる。
5. WSL パスを起動可能なパスへ変換し、失敗時は理由付きで無効になる。
6. 対象未確定でもボタン自体は表示され、無効理由が通知される。
7. アプリ設定の CLI／モデルが Agent Dashboard 独自呼び出しすべてへ適用される。
8. 各エンジンへ渡す agent、tier、model、役割別指定が変化しない。
9. アプリ設定が空なら `dashboard` 実行方針へ従う。
10. CLI とモデルを片方だけ上書きできる。
11. Doctor、下書き、補助、外部相談の既存機能が回帰しない。
12. 375px、768px、1024px、1440px で横スクロールせず、キーボード操作とフォーカス表示が成立する。

## 非目標

- 各エンジンの実行方針、工程別・役割別エージェント選択の変更
- Dashboard 内へのチャット UI の埋め込み
- 相談内容の保存、要約、成果物化
- `repos.json` や agent-control の契約変更

## 実装計画

1. 前回の未コミット実装を本設計との差分ごとに分類し、流用可能部分だけを残す。
2. Dashboard AI 専用の設定解決順を main process に実装し、独自 IPC 呼び出しを統一する。
3. 全体設定 ＞ アプリ設定へ Dashboard AI の CLI、モデル、待ち時間を追加する。
4. 画面状態から対象を返す領域別 target adapter と共通 AI 操作バーを実装する。
5. プロジェクト、ワークフロー、ミッション、定常業務の一覧・入力・詳細画面へ共通バーを配置する。
6. WSL／ホストパス正規化と理由付き無効状態を接続する。
7. 単体テスト、DOM 配置テスト、既存テスト、lint を実行する。
8. 実画面を 375px、768px、1024px、1440px で確認し、配置と文言を調整する。

## 既存スキルとの関係

- `ui-designer`: 共通操作バー、常時表示、44px 操作領域、レスポンシブ、無効理由の近接表示へ反映した。
- `systematic-debugging`: 前回差分から欠落画面と残留状態の原因を切り分ける際に利用できる。
- `webapp-testing`: 画面遷移、詳細画面、狭幅表示の実ブラウザ検証に利用できる。
