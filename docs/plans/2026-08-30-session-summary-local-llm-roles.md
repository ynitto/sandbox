## 1. 結論

**e4b で代替できない役割は 2 つに絞れた。** レビュー（RV 1/3。12b は 3/3 なので割り当てで
解ける）と、regex の生成（CG1。実行結果を見せて投げ直しても戻らない）。

**それ以外の「落ちる」はすべて、モデルではなく形の問題だった。** 直し方は 1 つの型に
収まる——**ゲートで 1 度言わせ、それでも残るぶんは機械が形を直す**。この日だけで 4 例:

| 何が落ちていたか | 機械が何をしたか | 実測 |
|---|---|---|
| split の後ろに静的な map/reduce を書く | 下流ごと外して運ぶ | PL3 0/3 → **3/3** |
| 1 行の修正を「読む→特定→直す→適用」に割る | 同じファイルを触る成果ノードを畳む | PL4 1/3 → **3/3** |
| 予算を超える組合せを選ぶ | 転記だけさせて総当たりは機械が回す | PR1 0/3 → PR1P **3/3** |
| `filter` に使われない `tie_break` を書く | その 1 語だけ落として decision は運ぶ | PL6 1/3 → **3/3** |

**指示文の書き換えで動いた例は 1 つも無い。** モデルは 4 例とも、作り直しを命じられても
同じ形を書き続けた。動いたのは運搬（機械が形を直す）を足したときだけである。

## 3. 測っていたものが本番に無かった 2 件

**役割の可否より先に、「その役割は本番にあるか」を見る。** この日 2 件見つかった。

**受入判定（PV1）。** 08-23 に「道具なしの verifier は成立しない」（e4b は捏造 pass 12/12、
12b は契約違反で全 fail）と測り、**その結果を根拠に 08-24 で自然文 verifier ごと撤去された**
（コミット `5de9a23ec`）。いま `acceptance` が自動判定するのは charter の決定的コマンドだけで、
自然文は milestone の検収チェックリストへ回る。ハーネスは本番関数の消滅で `AttributeError` に
なる残骸だったので、理由を告げて終了するようにした。**モデルを替えても戻らない**——
役割そのものが無い。

**ファイル分配（S2）。** 0/5 のままだが、本番の split は「独立に処理できる小片のリストへ
分解」で、engine は要素 1 つにつき map ノード 1 つを作る。まとめる方向の宣言はどこにも無い。
N 件を K 組へ配るのは算術で、モデルに訊く仕事ではない。割り当て表からは外した。

## 4. 検証役 — 見立てが外れた 1 件

**測る前の見立ては「危ない」だった。** 本番の `verify → ollama-verify` は `file_flag` も
`read_flag` も `tools` も宣言しておらず、割り付けたファイルが 1 つも届かない。PV1 と同じ
構造で、しかも flow 側の `_normalize_verify` には証跡の要求が無い。

**それでも 5/5・5/5・5/5 だった。** PV1 と同形に寄せた V3（完了条件がファイルを名指し・
中身はプロンプトに無い）でも、e4b は `ok=false` を選び「証跡が無い」と書いた。

**差は材料の在り処にある。** PV1 は「ワークスペースを見て判定せよ」と言われて手元に
何も無く、捏造で埋めた。flow の verify は依存の成果がプロンプト内にあり、中身が無い場合でも
「無い」と言える。**「道具なしの verifier は成立しない」を一般則にしてはいけない**
——新しい検証面を疑うときは、まず材料がプロンプトに入るかを見る。

## 5. 測定側で直した欠陥 3 件

数字より先に、数字の出どころが壊れていた。

1. **診断に正解を混ぜていた。** CG1 の再投入診断の初版が `GOLD_GREP` から「当てるべき行を
   落とす 5 行（例 `billing.py:4`）」を返していた。本番の機械は正解を持たないので、これは
   本番で再現しない助けである。走らせかけた測定を止め、実行結果だけ（コンパイル可否・
   当たった行）へ直した。**同じ罠が既存の `text_eval --repair` にもある**——PR1 の診断は
   `期待 p1+p4=効果 120/予算 10` と正解そのものを渡している（それでも 1/3 が外れていた）。
2. **verify を本番より厳しく採点していた。** JSON を抽出できないと `unparsable` で不合格に
   していたが、本番のゲートは本文の `verify=pass` / `verify=fail` も読む。本番なら正しく
   fail へ倒れる出力をモデルの失点として数えていた（V3 の 1 本目がこれ）。
3. **パス抽出が日本語を巻き込んでいた。** `_mentioned_paths` の `\w` が助詞を拾い
   `をREADME.md` を 1 語にしていた。**既存の宣言剥がしにも効く欠陥**で、要求が
   「README.mdを直す」と空白なしで書くと、正当に宣言された成果物が「要求に無い」と
   判定されて落ちる。パス文字を ASCII に限った。

| agent-project の `review` / `adjudicate` | 12b 側の確認 | レビュー族（RV は e4b 1/3・12b 3/3） |

「モデルが外しても機械が形を直せる」からで、生成そのものが要る仕事にはその手が使えない。
