# agent-app レスポンス表示・共通設定再設計

## 背景

agent-app の会話画面は、エージェントの最終回答と実行ログを別々には扱っているものの、利用者が知りたい「何を考えながら進めているか」「結論は何か」「何を実行したか」が一つのメッセージとして整理されていない。また、全体設定は tmux、worktree、WSL の最低限に留まり、agent-dashboard が持つ共通指示、スキル、セッション開始コマンド、実行方針に相当する設定がない。

agent-dashboard の設定をそのまま移植すると、予算、ワークロード、適格性、実行レベル切替など agent-app の会話用途には不要な概念まで持ち込むことになる。本設計では、一般的なエージェントアプリの「回答を主役にし、進捗と証跡を段階的に開示する」構成を採り、設定は agent-app が実際に適用できる項目だけへ絞る。

## 目的

- エージェントのレスポンスを「思考・進捗」「回答」「実行情報」として視覚的に分離する。
- 回答は通常の会話と同じ吹き出しとして常に読みやすく表示する。
- CLI ごとの差を共通のレスポンス形式へ正規化し、取得不能な情報は推測しない。
- 共通指示、推奨スキル、セッション開始アクションを UI コントロールで設定できるようにする。
- 起動方針が Tier を選び、Tier ごとのエージェント・モデル設定を決定的に解決する。
- 既存の `config.json` と会話履歴を後方互換のまま移行する。

## 非目的

- 非公開の chain-of-thought を取得・表示すること。
- 回答文を見出しや語句によって推測分割すること。
- エージェントやモデルを品質評価で自動ランキングすること。
- 予算、クォータ、利用量に応じて Tier を自動降格すること。
- agent-dashboard のワークロード別制御、サービス停止、候補適格性を移植すること。
- `config.json` の生 JSON エディターを提供すること。

## 参考にした UX

- Codex app は、長時間実行するエージェントのタスク、進捗、変更、差分を会話の文脈から確認できる構成を採る。
- GitHub Copilot coding agent は、セッション概要とログを分け、進捗、ツール利用、検証の証跡を確認できる。
- Codex CLI は、読み取り、ワークスペース実行、フルアクセスのように実行権限を利用者が理解できるモードへまとめている。

## 情報設計

### 主メニューとの関係

主メニューは既存決定どおり「会話／タスク／ワークフロー」の三つを維持する。設定は主メニューへ追加せず、サイドバー下部の歯車から開く補助画面とする。

### レスポンスカード

エージェントの一つのターンを、縦に並ぶ三層として表示する。

```text
Codex · 実行中

▼ 思考・進捗  3件
  ✓ 関連ファイルを確認
  ● テストを実行中

┌────────────────────────────┐
│ 最終回答を通常の会話として表示 │
└────────────────────────────┘

▸ 実行情報  5件 · 42秒 · 成功
```

- **思考・進捗**: 作業中は展開し、完了後は折りたたむ。ユーザー向けに公開された reasoning summary と意味のある進捗だけを表示する。
- **回答**: 常に展開する。ユーザーメッセージと対になる通常の吹き出しで、最も強い視覚階層を持つ。
- **実行情報**: ツール、コマンド、参照・変更ファイル、経過時間、終了状態、エラーを折りたたんで表示する。
- 空の区分は表示しない。
- エラー、停止、確認待ちでは実行情報を自動展開する。
- 生ログは実行情報内の「詳細ログ」で必要時だけ表示する。

作業中のカードは同じ DOM 上で更新し、完了時に別カードへ差し替えて大きくスクロール位置が動くことを避ける。

### レスポンシブとアクセシビリティ

- 狭幅では三層をそのまま一列表示し、吹き出しの最大幅制限だけを緩める。
- 開閉操作は 44px 以上のクリック領域を持たせる。
- 開閉ボタンは `aria-expanded` と `aria-controls` を持つ。
- 状態は色だけで伝えず、「実行中」「成功」「失敗」「停止」の文字を併記する。
- `prefers-reduced-motion` では展開アニメーションを無効化する。

## 設定画面

agent-dashboard の分類を agent-app 向けに三つへ圧縮する。生 JSON は見せず、利用者が変更できる設定はすべてフォームコントロールとして提供する。

### アプリ

- 対話セッションを維持する（既存 `transport`）。
- 会話ごとに作業を分離する（既存 `useWorktree`）。
- Windows のときだけ WSL ディストリビューションを表示する（既存 `wslDistro`）。
- 現在の実行環境と利用可能なエージェントを読み取り専用で表示する。

### 共通指示

- 共通指示の有効・無効。
- 指示本文。固定の上限を持たせ、上限自体は設定項目にしない。
- 検出済みスキルを検索して追加・削除する推奨スキル一覧。
- セッション開始アクションの追加・並び替え・削除。

開始アクションは次の最低限だけを持つ。

| 項目 | 値 |
|---|---|
| 種類 | スキルを呼ぶ／コマンドを実行 |
| 内容 | スキル名またはコマンド本文 |
| 失敗時 | 続行／セッション開始を中止 |

コマンドは会話の作業フォルダで上から順に実行する。個別タイムアウト、適用条件、環境変数、まとめて依頼は UI に出さず、各コマンド 60 秒、合計 120 秒に固定する。

### 実行制御

- 新規会話の既定起動方針。
- Tier ごとのエージェント・モデル。
- 新規会話の既定モード（Ask／実行）。
- 同時実行数（1〜8）。

Tier は三つに限定する。

| Tier | UI 表示 | 設定内容 |
|---|---|---|
| `small` | 軽量 | エージェント＋モデル |
| `medium` | 標準 | エージェント＋モデル |
| `large` | 高性能 | エージェント＋モデル |

起動方針は Tier を決定的に選ぶだけで、候補の順位付けはしない。

| 起動方針 | 選択 Tier |
|---|---|
| `recommended`（おすすめ） | `medium` |
| `saving`（節約） | `small` |
| `quality`（品質重視） | `large` |

会話の実行設定では、その依頼だけ起動方針を変更できる。必要な場合は直接指定へ切り替え、CLI とモデルを一時的に選べる。設定された CLI が利用不能な場合は送信前に警告し、別 Tier へ自動変更しない。

## 設定データ

既存の `config.json` を正典とし、内部状態とユーザー設定を同じファイルに後方互換で保持する。新規キーは概念ごとにまとめる。

```json
{
  "instructions": {
    "enabled": true,
    "text": "",
    "skills": [],
    "startupActions": []
  },
  "execution": {
    "defaultPolicy": "recommended",
    "defaultReadonly": false,
    "maxConcurrent": 2,
    "tiers": {
      "small": { "cli": "aider", "model": "gemma4:e4b" },
      "medium": { "cli": "codex", "model": "" },
      "large": { "cli": "claude", "model": "" }
    }
  },
  "transport": "tmux",
  "useWorktree": true,
  "wslDistro": ""
}
```

実際の初期値は利用可能なエージェントを勝手に推測せず、既存 `lastCli` / `lastModel` を三つの Tier へコピーして移行する。ユーザーが各 Tier を設定した後は、その値を維持する。`lastRepo`、`area`、`view` などアプリが自動管理する状態値は設定 UI に出さない。

保存時は次を行う。

1. renderer で入力不足を即時表示する。
2. main で同じ規則を再検証する。
3. 未知キーを保持したまま既知キーを正規化する。
4. 一時ファイルへ書き、置換して部分書込みを防ぐ。
5. 成功後だけ renderer の設定状態を更新する。

## 起動方針の解決

解決は副作用のない一関数へ集約する。

```text
ターンで直接指定されている → 指定された CLI / model
ターンで方針が指定されている → 方針に対応する Tier
指定がない → config.execution.defaultPolicy に対応する Tier
Tier → config.execution.tiers[tier] の CLI / model
```

解決結果には `policy`、`tier`、`cli`、`model`、`source` を含め、実行メッセージの情報欄へ保存する。設定値から後で再推測しない。

## 共通指示とセッション開始アクション

### 共通指示

共通指示は、画面に保存するユーザー本文とは分けて、CLI に渡す実行用プロンプトへ一度だけ前置する。今回の依頼とリポジトリ固有指示を優先する旨を固定ヘッダーで示し、マーカーによって二重注入を防ぐ。

推奨スキルは共通指示ブロックへ名前として列挙する。固定出力契約を持つワークフロー内部の判定・評価には注入しない。

### 開始アクション

- シェルコマンドは CLI 起動前に作業フォルダで実行する。
- スキル呼び出しは `agents/<name>.json` の `skill_command_prefix` を使い、最初の依頼へ起動アクションとして一度だけ添える。
- 同じ会話で別 CLI を初めて使う場合は、その CLI セッションに対して一度適用する。
- 既存 CLI セッションの再開では再実行しない。
- 設定変更は既に動いているセッションへ割り込ませず、次の新規 CLI セッションから反映する。
- 実行結果は「実行情報」に残す。

## レスポンスデータ契約

既存の `message.text` を回答の正典として残し、任意の `parts` を追加する。

```js
{
  role: 'assistant',
  text: '最終回答',
  cli: 'codex',
  model: '',
  policy: 'recommended',
  tier: 'medium',
  parts: {
    thinking: [
      { text: '関連ファイルを確認', status: 'done', at: '...' }
    ],
    information: [
      { type: 'command', title: 'npm test', status: 'success', detail: '...' },
      { type: 'file', title: 'src/app.js', action: 'modified' }
    ]
  },
  elapsedMs: 42000,
  code: 0
}
```

### 共通イベント

`information` の `type` は初期実装では `tool`、`command`、`file`、`reference`、`status`、`error` に限定する。CLI 固有の未知イベントは生データをそのまま UI へ渡さず、詳細ログへ落とす。

### 取得経路

- Codex の headless 実行は既存の JSONL stdout を解析し、reasoning、command、file change、tool event を共通イベントへ変換する。最終回答は従来どおり output file を正典にする。
- 構造化出力を安全に有効化できる CLI は、CLI ごとの adapter を追加して同じ契約へ変換する。
- tmux と非構造化 CLI は、アプリの開始、処理中、確認待ち、終了と、終了コード、時間、エラーを使う。端末画面の文章を推測分類しない。
- adapter が一行でも壊れた場合はその行を詳細ログへ残して処理を続ける。ターン全体の変換に失敗しても `text` を表示する。

## 同時実行制御

main プロセスを正典として実行中ターン数を管理する。renderer は事前に送信可否を表示するが、IPC 側でも上限を検証する。

- 上限到達時は新しい依頼をキューへ積まず、実行中件数と上限を表示する。
- 同じ会話の二重送信は従来どおり拒否する。
- 正常終了、失敗、停止、spawn 失敗のすべてで実行枠を解放する。
- ワークフローエンジンなど別プロセスの内部並列数は対象外とする。

## エラーハンドリング

- 選択方針の Tier が未設定なら、設定への導線付きで送信を止める。
- Tier の CLI が利用不能なら自動フォールバックせず、理由を表示する。
- 開始コマンド失敗時は設定どおり続行または開始中止し、実行情報にコマンドと結果を残す。
- スキルが見つからない場合は開始中止せず警告として残す。
- 設定保存の検証失敗は項目直下へ表示し、既存設定を変更しない。
- 古い会話、`parts` がないメッセージ、未知のイベント型は回答表示を妨げない。

## テスト方針

- 設定の正規化、旧設定移行、未知キー保持。
- 起動方針と Tier の決定表、直接指定の優先順位。
- 共通指示の no-op、上限、二重注入防止。
- CLI ごとのスキル記号変換と開始アクションの一度だけ適用。
- 同時実行枠の取得・解放・上限拒否。
- 構造化イベント fixture の変換、壊れた行のフォールバック。
- `parts` の有無による新旧会話レンダリング。
- 作業中から完了への一カード更新。
- 開閉状態、キーボード、状態文字、狭幅表示。
- Electron 起動、設定保存、会話表示のスモークテスト。

## 既存スキルとの関係

- **ui-designer**: 回答を主役にする視覚階層、progressive disclosure、狭幅・フォーカス・reduced motion の規則を設計へ反映した。
- **test-driven-development**: 設定契約、方針解決、event adapter、実行枠を純粋関数から Red-Green-Refactor で実装する。
- **self-checking**: 完了時に要件とテスト証跡を照合する用途で相乗効果がある。
- React 系スキルは、現行が素の Electron / HTML / CSS / JavaScript であるため適用しない。
