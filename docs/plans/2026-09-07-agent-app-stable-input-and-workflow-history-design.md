# agent-app 入力安定化・ワークフロー履歴表示設計

> 作成: 2026-09-07  
> 対象: `tools/agent-app`、`tools/statemachine-maker` の埋め込みワークベンチ  
> 更新対象: `2026-09-05-agent-app-task-workflow-navigation-design.md`、`2026-09-06-agent-app-agent-loop-task-catalog-design.md`

## 背景

会話画面では `メッセージ` と `端末操作` の切替時に入力ドックの内容量が変わり、画面下部の高さが揺れる。
また、会話履歴はライブ端末の補助情報であるにもかかわらず初期状態で開いている。タスク画面のリポジトリ選択は
役割が見えにくく、ワークフロー画面では既存の実行履歴機能が埋め込み用 CSS により非表示になっている。

調査の結果、タスクとワークフローの取得処理はすでに選択中リポジトリを `root` として渡している。
ワークフロー実行履歴も `flowRunList(root, 30)`、実行詳細、成果、ログ、再実行の機能が実装済みであり、
新たな横断検索やインポート機構は必要ない。

## 目的

- 入力モードを切り替えても入力ドックの基準高を変えない。
- 会話履歴を必要なときだけ開く補助領域にする。
- タスクとリポジトリの関係を維持し、選択中リポジトリ以外のタスクを混ぜない。
- 選択中リポジトリのワークフロー実行履歴を、定義一覧と混在させず確認できるようにする。
- 既存 IPC、保存形式、実行履歴ストアを変更しない。

## 採用設計

### 会話入力ドック

入力ドックを `モード切替 / 入力面 / 操作面` の共通グリッドとして扱う。メッセージモードでは入力面に textarea、
操作面に添付・実行設定・送信を置く。端末操作モードでは仮想キー面を入力面から操作面まで使って表示する。
モードごとの内容は差し替えるが、ドックには共通の基準高を持たせる。

- 初期表示および通常のモード切替では外形の高さを固定する。
- 添付行の増加や利用者による textarea のリサイズは内容拡張として許可する。
- 狭い高さでは中央の端末面を縮め、入力ドックを縮めない。
- 非表示側の操作はフォーカス順から外し、キーボード操作を維持する。

### 会話履歴

`conversation-history` の HTML 初期 `open` を廃止し、会話を開いた直後は閉じる。利用者が明示的に開いた後は、
メッセージ追加や状態更新だけを理由に閉じない。ヘッドレス会話で履歴が主表示になる場合は従来どおり履歴面として
表示する。

### タスクとリポジトリ

共通リポジトリ選択を残す。タスク一覧は従来どおり、選択中リポジトリに対するステートマシン定義、agent-loop
スナップショット、教示中タスクだけを統合する。リポジトリ選択を隠す変更は行わない。

理由は、リポジトリがタスク定義、実効 cwd、定期設定、実行履歴のスコープを決める実質的な操作だからである。
空状態と一覧更新のテストで、別リポジトリのタスクが混ざらないことを明示する。

### ワークフロー実行履歴

選択中リポジトリのワークフロー詳細に `実行履歴` を追加する。保存済みワークフロー一覧は左サイドバーに維持し、
実行履歴を同じ一覧へ混ぜない。履歴画面は既存の run list と run detail を再利用し、各実行から次を確認できる。

- 開始日時と状態
- 完了・失敗工程数と進捗
- 確認要求と回答
- 工程別成果と最終成果
- 起動ログ
- 同じ内容での再実行

初版は選択中リポジトリの履歴だけを表示する。他リポジトリの自動探索、関連性推定、インポートは非目標とする。
将来、複数リポジトリを一つのプロジェクトとして明示管理する契約が追加された場合に再評価する。

## 状態とデータフロー

```text
repo-select
  ├─ tasks: runSnapshot(repo) + listMachines(repo) + teachingList(repo)
  └─ workflows: flowList(repo) + flowRunList(repo, 30)
                                      ↓
                         実行履歴選択 → flowRunRead(repo, runId)
```

リポジトリ切替時はタスク、ワークフロー、履歴選択をそのリポジトリの状態へ切り替える。別リポジトリの run ID を
引き継がない。履歴取得失敗はワークフロー定義の表示を妨げず、履歴面に回復可能なエラーを表示する。

## テスト

- DOM: 会話履歴に初期 `open` がなく、利用者が開いた状態を通常の再描画で保持する。
- CSS/DOM: メッセージ／端末操作の双方で入力ドックの基準高が一致する。
- 入力: モード切替後も未送信文章を保持し、非表示操作へ Tab フォーカスしない。
- タスク: リポジトリ切替後、選択 root の項目だけを一覧化する。
- ワークフロー: 選択 root の run list を表示し、履歴選択から既存 run detail を開ける。
- 回帰: 実行、回答、成果取得、ログ、再実行、削除、リポジトリ切替を維持する。
- 実機: Electron で空会話、tmux 会話、ヘッドレス会話、タスク、ワークフロー履歴を確認する。

## 検討した案

| アプローチ | 実装コスト | リスク | 保守性 | 拡張性 | 学習コスト | 推奨度 |
|---|---|---|---|---|---|---|
| 中央のワークフロー詳細に実行履歴を表示 | 低 | 低 | 高 | 高 | 低 | ★★★ |
| 左サイドバーへ定義と分けた履歴セクションを追加 | 低 | 中 | 中 | 中 | 中 | ★★☆ |
| 関連リポジトリから履歴をインポート | 高 | 高 | 低 | 高 | 高 | ★☆☆ |

中央表示は既存 run detail を再利用でき、保存済み定義と実行単位を混同しない。左サイドバー案は操作数が少ないが、
一覧の責務が増える。インポート案は関連性、重複、移動後の履歴、パス変換の契約が必要になり、現時点では過剰である。

## 既存スキルとの関係

- `ui-designer`: 固定高グリッド、履歴タブ、狭幅時の優先順位を実装時に確認する。
- `webapp-testing`: Electron 上のモード切替、履歴選択、リポジトリ切替を検証する。
- `code-simplifier`: 埋め込み専用の分岐や CSS が重複しないか実装後に確認する。

既存スキルが agent-app 固有の状態・IPC 統合を代替することはない。
