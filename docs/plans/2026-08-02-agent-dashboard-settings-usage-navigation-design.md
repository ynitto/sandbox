# Agent Dashboard 全体設定・利用状況ナビゲーション設計

## 背景

全体設定の「エージェント」には、画面内 AI、共通指示、セッション開始コマンド、利用上限、担当設定、利用状況、実行制御、エージェント一覧が直列に並び、目的の項目へ辿り着きにくい。

また、利用状況は上限を基準にしたバーが中心で、上限を設定していない場合の実使用量が読み取りにくい。トークン実測がない台帳行は推定レートが未設定だと 0 トークンとして集計される一方、記録済みの実行時間が機能別表示に出ていないため、「未使用」と「推定不能」を区別できない。

## 採用方針

利用状況を全体設定の独立タブへ移し、肥大化したエージェント設定を目的別タブへ分割する。既存の集計、カード、表、プログレスバーを再利用し、新しいチャート依存は追加しない。

全体設定の分類は次の順にする。

1. アプリ
2. 利用状況
3. エージェント
4. 共通指示
5. 実行制御
6. 同期と実行
7. 定常業務
8. 外部連携

### 各タブの責務

- **利用状況**: 合計利用量と機能別内訳を確認する読み取り専用画面
- **エージェント**: 画面内 AI、機能別のエージェント・モデル、登録エージェント一覧
- **共通指示**: 全エージェントへ渡す共通指示、セッション開始コマンド
- **実行制御**: 利用上限と配分、実行サービスの許可・停止

保存処理とデータ契約は変えず、既存パネルを配置換えする。状態更新ボタンは、オーケストレーション情報を表示する4タブで利用できるようにする。

## 利用状況 UX

### 合計

- 期間、合計トークン、実測値、推定値、実行時間を常に表示する。
- 上限ありの場合は使用率、使用量、残量を数値とプログレスバーで表示する。
- 上限なしの場合は使用率を作らず、「上限なし」と現在の利用量を表示する。

### 機能別

- トークン、実行時間、記録件数、全体に占める割合を表示する。
- トークンが集計できる場合、構成比バーは全体トークンに対する割合を示す。
- 台帳行と実行時間があるのにトークンを集計できない場合は「推定不可」と表示する。0 トークンとは表示しない。
- 台帳行がない場合だけ「利用記録なし」と表示する。
- 機能別上限がある場合は状態欄に到達・節約状態を従来どおり表示する。

推定レートの設定 UI は追加しない。既存の「推定値を調整」を実行制御へ残し、利用状況は記録された事実と推定可否を正確に伝える。

## データフロー

既存の node-budget 台帳を読み、期間対象の各行についてワークロード別の実行秒数、実測・推定トークンに加えて記録件数を集計する。レンダラーは次を使い分ける。

- `recordCount === 0`: 利用記録なし
- `recordCount > 0 && totalTokens === 0 && seconds > 0`: トークン推定不可、実行時間を表示
- `totalTokens > 0`: トークン値と全体構成比を表示

壊れた JSONL 行は従来どおり無視する。上限値は表示方法の選択にだけ使い、利用量そのものの表示条件には使わない。

## アクセシビリティとレスポンシブ

- 既存の `tablist` / `tab` / `tabpanel` と矢印キーボード操作を維持する。
- 狭幅では既存の分類セレクトへ8分類をそのまま反映する。
- バーだけで状態を伝えず、数値、割合、状態語を併記する。
- 表は既存の横スクロール対応を再利用する。

## エラー処理

- オーケストレーション情報の読み込み失敗は、対象4タブ内で既存のエラー表示を使う。
- 集計不能を利用量0として扱わない。
- 台帳の一部が壊れていても、有効な行の集計と画面表示は継続する。

## テスト

- 全体設定が8分類になり、各パネルが意図したタブへ1回だけ配置されること。
- 状態更新ボタンが対象4タブで表示されること。
- 上限なしでも合計利用量と時間が表示され、上限基準のバーを出さないこと。
- 機能別の記録件数と実行時間が集計されること。
- 推定不能、利用記録なし、実測・推定ありを区別すること。
- 上限ありの場合の到達・節約判定が維持されること。
