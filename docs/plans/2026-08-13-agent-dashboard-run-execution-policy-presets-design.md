# Agent Dashboard 実行時方針プリセット設計

## 目的

ワークフロー実行画面の「今回だけ実行レベル・エージェントを指定」を、全体設定と同じ方針カードから選ぶ操作へ簡略化する。指定はその実行だけに適用し、全体設定を変更しない。

## UI

折りたたみを廃止し、次の5つの方針カードを常時表示する。既定は「おすすめ」。カードの選択表現、フォーカス表示、説明文は全体設定の `.orch-policy-card` を再利用する。

| モード | 動作 |
|---|---|
| おすすめ | overrideを作らず、agent-control / agent-flowの自動決定へ委ねる |
| 節約 | `small`を基準にし、許可されない役割・機能だけ最低限必要なtierへ上げる |
| 品質優先 | 対象となる全役割・全機能を`large`へ固定する |
| コスト優先 | 各役割・各機能に許可された最低tierを選び、可能な機能は`basic`へ固定する |
| カスタム | 現行の役割・機能別tier／エージェント／モデル入力を表示する |

カスタム以外では詳細入力を表示しない。色だけに依存せず「選択中」を表示し、ラジオ入力によるキーボード操作を維持する。

## データフロー

画面で選んだプリセットを、既存の`execution_overrides` v1（`roles` / `kinds`）へ投入前に展開する。新しいエンジン契約は作らない。

- 節約: `max(index(small), index(allowed minimum))`
- 品質優先: `large`
- コスト優先: `allowed tiers`の先頭
- おすすめ: `null`
- カスタム: 入力された行だけを従来どおり送る

展開後は既存のDashboard境界でtier候補をエージェント／モデルへ解決し、適格性・利用可能性を検証する。runスナップショットと再実行は従来の`execution_overrides`コピーを使う。

選択モード名は`execution_overrides.mode`へ加算的に保存し、実行詳細で方針名を表示できるようにする。agent-flowは未知キーを無視し、実際の選択には展開済み`roles` / `kinds`だけを使う。

## 既存設計との関係

全体設定では、仕事内容が不明なworkload全体へ`basic`を適用しない既存方針を維持する。今回の`コスト優先`は、役割・機能ごとの適格tierが判明しているワークフロー実行画面だけの例外である。

## エラーハンドリング

- プリセット展開後のtierに候補がない場合は、既存の投入前エラーをそのまま表示する。
- 不適格tierは生成せず、カタログの許可範囲へ切り上げる。
- カスタムの不正なエージェント／モデル／tierは既存境界で拒否する。
- おすすめではoverrideを送らず、既存の自動決定と完全に同じ動作を保つ。

## テスト

- 5モードが表示され、おすすめが既定である。
- 折りたたみUIがなく、カスタム選択時だけ詳細入力が見える。
- 節約・品質優先・コスト優先が適格tierへ正しく展開される。
- コスト優先で`classify`等は`basic`、`planner`等は許可された最低tierになる。
- おすすめはoverrideを生成しない。
- modeを含むスナップショットが再実行へ継承される。
