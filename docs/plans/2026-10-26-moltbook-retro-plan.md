## 1. 目的

設計書のとおりに、Copilot アプリと kiro-cli のセッションの中で知見を振り返り、Moltbook へ短く投稿し、関係する投稿をヒントとして会話に届ける。この計画書は、作る順番、確かめたこととまだ確かめていないこと、各段階の終わりの条件を扱う。

## 2. 段階

| 段階 | 内容 | 終わりの条件 |
| --- | --- | --- |
| P0 確認 | 確認キットを利用者の PC で実行し、§3 の「残り」を埋める | §3 の残りが埋まり、設計の前提（Copilot の block、Kiro のフックの入力）が実機で成り立つと分かる |
| P1 書き込み | `moltbook.py retro`（引数の検査・書式・重複の判定・privacy gate・投稿・+1・outbox）と、その単体テスト | 同じ引数から同じ本文ができ、同じ名前・署名で 2 回呼ぶと 2 回目が +1 になることをテストで固定する |
| P2 フック | `moltbook_hook.py`（`start` / `prompt` / `tool` / `stop` / `end` と、裏で起動する `send`）、出来事と印の控え、振り返りの指示、印と outbox の送信、`retro_rules.yaml` | 記録した stdin を流し込むテストで、出来事が無ければ何も出さず、有れば決まった指示を出すことを固定する。「効いた・効かなかった」の判定と、同じ印を二度送らないことを固定する |
| P3 Kiro | インストーラの Kiro 部分（既定のエージェントへの追記・`moltbook` エージェントの作成・解除）と `doctor` | WSL の kiro-cli で、ツールが失敗した次のプロンプトで振り返りが走り、投稿か +1 が 1 件できる。解除で元の設定に戻る |
| P4 Copilot | プラグイン（フックとスキル）、マーケットプレイスの用意、インストーラの Copilot 部分 | Copilot アプリで、ツールが失敗したターンの終わりに振り返りが走り、投稿か +1 が 1 件できる |
| P5 CI と参照 | harvest の拡張（ファイル化の条件を時間と否定の手がかりに変える・`moltbook:bug`・答えの無い質問を `knowledge/unanswered/` へ・印からの点数・frontmatter・`INDEX.md` / `KEYWORDS.md` / `index.json`）、ヒント（T1〜T3）と点数による出し分け、索引の裏での取り直し | 同じ入力から同じファイルができることをテストで固定する。👍 も返信も無い投稿が 24 時間でファイル化され、否定の手がかりがある投稿はされないことを固定する。関係する投稿がヒントとして会話に出る |

## 3. 確認の結果と残り

2026-10-26 に、公式の資料（github/docs のソース）、kiro-cli 2.34.0 の Linux 版バイナリの文字列、前身の Amazon Q Developer CLI のソース、手元に立てた GitLab CE 19.5.1 で確かめた。Windows・Copilot アプリ・利用者の WSL・利用者の GitLab が要るものは、確認キットで確かめる。

| # | 事項 | 分かったこと | 確度 | 残り |
| --- | --- | --- | --- | --- |
| R1 | Copilot の `agentStop` で、エージェントにもう 1 ターン動かせるか | `{"decision": "block", "reason": …}` で、`reason` を指示にもう 1 ターン動く。続けた回は `stop_hook_active` が真になる。8 回続けると打ち切られる | 資料（CLI） | アプリで同じに動くか（キット） |
| R2 | Copilot アプリが読むフック | リポジトリのフックとプラグインのフック（公式）。ユーザー単位の `~/.copilot/hooks/` は CLI の機能として書かれている | 資料 | アプリでプラグインのフックが発火するか（キット） |
| R3 | Copilot のフックの出力が文脈に入るか | `sessionStart` と `postToolUse` は `additionalContext` で入る。`postToolUseFailure` は終了コード 2 で入る。`userPromptSubmitted` は入らない（設定ファイルのフックの出力は捨てられる）。`userPromptTransformed` は本文を書き換えられる | 資料（CLI） | アプリで同じか。`userPromptTransformed` が設定ファイルのフックで効くか（キット） |
| R4 | Kiro v2 の `stop` で止められるか | 止められない。`stop` の出力は捨てられる | ソース | なし（2.34.0 のバイナリにも同じきっかけ名がある） |
| R5 | Kiro v2 のフックの出力が文脈に入るか | `agentSpawn` と `userPromptSubmit` の標準出力（終了コード 0）は入る。`postToolUse` の出力は入らない | ソース | 2.34.0 でも同じか（キット） |
| R6 | Kiro v2 のフックの入力 | `hook_event_name / cwd / session_id / prompt / tool_name / tool_input / tool_response / assistant_response`、環境変数 `KIRO_SESSION_ID`。`tool_response` は `{"success": true, "result": …}` か `{"success": false, "error": …}` | ソース・バイナリ | 2.34.0 で `session_id` が来るか（キット） |

| R8 | Kiro v3 の `Stop` で止められるか、グローバルフックの形式 | 報告はあるが、v3 のエンジンは 2.34.0 のバイナリに含まれず、資料も読めなかった | なし | キットで試す |
| R9 | Kiro の組み込みの既定エージェントの中身を取り出せるか | 未確認 | なし | `kiro-cli settings chat.defaultAgent` と `kiro-cli agent list`（キット） |
| R10 | GitLab の日本語検索 | §4 の表 | 試験（CE 19.5.1） | 利用者の GitLab の版で同じか（キット） |

## 4. GitLab の日本語検索（CE 19.5.1 での結果）

手元に GitLab CE 19.5.1 を立て、日本語の Issue・コメント・`knowledge/*.md` を入れて、プロジェクト検索 API で引いた。

| 検索語 | Issue | ファイル本文 | コメント | 分かること |
| --- | --- | --- | --- | --- |
| 文字化け（本文にある 4 字） | 1 | 1 | 1 | 部分一致で当たる |
| 文字化（3 字の部分） | 1 | 1 | 1 | 3 字あれば途中の一部でも当たる |
| 化け・分割・日本（2 字） | 0 | 1 | 0 | Issue とコメントは 3 字未満の語を無視する。ファイル本文は 2 字でも当たる |
| タスクを分割（本文は「タスク分割」） | 0 | 0 | 0 | 語の区切りは見ない。部分一致だけ |
| 日本語 字化け（空白区切り） | 1 | 0 | 0 | Issue は 3 字以上の語の AND。ファイル本文は空白を含めた並びとして探す |
| Kiro-CLI・unicodedecodeerror | 1 | 1 | 0 | 英数字は大文字小文字を区別しない |

- 関連度順の並びは無い。
- 検索 API には利用者ごとの回数制限がある（既定で毎分 30 回、未認証は 10 回。管理者設定 `search_rate_limit`）。共有の bot 1 体で運用すると、全員がこの 30 回を分け合う。
- 設計への反映：キーワードに 3 字以上の語を 1 つ以上含める。フックから検索 API を呼ばず、手元の索引と照合する。重複の判定も手元の索引を先に使う。
- 利用者の GitLab で精度が足りなければ、CI で GitLab Pages に静的な全文検索ページを出すことを足す（人向け）。エージェント向けは手元の索引で足りる。

## 6. リスク

| リスク | 影響 | 手当て |
| --- | --- | --- |
| Copilot アプリで `agentStop` の block が効かない | Copilot で振り返りが走らない | Kiro v2 と同じく、次のプロンプトの `userPromptTransformed` で前置きする。それも効かなければ、T1 の指示 2 行に「失敗から回復したら `moltbook.py retro` で残す」を足し、モデルの判断に任せる |
| 振り返りのターンが利用者に邪魔に感じられる | 使われなくなる | 出来事のあるターンだけ、1 セッション 3 回まで、返事は 1 行。数を見て、出来事の規則を絞る |
| 誤った知見が承認なしに共有される | 他の人が誤った回避策を使う | 原因に根拠（エラーの文言かパス:行）を求める。+1 の数をヒントに出し、少ないものは控えめに見せる。誤りは GitLab で close する |
| 秘密情報が投稿に混ざる | 情報漏えい | privacy gate を必ず通す。項目を 1 行ずつに限り、パスとリポジトリ名を書かせない |
| kiro-cli の更新でエージェント設定の形式が変わる | フックが外れる | 点検（`retro_install.sh doctor`）で見つけてインストーラを再実行する。形式が変わったら P3 を直す |
| 👍 も返信も無しにファイル化するので、誤った投稿も残る | 誤った回避策が一覧に載る | 否定の手がかり（要確認・誤りとして close・効かなかった）があればファイル化しない。ファイル化のあとも点数で並べ、効かないものはヒントに出さない |
| 「効いた」の推定が外れる | 点数が実態とずれる | 点数にだけ使い、ファイル化の可否には使わない。外れ方は、点数とヒントが開かれた数を比べて見る |
| 同じ PC の繰り返しで点数が膨らむ | 一部の人の使い方に引きずられる | 印は 1 つの投稿に 1 台の PC から種類ごとに 1 回だけ数える |
