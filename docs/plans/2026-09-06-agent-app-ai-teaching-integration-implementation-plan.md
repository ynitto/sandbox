# agent-app AI教示タスク統合 実装計画

> 作成日: 2026-09-06  
> 設計: [agent-app AI教示タスク統合設計](2026-09-06-agent-app-ai-teaching-integration-design.md)

## 方針

statemachine-maker の教示機能を共通実装として使い、agent-app はリポジトリ、会話からのintent、選択状態だけを接続する。親画面とiframeの境界を最初に一本通し、その後に新規作成、既存タスク変更、完了後の一覧反映、用語統一を段階追加する。

## Stage 1: intent契約

- 選択した利用者メッセージから、本文、添付参照、AI設定を持つ一回限りのintentを作る純粋関数を追加する。
- リポジトリ未選択、不正メッセージ、秘密になりうる添付値を拒否する。
- 同一intentを一度だけ消費する振る舞いをテストする。

成功条件: 公開関数の分岐カバレッジ100%。  
失敗条件: 会話全体やassistantの思考内容を引き継ぐ必要が生じた場合は設計へ戻る。

## Stage 2: 共通実装とIPC

- vendor生成へstatemachine-makerの教示rendererを追加する。
- `api.automation.*` へ教示IPCを公開する。
- 登録済みリポジトリ検査と既存channel prefixを維持する。
- iframeの準備完了、intent受信、重複防止イベントを追加する。

成功条件: preload、main、vendor rendererの契約テストが通る。  
失敗条件: 共通rendererの変換がagent-app固有APIを漏らす場合は、小さいadapter moduleへ分離する。

## Stage 3: シームレスなUI導線

- 利用者メッセージに「この依頼をタスクにする」を追加する。
- 「新しいタスク」は空の教示セッションを開始する。
- 既存タスクはAI教示を標準の変更入口にし、高度な編集を副操作へ置く。
- iframe準備前のintentは親で保持し、ready後に再送する。

成功条件: 親画面から教示画面へ一操作で遷移し、目的とAI設定が引き継がれる。  
失敗条件: 元の会話が失われる、またはタスクが重複作成される場合は次へ進まない。

## Stage 4: 完了後の接続

- 教示セッションが利用可能になった通知で、親のタスク一覧を再取得する。
- 完成したmachine IDを選択し、既存タスク詳細を表示する。
- 試運転失敗時は教示画面に留まり、正式定義を選択しない。

成功条件: 教示完了から実行・定期実行・履歴まで画面遷移が切れない。  
失敗条件: 正式保存前の候補が通常タスクとして見える場合は保存境界を修正する。

## Stage 5: 用語統一

- statemachine-makerとagent-appの通常画面にある「仕事」を「タスク」へ変更する。
- 内部識別子と保存形式は変更しない。
- READMEと静的UIテストを更新する。

成功条件: 通常画面の表示文言に「仕事」が残らず、既存データを読み戻せる。  
失敗条件: ユーザー入力や保存済み目的文まで機械置換しない。

## Stage 6: 結合検証

```bash
cd tools/statemachine-maker && npm test && npm run lint
cd tools/agent-app && npm run vendor && npm test
```

- Electron実機で会話からタスク化、新しいタスク、既存タスク変更、完成後の詳細表示を確認する。
- 720px、980px、1360pxで横スクロールと二重ナビゲーションがないことを確認する。
- intentと接続adapterのC1カバレッジ100%を確認する。

## 最大リスクと停止条件

最大リスクは、親画面、iframe、IPCの非同期な準備順によりintentが欠落または重複すること。最初のトレーサーバレットは「会話メッセージ→一回限りのintent→同じ目的の教示下書き」の一本とする。

既存の未コミット変更と競合する箇所を大きく書き換える必要が出た場合、正式タスク保存前に一覧へ候補が漏れる場合、または登録外リポジトリへ書き込める場合は実装を停止する。
