# judge の読み出し経路 — 初回実測と、測れていないもの

設計: `docs/plans/2026-09-19-agent-herd-system-one-judge-design.md`（§4 の縮退表・§6 の
「測ってから決めること」）。道具: `tools/agent-tools/eval/readout_eval.py`。

## 1. 実測（gemma4:e4b・12 セル × 3 回 = 36 回・2026-09-20）

既存セルの入力と正解を借りて judge 経路で引き直した。合否は借りたセルの `check` がつける。
初回は 9 セルで回し、不正解が E3 の 1 セルに固まったので、**同じ形（全ノード green だが
要求の段が欠けている）のセルを E4 / E5 と、対照の E6 を足して引き直した**のがこの表である。

| セル | 役割 | 合否 | 確度 | coverage |
|---|---|---|---|---|
| F1 | filter（候補 6 件 = boolean 6 問） | 3/3 | 0.627 | 0.997 |
| J2 | judge（候補の上の choice） | 3/3 | 0.989 | 0.970 |
| CL1 | classify（3 ラベルの choice） | 3/3 | 1.000 | 1.000 |
| E1 | evaluator（failed ノードあり → replan） | 3/3 | 0.997 | 1.000 |
| E2 | evaluator（3 段そろい verify pass → done） | 3/3 | 0.996 | 1.000 |
| E3 | evaluator（**出力段が無い** → replan） | **0/3** | 0.951 | 1.000 |
| E4 | evaluator（**集計段が無い** → replan） | **0/3** | 0.949 | 1.000 |
| E5 | evaluator（**収集段が無い** → replan） | **0/3** | 0.991 | 1.000 |
| E6 | evaluator（3 段そろう・verify の文面は E3〜E5 と同じ → done） | 3/3 | 0.991 | 1.000 |
| RO1 | route（本番の問いをそのまま） | 3/3 | 1.000 | 1.000 |
| RO2 | route | 3/3 | 1.000 | 1.000 |
| RO3 | route（「判断できない」＝ other） | 3/3 | 0.819 | 1.000 |

確度と coverage は問いをまたいだ最小。3 回とも同じ値に落ちた（温度 0）。

**§6 の 1（coverage の分布）**: 0.8 を割った回は 0/36、中央値 1.0。ラベルの置き方と
「Answer (one letter):」の末尾は直さなくてよい。

**§6 の 2（信頼度図）**:

| 区間 | 正答 |
|---|---|
| 0.6-0.8 | 3/3 = 1.00 |
| 0.8-1.0 | 24/33 = 0.73 |

**確度では止まらない。** 不正解 9 回はすべて E3〜E5（確度 0.949〜0.991）で、正解した回と
同じ帯にいる。しきい値を上げても落ちるのは F1（0.627）と RO3（0.819）という**正解していた
回**のほうで、誤りは 1 つも落ちない。この corpus では**確度の高い帯のほうが正答率が低い**
（0.6-0.8 が 1.00、0.8-1.0 が 0.73）。`--min-confidence` はこの誤りに対しては効かない。

**誤りの正体（E4 / E5 / E6 を足して分かったこと）**: 欠けている段が出力・集計・収集の
どれであっても結果は同じ（0/3 × 3 セル）。一方、verify の文面を E3〜E5 と揃えたまま 3 段を
そろえた E6 は 3/3 で `done` に留まる。つまりモデルは**verify の言い回しに反応しているのでは
なく、ノードの status しか読んでいない**——全部 green なら要求の段が欠けていても `done`。
E1（failed ノードあり）が 3/3 なのも同じ理由で、status から従う判断だけが当たっている。

直す先は確度のしきい値ではなく**問いの立て方**である。要求の 3 段を選択肢の説明か状態の
側に明示し、「どの段が結果に現れているか」を先に訊く形にしない限り、この面は judge へ
寄せられない。しきい値の既定は、この面を問いの側で直してから改めて測る。

## 2. 問いの立て方を変えて測り直した（evaluator・2026-09-20）

§1 の結論（直す先はしきい値ではなく問いの立て方）を実際に試した。要求の段（収集・集計・
出力）を**問いの側**へ出す形を 2 つ用意し、同じ E1〜E6 を 3 通りで引いた（各 3 回）。

| 問いの立て方 | 訊き方 | 判定 |
|---|---|---|
| 既定 | 「この結果で要求を満たしたか」の choice 1 問（done / replan） | モデル |
| `+stages` | 段を選択肢に並べた choice 1 問（done / missing:収集 / missing:集計 / missing:出力） | 機械（done 以外は replan） |
| `+checklist` | 段ごとに boolean 1 問（計 3 問。「その段の成果が出ているか」） | 機械（1 つでも no なら replan） |

段の名前は要求の本文から取り出す（`_request_stages`）。ケースの入力と正解は §1 と同じ。

| セル | 既定 | `+stages` | `+checklist` |
|---|---|---|---|
| E1（failed ノードあり） | 3/3・0.997 | 3/3・0.984 | 3/3・0.795 |
| E2（3 段そろう） | 3/3・0.996 | 3/3・0.994 | 3/3・0.997 |
| E3（**出力段が無い**） | 0/3・0.951 | 0/3・**0.675** | **3/3**・0.644 |
| E4（**集計段が無い**） | 0/3・0.949 | 0/3・**0.497** | 0/3・0.940 |
| E5（**収集段が無い**） | 0/3・0.991 | 0/3・0.982 | 0/3・0.923 |
| E6（3 段そろう・弱い verify） | 3/3・0.991 | 3/3・0.942 | 3/3・0.998 |
| **合計** | 9/18 | 9/18 | **12/18** |

**選択肢に並べるだけでは答えは変わらない。変わるのは確度。** `+stages` の正答は既定と
同じ 9/18 だが、E3 が 0.951 → 0.675、E4 が 0.949 → 0.497 へ落ちた。確信のある誤りが迷いに
変わり、**棄権できる誤りになった**——evaluator の正答の最小が 0.942 なので、この面だけなら
0.8〜0.9 のしきい値で誤り 6/9 を「決めない」へ回せて、正解は 1 つも落ちない。E5 は 0.982 の
ままで残る。

**1 段ずつ訊くと E3 が直る。** `+checklist` は E3 を 3/3 にした（合計 12/18）。ただし確度は
0.644 で、しきい値を 0.7 に置くと**正解のほうが棄権に回る**。この形では誤り（0.940 / 0.923）
のほうが確度が高く、確度では切れない。

**残った誤りの正体は status の読み落としではない。** `+checklist` の段ごとの答えを見ると:

| セル | 収集 | 集計 | 出力 |
|---|---|---|---|
| E3 | yes 0.997 | yes 0.998 | **no（yes 0.357）** |
| E4 | yes 0.991 | **yes 0.940**（ノードは無い） | yes 0.996 |
| E5 | **yes 0.923**（ノードは無い） | yes 1.000 | yes 0.999 |

E4 は writer の「日次レポートを書き出す」から集計を、E5 は「日次のトークン合計を出す集計」
から読み込みを**推測している**。E3 だけが直るのは、writer が他の段の記述から推測できない
ためである。つまり残る誤りは「全部 green なら done」ではなく、**隣の段の記述から欠けている
段を埋める**という別の形である。

**素材の側の但し書き**: E4 / E5 の正解（集計・収集が無い → replan）は E3 ほど自明ではない。
「日次レポートを書き出した」なら集計は済んでいると読むのは無理のない解釈で、モデルの推測は
擁護できる。素材が正解と食い違っていたので、次の節で直して測り直した。

## 3. 素材から他の段の含意を外して測り直した（2026-09-20）

§2 の但し書きのとおり、E4 / E5 は**欠けているはずの段の仕事が済んでいると読める記述**を
他のノードに置いていた。各ノードの説明は自分の段のことだけを言う、という規則で書き直した
（正解は変えていない——欠けている段は同じ）。

| セル | 直す前 | 直した後 |
|---|---|---|
| E4（集計段が無い） | 「**日次レポートを** Markdown で書き出す writer」 | 「Markdown のファイルへ書き出す writer」 |
| E5（収集段が無い） | 「**日次のトークン合計を**出す集計」 | 「日付ごとの合計を出す集計」 |

| セル | 既定 | `+stages` | `+checklist` |
|---|---|---|---|
| E3（出力段が無い・素材は元のまま） | 0/3・0.951 | 0/3・0.675 | 3/3・0.644 |
| E4 直す前 | 0/3・0.949 | 0/3・0.497 | 0/3・0.940 |
| **E4 直した後** | 0/3・0.921 | **3/3**・0.345 | 0/3・0.880 |
| E5 直す前 | 0/3・0.991 | 0/3・0.982 | 0/3・0.923 |
| **E5 直した後** | 0/3・0.979 | 0/3・**0.775** | 0/3・0.828 |
| **合計（E1〜E6）** | 9/18 | 12/18 | 12/18 |

**含意は確度に効いたが、答えは変えなかった。** 直した後も既定と `+checklist` の答えは
0/3 のままで、動いたのは確度だけである（E4 の「集計あり」0.940 → 0.880、E5 の「収集あり」
0.923 → 0.828）。含意が確度の一部を作っていたのは確かだが、それを外しても**モデルは根拠の
無い段を「ある」と言い続ける**。要求が 3 段だと書いてあるので、結果の側に無くても 3 段
そろっているものとして読んでいる、と見るのが素直な解釈になる。

**E4 の `+stages` 3/3 は当たりではない。** 確率は done 0.307 / missing:収集 0.345 /
missing:集計 0.336 の**三つ巴**で、モデルが選んだのは `missing:収集` ——E4 に実在する段の
ほうである。`missing:` はどれでも機械が `replan` へ畳むので、**欠けている段を取り違えても
合否だけは当たる**。確度 0.345 はどのしきい値でも棄権に回るので、本番なら「決めない」へ
倒れる。この形の合否を段の正しさの証拠として読まないこと。

**残る E5 は素材の問題ではない。** 含意を外しても `収集` に yes 0.828。集計ノードがあれば
その入力はどこかから来ているはず、という埋め方をしている。

## 4. 状態の側に閉世界を明示して測り直した（2026-09-20）

§3 の残り（E5 は素材の問題ではない）を追った。既定の状態はノードを並べるだけで、
**並んでいないものが無いとは言っていない**。状態の先頭に 1 行足して黙約を書き下す:

> このワークフローのノードは次の 3 件がすべてで、ここに現れていない仕事は行われていない。

問いの立て方 3 つ × 閉世界の明示の有無 = 6 通りを、同じ E1〜E6 で引いた（各 3 回）。

| セル | 既定 | `+stages` | `+checklist` | `+closed` | `+stages_closed` | `+checklist_closed` |
|---|---|---|---|---|---|---|
| E1 | 3/3・0.997 | 3/3・0.984 | 3/3・0.795 | 3/3・0.996 | 3/3・0.924 | 3/3・0.792 |
| E2 | 3/3・0.996 | 3/3・0.994 | 3/3・0.997 | 3/3・0.995 | 3/3・0.994 | 3/3・0.993 |
| E3 | 0/3・0.951 | 0/3・0.675 | 3/3・0.644 | 0/3・0.963 | 0/3・0.486 | **3/3・0.807** |
| E4 | 0/3・0.921 | 3/3・0.345 | 0/3・0.880 | 0/3・0.919 | 0/3・0.564 | **0/3・0.560** |
| E5 | 0/3・0.979 | 0/3・0.775 | 0/3・0.828 | 0/3・0.974 | 0/3・0.609 | **0/3・0.571** |
| E6 | 3/3・0.991 | 3/3・0.942 | 3/3・0.998 | 3/3・0.991 | 3/3・0.951 | 3/3・0.995 |
| **合計** | 9/18 | 12/18 | 12/18 | 9/18 | 9/18 | **12/18** |

**閉世界だけでは答えは 1 つも変わらない。** 既定の問いに足しても 9/18 のままで、確度すら
ほとんど動かない（E3 は 0.951 → 0.963 と、むしろ上がる）。`+stages` に足すと E4 の当たりが
消えるが、あれは元から三つ巴の偶然なので当たり外れの話ではない。

**効くのは「段ごとに訊く」と組んだときで、効き方は正答率ではなく確度の分離である。**
`+checklist_closed` の段ごとの確率を、3 段階の介入で並べると:

| 訊いている段 | 素材に含意あり | 含意を外す（§3） | ＋閉世界（本節） |
|---|---|---|---|
| E4「集計あり」（**誤り**） | yes 0.940 | yes 0.880 | yes **0.560** |
| E5「収集あり」（**誤り**） | yes 0.923 | yes 0.828 | yes **0.571** |
| E3「出力あり」（正しく no） | no（yes 0.357） | no（yes 0.357） | no（yes **0.193**） |

誤りは 0.5 のすぐ上まで落ち、正しい判断は逆に鋭くなった。セル単位で見ると:

- 正答（E1 0.792 / E2 0.993 / E3 0.807 / E6 0.995）と誤答（E4 0.560 / E5 0.571）が
  **完全に分離している**。
- したがって `--min-confidence` を 0.6〜0.79 の間（たとえば **0.7**）に置くと、
  **答えた 12 回はすべて正答、誤りの 6 回はすべて棄権**になる。棄権は生成経路へ倒れるので、
  judge が間違った done を返す回が 0 になる。
- 閉世界を外した `+checklist` で同じ 0.7 を置くと壊れる: 誤りの E4（0.880）と E5（0.828）は
  素通りし、正答の E3（0.644）が落ちる。**閉世界の 1 行が、しきい値を使える状態にしている。**

**この面はまだ配線されていない。** evaluator（done / replan）は judge の 7 か所の配線に
入っておらず、生成経路のままである。寄せるなら形は「状態に閉世界を明示し、段ごとの
boolean で訊き、判定は機械が畳む」——確度のしきい値はその形とセットでしか意味を持たない。

**標本の但し書き**: 6 セル × 3 回、温度 0 で 3 回とも同値、モデルは gemma4:e4b の 1 つ。
反復は独立な標本ではない。分離が見えたのは 4 正答対 2 誤答の並びであって、既定値を決める
根拠にはまだ足りない。

## 5. 採用形で corpus 全体を測り直した（2026-09-20）

evaluator を `+checklist_closed`（状態に閉世界・段ごとの boolean・判定は機械）に替え、
他のセルは §1 と同じ形のまま、12 セル × 3 回で引き直した。

| セル | 合否 | 確度 |
|---|---|---|
| CL1 / RO2 | 3/3 | 1.000 |
| RO1 | 3/3 | 1.000 |
| E6 | 3/3 | 0.995 |
| E2 | 3/3 | 0.993 |
| J2 | 3/3 | 0.989 |
| RO3 | 3/3 | 0.819 |
| E3 | 3/3 | 0.807 |
| E1 | 3/3 | 0.792 |
| **F1** | 3/3 | **0.627** ← 正答の最小 |
| **E5** | 0/3 | **0.571** ← 誤答の最大 |
| E4 | 0/3 | 0.560 |
| **合計** | **30/36** | |

**信頼度図が初めて単調になった。**

| 区間 | §1（既定の evaluator） | 本節（採用形） |
|---|---|---|
| 0.4-0.6 | — | **0/6 = 0.00** |
| 0.6-0.8 | 3/3 = 1.00 | **6/6 = 1.00** |
| 0.8-1.0 | 24/33 = 0.73 | **24/24 = 1.00** |

§1 では確度の高い帯のほうが正答率が低かった（0.73 対 1.00）。evaluator の問いの形を替えた
だけで、確度と正答の向きが揃った。**確度が役に立たなかったのはモデルの性質ではなく、
問いの立て方の側の問題だった。**

**しきい値の掃引（36 回）**:

| `--min-confidence` | 答えた | 正答 | 誤答 | 棄権 |
|---|---|---|---|---|
| 0.00 / 0.50 | 36 | 30 | **6** | 0 |
| **0.60** | **30** | **30** | **0** | 6 |
| 0.65 / 0.70 / 0.75 | 27 | 27 | 0 | 9 |
| 0.80 | 24 | 24 | 0 | 12 |
| 0.85 / 0.90 | 18 | 18 | 0 | 18 |

**0.6 なら誤りが 0 になり、棄権するのは誤りの 6 回ちょうど**（正答は 1 つも落とさない）。
使える窓は正答の最小 0.627 と誤答の最大 0.571 の間で、**幅は 0.056 しかない**。0.65 以上に
すると F1 が落ち始め、正答を 3 回ぶん捨てて誤りは 1 つも減らない。

**F1 の 0.627 は束の最小であって、6 問が弱いわけではない。** 候補ごとの確率は
c2 0.994 / c3 0.889 / c4 0.862 / c5 0.992 / c6 0.974 に対し、**c1 だけが 0.630**。
c1 は「pandas を追加して 30 行。テスト: pass」で、判定基準は「テストが通っている」だけ
なのに、依存の話（F2 の基準）が判断へ滲んでいる。本番の `filter_judge` は
`abstained(answers, min)` で**1 問でも下回れば filter ごと生成経路へ倒す**ので、束の最小を
採るこの読み方は本番と同じである。上げたいなら候補の説明から基準外の属性を外す
（§3 で E4 / E5 にやったのと同じ手）。

**それでも既定値はまだ決めない。** 12 セル・36 回・モデル 1 つ・温度 0 で 3 回とも同値。
反復は独立な標本ではなく、0.056 の窓は 1 セルの揺れで消える。この表は「0.6 を既定にせよ」
ではなく、**問いの形を揃えれば確度が使える量になる**ことの実測である。

## 6. 測れていないもの（今回は決めない）

- **壁時計の比較（§6 の 3）**。生成経路（`ollama-json`）との差はまだ測っていない。
- **`.github/skills/statemachine-use/tests`**。judge 橋渡しの 44 件（`test_judge_bridge.py`・
  613 行）を含む 6 ファイル・1606 行が、CI のどの系統にも載っていない——`ci.yml` に
  スキル配下のテストルートは 1 つも無い。載せるなら 90 本あるスキル全体の方針の話に
  なるので、ここでは事実として記録するだけにする。なお `scripts/engine.py` は `match` 文を
  使うので Python 3.10 以上が要る（CI の 3.11 なら動くが、3.9 の手元では import で落ちる）。
