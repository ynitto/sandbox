# agent-app: agent-audit が無いときの見せ方、手動の利用枠、利用枠に応じたエージェント選択

作成: 2026-09-16。状態: **提案（実装前。画面は ASCII の承認待ち）**。
対象: `tools/agent-app`（一部 `tools/agent-audit`）。
前提: [agent-app と agent-audit の責務分割](2026-09-16-agent-app-agent-audit-split-and-artifact-sharing-design.md)。

## 0. TL;DR

依頼の 4 件は、どれも「**枠の観測をどこが作り、どこが使うか**」という 1 つの問いの別の面である。
枠の観測は既に `agent-audit usage --json` の `agent_limits[]` が出していて、画面（設定 > 利用状況）も
それを並べている。足りないのは 3 つ——観測が取れない CLI（Kiro）の入口、観測を**選択に使う**経路、
そして agent-audit が無いときに「押せるように見えるが何も起きない」操作を畳むこと。

主要な決定:

1. **可用性は 3 値にそろえ、薄くするのは「agent-audit が居ないと本当に動かない操作」だけ**。
   ローカルに読めるもの（定型化したもの・手動で入れた枠）は薄くしない。理由は 1 か所に 1 行だけ出す。
2. **手動の利用枠は「申告」として台帳に 1 行書く**。上限は agent-app の設定、使った量は台帳の
   `quota_snapshot` 行。**割合の計算は agent-audit にやらせる**（数字は app で作らない）。
   Kiro だけの機能にはしない——単位（リクエスト / クレジット / トークン / 金額）を選べる一般の口にする。
3. **tier は「1 つのエージェント」から「候補の列」へ広げる**。保存値の旧形（単一の組）は 1 件の
   候補列として読み替える。同じ CLI の別モデルは枠を共有するので、枠を理由にモデル間は切り替えない。
4. **選択は純関数のまま**。`settings.resolve()` に観測（`agent_limits[]`）を引数で渡し、帯（緑 / 橙 /
   赤 / blocked）で候補を並べ替える。しきい値と並べ方は agent-dashboard の `profiles.js` と同じ語彙を
   借りる。**tier は勝手に下げない**（「品質重視」を選んだ人の意味を壊さない）。
5. **会話の途中では切り替えない**。会話は作った時点で CLI と tmux の文脈が決まる。効くのは
   新しい会話・タスク / ワークフローの手動実行・定期実行の既定だけ。

却下した主要案: agent-app が割合を計算して書く、node-budget の `config.json` を agent-app が書く、
agent-dashboard の `profiles.json` を agent-app が読む、利用枠が減ったら tier を自動で下げる、
枠が尽きた CLI を候補から消す。

読むべき人: 4 件のどれかを実装する人。画面だけを直す人は §5 の ASCII だけでよい。

## 1. いまどうなっているか

| もの | 置き場 | 作る人 |
|---|---|---|
| 枠の観測（`quota_used_percent` / `reset_at`） | 監査ストア（`userData/audit`） | `agent-audit collect` の `cli-quota`（claude / codex / copilot / kiro-cli を叩く） |
| 宣言上限（`max_tokens`） | node-budget の `config.json` の `allocation.agents.<cli>` | 人 / agent-dashboard / `agent-audit tune --apply` |
| 上の 2 つを畳んだ行 | `agent-audit usage --period total --json` の `agent_limits[]` | `usage.py` の `aggregate_agent_limits()` |
| 画面 | 設定 > 利用状況の「利用枠」 | `src/renderer/audit.js` の `renderLimits()` |
| 既定のエージェント | `execution.tiers.{small,medium,large} = {cli, model}` | 人（設定 > 実行制御） |
| 選択 | `settings.resolve(config, request, { optimized })` | 純関数。**観測を見ていない** |

引っかかりは 4 つ。

- **(1) 居ないときも押せる。** `Auditor.available` は `run()` か `summary()` を呼ぶまで `null`。
  「今すぐ集める」も期間・軸の選択も「記録を集める」も押せて、押すと 20 秒待たされて 1 行のエラーが出る。
- **(2) Kiro の枠が埋まらない。** 観測は WSL の `kiro-cli` へ ACP の usage を訊く実装なので、Kiro を
  Windows 側や IDE で使っている PC では 0 件になる。しかも Kiro の枠は**トークンではなくクレジット /
  リクエスト**（`agents/kiro.json` の `Monthly request limit reached`）なので、`max_tokens` に書ける数字が
  そもそも無い。画面は「取得できず」のまま動かない。
- **(3) 観測が選択に効かない。** 利用枠のカードは見られるが、枠が尽きた CLI が既定のまま選ばれ続ける。
  人が設定 > 実行制御を開いて付け替えるまで、失敗するほうへ送り続ける。
- **(4) tier に 1 つしか置けない。** 付け替えは「いま入っている 1 つを別のものに書き換える」操作なので、
  戻すには前の値を覚えていないといけない。

## 2. 目標と非目標

目標:

- agent-audit が入っていない PC で、利用状況の画面を開いても**押せる操作と押せない操作が見て分かる**。
- 観測が取れない CLI（いまは Kiro）でも、枠の残りが画面に出て、選択にも効く。
- 枠が尽きかけた CLI から、人が設定を開かずに次の候補へ移る。移ったことは画面の要約で分かる。
- 上の全部を切っても、いまと同じ動き（tier の先頭候補が固定で選ばれる）に戻せる。

非目標:

- 料金の計算。円やドルは**人が入れた数字をそのまま並べるだけ**で、単価表も為替も持たない。
- 会話の途中でのエージェント切り替え。
- agent-dashboard の `agent-profiles` / `agent-control` との統合（§4.5 で触れるが、この提案には含めない）。
- 複数 PC の枠の合算。

## 3. 決定

### 3.1 可用性は 3 値。薄くするのは「本当に動かない操作」だけ（項目 1）

`Auditor.probe()` の結果を、任意ツールで既に使っている 3 値（`available` / `unavailable` / `unknown`）で
`audit:status` に載せる。`automation:capabilities` と同じ語彙・同じ 60 秒キャッシュにして、renderer が
コマンド名や PATH を解釈しない現行の作法を保つ。

薄くする / 薄くしないの線は「agent-audit が居ないと**結果が変わらない**操作か」で引く。

| もの | 居ないとき | なぜ |
|---|---|---|
| 今すぐ集める | 薄く | 連鎖 6 段がそのまま失敗する |
| 使用量の期間・軸の選択 | 薄く | `usage --json` / `stats --json` が呼べない |
| 記録を集める・集める間隔 | 薄く | 周期を回しても 1 段目で止まる |
| 利用枠の自動観測の行 | 「—」 | 観測が更新されない |
| **手動で入れた枠** | **そのまま** | 人が入れた値で、app がローカルに持っている（§3.2） |
| **定型化したもの・改善案を出す** | **そのまま** | `artifacts.json` はネイティブに読め、git は app が持つ |
| 共有先の設定 | そのまま | 保存するだけ |

理由は `#audit-status` の既存の 1 行だけに出す（`renderRestrictions()` の「理由は出さない」と同じ）。
いまは「利用状況の収集ツールが見つかりません」が使用量の枠にも出て**同じことを 2 回言っている**ので、
使用量側は空にする（CLAUDE.md「同じことを 2 回言わない」）。

`unknown` の扱いは、2 つの規則を使い分ける。

- **操作を足すか**（[任意ツールの提案](2026-09-14-agent-app-optional-tools-usability-proposal.md)）:
  `unknown` は `unavailable` と同じ。足さない。
- **既にある操作を薄くするか**（本件・herd と同じ）: `unknown` の間は薄くしない。先に薄くして後で戻す
  ほうが、戻すより目立つ。

probe は「起動 90 秒後の初回周期」に加えて「設定 > 利用状況を開いたとき」に 1 回走らせる（60 秒
キャッシュ）。後から `install.sh` で入れた人は、タブを開き直せば戻る——そのための「再確認」ボタンは
足さない（押せる操作を増やさない）。

### 3.2 手動の枠は「上限は設定・使った量は申告」（項目 2）

**上限**は agent-app の設定に持つ。

```jsonc
// userData/config.json の audit
"limits": {
  "kiro": { "amount": 500, "unit": "request", "period": "month", "resetAt": "2026-10-01" }
}
```

node-budget の `config.json` は**書かない**。あちらは WSL 側の書き手（人・agent-dashboard・
`agent-audit tune --apply`）が既に居て、`allocation.agents.<cli>.max_tokens` はトークン専用である。
書き手を増やすと、責務分割の「一つのストアに同時に一つの書き手」を別の場所で破ることになる。

**使った量**は台帳に 1 行書く。`audit.js` の `feed()` にもう 1 つの行の形を足すだけで、reader は増えない
（`collect.py` は `event` 付きの行を `kind: event` として取り込み、`aggregate_agent_limits()` が CLI ごとの
最新 1 件を拾う。既に `quota_source` を運ぶ口がある）。

```jsonc
{"ts":"2026-09-16T05:00:00Z","node":"pc-a","tool":"agent-app","agent_cli":"kiro",
 "workload":"quota","ref":"quota","purpose":"quota","event":"quota_snapshot",
 "quota_source":"manual","quota_used_units":120,"quota_limit_units":500,
 "quota_unit":"request","reset_at":"2026-10-01T00:00:00Z","seconds":0,"status":"done"}
```

**割合は agent-audit が作る。** `usage.py` の `aggregate_agent_limits()` に、`quota_used_percent` が無く
単位付きの値があるときだけ `used / limit` から百分率を出す枝を足し、`quota_unit` /
`quota_used_units` / `quota_limit_units` をそのまま出力に載せる。単位の解釈（月初リセット・繰り越し・
端数）が後から増えても、規則が増えるのは agent-audit の 1 か所だけになる。

- 却下: **app が割り算して `quota_used_percent` を書く。** 1 行で済むが、「数字は agent-audit が作る」
  という責務分割の不変条件を破る。次に「先月の繰り越しは足すのか」が出た瞬間、規則が 2 か所になる。
- 却下: **Kiro 専用の入力欄。** 単位が違うだけで、Copilot の企業プランや ollama の電気代でも同じものが
  要る。CLI 名で分岐した画面は、次の CLI で必ずもう一度書くことになる。

段取りの都合を 1 つ。agent-audit 側の枝が入るまでの間、app は割合を出せない。そのときは棒を描かず
「手動 120 / 500 リクエスト（9/16 申告）」とだけ出す——**入れた値をそのまま出すのは集計ではない**。

手動と自動の混ざり方:

- 自動観測がある CLI では自動が主。手動は小さく添える（`quota_source` で区別できる）。
- 観測が無い CLI（Kiro）では手動が主。
- 手動の申告も期間の切り替わりで失効する（既存の `expired` と同じ規則）。失効したら「更新待ち」と出し、
  **手動上限から現在の使用率を推測しない**（`renderLimits()` の現行コメントどおり）。

### 3.3 tier は候補の列（項目 4）

```jsonc
"execution": {
  "tiers": {
    "small":  { "candidates": [ {"cli":"copilot","model":""}, {"cli":"kiro","model":""} ] },
    "medium": { "candidates": [ {"cli":"claude","model":"sonnet"} ] },
    "large":  { "candidates": [ {"cli":"claude","model":"opus"} ] }
  }
}
```

- 旧形（`{"cli":"claude","model":"sonnet"}`）は `normalize()` が 1 件の候補列へ読み替える。保存は新形。
- 上限 4 件（画面が縦に伸びず、並べ替えの手間も出ない）。
- **同じ CLI の別モデルは枠を共有する**ので、枠だけを理由にモデル間を切り替えない
  （`schemas/agent-profiles.schema.json` の規則をそのまま借りる）。帯は CLI 単位で見る。
- 候補列の**先頭が既定**。§3.4 を切っても、いまと同じ「tier ごとに固定の 1 つ」に戻る。

### 3.4 選択は純関数のまま、観測は引数で渡す（項目 3）

```js
settings.resolve(config, request, { optimized, limits, current, now })
//   limits  … agent-audit の agent_limits[] をそのまま（app は加工しない）
//   current … いま選ばれている候補（ちらつき防止の保持に使う）
```

帯としきい値は agent-dashboard の `profiles.js` と同じにする。**同じ語彙を 2 通りに定義しない**ため。

| 帯 | 条件 |
|---|---|
| 緑 | 使用率 70% 未満 |
| 橙 | 70% 以上 90% 未満 |
| 赤 | 90% 以上 100% 未満 |
| blocked | 100%、または `quota_kind` が立っていて `reset_at` が未来 |
| unknown | 観測が無い・古い（周期の 3 倍より古い）・読めない |

並べ替えは `帯 → いま使っている候補 → 宣言順`（`bestCandidate()` と同じ）。unknown は緑と赤の間に置く
（観測が無いことを理由に、枠が減っていると決めつけない）。

agent-dashboard と**変える点**は 1 つ。**tier は落とさない。** あちらは予算方針から tier を決めるので
降格が筋だが、agent-app の tier は人が「節約 / 標準 / 品質重視」として選んだ意味を持つ。全候補が赤・
blocked のときは先頭候補のまま送り、枠の状態は利用状況の画面が既に出しているので、実行設定に説明文を
足さない（「説明文を画面に常駐させない」）。

- 保持: 選んだ候補は最低 15 分（`min_hold_sec: 900` と同じ）保持する。blocked だけは即時に退避。
- 更新の頻度: 帯は `audit:changed` と `audit:summary` の結果からだけ更新する。**会話を送るたびに WSL を
  叩かない**（周期は既定 1 時間、タブを開いたときにも更新）。
- 効く場所: 新しい会話の既定、タスク・ワークフローの手動実行、定期実行の既定。
  **会話の途中では変えない**（tmux の cwd も CLI の文脈も、会話を作った時点で始まっている）。
- 切る: 設定 > 実行制御の「利用枠に応じて切り替える」（既定 ON）。agent-audit が `unavailable`、
  または観測が 1 件も無いときは、チェックに関わらず黙って先頭候補（§3.1 と同じ規則で、理由は
  利用状況の 1 行だけ）。

### 3.5 却下した案

- **枠が尽きた CLI を候補の一覧から消す。** 「選べたものが消える」は、原因が画面から読めない。薄くも
  しない——枠は数分で戻ることがあり、戻るたびに増減する一覧は落ち着かない。並べ替えだけにする。
- **agent-dashboard の `profiles.json` を agent-app が読む。** 任意ツールが本体機能の前提になり ADR-11 に
  反する。逆向き（agent-app の設定を agent-dashboard が読む）も、書き手が 2 本になる。
- **選択の履歴を台帳に書かない。** …ではなく、書く。切り替えが起きたら `event: "agent_switch"` の行を
  1 つ足す（消費 0 の観測行なので `kind: event` に入り、コストの数字を動かさない）。後から「何回
  切り替わったか」を数えられないと、しきい値の見直しができない。

## 5. 画面（ASCII。承認をもらってから実装する）

借りる形は各図に書く。新しい部品は作らない。

### 5.1 設定 > 利用状況（agent-audit がある。既存の形のまま、右端に手動の入口が 1 つ増える）

借りる形: いまの `.environment-status` カード（`.row` の見出し + `.sub` + `#audit-limits`）。
ボタンは `.small`。

```text
┌ 設定 ─────────────────────────────────────────────────────┐
│ アプリ  指示  実行制御  共有  保存データ  [利用状況]        │
├───────────────────────────────────────────────────────────┤
│ ┌───────────────────────────────────────────────────────┐ │
│ │ 利用枠                              [ 今すぐ集める ]  │ │
│ │ 9/16 14:20 に集めました · 定型化したもの 3 件         │ │
│ │                                                       │ │
│ │ Claude                                      60% 使用  │ │
│ │ ████████████░░░░░░░░                                  │ │
│ │ リセット 9/17 09:00 · 取得 14:20            [手動 +]  │ │
│ │                                                       │ │
│ │ Kiro                                        24% 使用  │ │
│ │ ████░░░░░░░░░░░░░░░░                                  │ │
│ │ 手動 120 / 500 リクエスト · 申告 9/16       [手動 +]  │ │
│ └───────────────────────────────────────────────────────┘ │
```

`[手動 +]` は行の右端の `.small`。名前は「手動で入れる」。

### 5.2 手動の枠を入れる（押した行だけ開く。要るまで出さない）

借りる形: 設定 > 指示の「起動時アクション」の行（`.startup-row`。`select` と `input` を 1 行に並べ、
右端に削除）。ここでは削除の代わりに `[やめる] [保存]`。

```text
│ │ Kiro                                                  │ │
│ │ [ 120      ] / [ 500      ] [ リクエスト ▾]           │ │
│ │ リセット [ 2026-10-01 ]         [やめる] [ 保存 ]     │ │
```

- 単位は `リクエスト / クレジット / トークン / 円`。
- 「リセット」は `（任意）`。空なら期間（月）の切り替わりで失効する。
- 保存すると行が畳まれ、`.sub` に「手動 120 / 500 リクエスト · 申告 9/16」が出る。

### 5.3 設定 > 利用状況（agent-audit が無い）

```text
│ ┌───────────────────────────────────────────────────────┐ │
│ │ 利用枠                              [ 今すぐ集める ]  │ │   ← 薄い
│ │ agent-audit が見つかりません（agent-tools の          │ │
│ │ install.sh で入ります）                               │ │
│ │                                                       │ │
│ │ Claude                                            —   │ │
│ │ Kiro          手動 120 / 500 リクエスト · 申告 9/16    │ │
│ └───────────────────────────────────────────────────────┘ │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ 使用量                                    [ 今月 ▾ ]  │ │   ← 薄い
│ │                                                       │ │   ← 空（理由は上に 1 回だけ）
│ │ 内訳                                    [ AIごと ▾ ]  │ │   ← 薄い
│ └───────────────────────────────────────────────────────┘ │
│ ▸ 定型化したもの                                          │   ← そのまま（ローカルで読める）
│ ▸ 収集・共有の設定                                        │
```

### 5.4 設定 > 実行制御（tier ごとの候補列）

借りる形: 設定 > 指示の「起動時アクション」「定型の依頼」と同じ
（`.settings-group` + `.settings-group-head` に `[追加]` + `.startup-actions` の行）。
いまの `.tier-grid` / `.tier-row` は、この形に寄せて置き換える。

```text
│ ☑ 節約・品質重視を使う                                    │
│ ┌ 既定の起動方針 ───────────────────────────────────────┐ │
│ │ ○ 標準    ● 節約    ○ 品質重視                        │ │
│ └───────────────────────────────────────────────────────┘ │
│ ☑ 利用枠に応じて切り替える                                │
│                                                           │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ 節約                                       [ 追加 ]   │ │
│ │ [ Copilot ▾] [ モデル（自動）      ]        [ 削除 ]   │ │
│ │ [ Kiro    ▾] [ モデル（自動）      ]        [ 削除 ]   │ │
│ └───────────────────────────────────────────────────────┘ │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ 標準                                       [ 追加 ]   │ │
│ │ [ Claude  ▾] [ sonnet              ]        [ 削除 ]   │ │
│ └───────────────────────────────────────────────────────┘ │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ 品質重視                                   [ 追加 ]   │ │
│ │ [ Claude  ▾] [ opus                ]        [ 削除 ]   │ │
│ └───────────────────────────────────────────────────────┘ │
│ 会話の既定権限          [ 確認して実行 ▾ ]                │
│ 同時実行数              [ 2 ]                             │
```

- 上から順が優先順（先頭が既定）。「利用枠に応じて切り替える」が ON のときだけ、枠の帯で順が変わる。
- 「節約・品質重視を使う」が OFF のときは、いまと同じく標準の行だけ残して他を薄くする。

### 5.5 実行設定（会話・タスクの手動実行）

**変えない。** 選ばれたエージェントの名前は、いまも要約に出ている（`標準 · Claude / sonnet · スキル 自動`）。
切り替わったことは、この名前が変わることで分かる。ここに理由の行を足さない。

```text
┌ 実行設定 ─────────────────┐
│ 起動方針   [ 標準      ▾ ] │
│ スキル     [ 自動      ▾ ] │
└───────────────────────────┘
   標準 · Codex / — · スキル 自動      ← 枠が減った日はここが Claude から Codex に変わる
```

## 6. 決めきれていないこと（実装前に返事がほしい）

1. **「利用料」の意味。** この提案は「使った量（リクエスト / クレジット / トークン）」として組み、
   単位に「円」も選べるようにしている。金額そのものを主にしたい（単価表を持って、トークンから円を
   出す）なら、agent-audit 側に単価の表が要るので別の提案にする。
2. **手動の申告をどのくらいの頻度で入れるか。** 月 1 回でよければ今の形で足りる。毎日入れるなら、
   入力の場所を設定の奥ではなく、利用枠が赤い CLI を選んだときの実行設定の中に置くほうがよい。
3. **切り替えの通知。** 既定のエージェントが変わったとき、無言で変えるか（この提案）、
   1 回だけ知らせるか。
