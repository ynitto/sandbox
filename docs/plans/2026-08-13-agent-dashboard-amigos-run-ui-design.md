# Agent Dashboard agent-amigos 実行UI設計

- 日付: 2026-08-13
- 状態: 承認済み
- 対象: `tools/agent-dashboard` の「ミッション」領域
- 参考: ワークフロー領域の「実行」タブ

## 目的

「参加」領域は他の仕事へ加わるための既存機能として維持する。その一方で「ミッション」領域を
agent-amigos の入口として明確にし、利用者がタスクを入力し、適切なチームを編成して実行するまでを
一続きで行えるようにする。

## 採用案

「ミッション」領域を「実行」「ミッション」の2タブ構成にする。「実行」を先頭かつ初期表示とし、
タスク内容からチームを自動編成する。自動編成を既定とするが、必要な利用者は編成結果の役割を確認・
編集してから実行できる。

既存の `agent-amigos build-team`、`post`、ミッション一覧、実行追跡の契約を再利用する。新しい実行器や
別形式のチーム定義は追加しない。

## 画面構成

### タブ

1. **実行**: チーム編成、タスク入力、実行開始
2. **ミッション**: 既存の進行状況、要対応、成果確認

「参加」領域の「参加できる仕事」「参加の状況」は変更しない。

### 実行タブ

ワークフロー実行タブと同じ余白、カード、フォーム、主要操作の配置を使う。

1. 上部にチーム編成方式と選択中チームの概要を置く。
2. 「自動で編成」を既定にする。
3. 自動編成後は役割名、責務、必須・任意の区別を概要カードで確認できる。
4. 「役割を調整」で詳細編集を展開する。通常利用ではJSONを直接見せない。
5. 中央にタイトル、完了したときの状態、進め方・制約、作業フォルダを置く。
6. 下部に主要操作を1つ置く。未編成時は「チームを編成して実行」、編成確認後は
   「このチームで実行」とする。
7. 実行開始後は「ミッション」タブへ移り、作成したミッションを選択する。

作業フォルダはワークフロー実行タブの cwd と同じ位置・入力形式で必須指定する。チームホームは
commands の投函先、作業フォルダは成果物を作る対象として分離し、後者を
`mission.workspace.repo` へ渡す。

agent-amigos ホームが未設定でも実行フォーム自体は表示する。設定不足はフォーム上部と実行時の
検証で案内し、入口を空画面へ置き換えない。

## 操作フロー

### 通常経路

1. 利用者がタスク内容を入力する。
2. Dashboard が既存の build-team 経路へ入力を渡す。
3. agent-amigos がチームを編成し、検証済みの roles を返す。
4. Dashboard が既存の post 経路でミッションを作成し、実行を開始する。
5. 作成したミッションを「ミッション」タブで表示する。

### 編集経路

1. タスク内容からチームを自動編成する。
2. 利用者が「役割を調整」を開く。
3. 役割名、責務、必須・任意など許可された項目を編集する。
4. 既存の roles 検証を通してからミッションを作成する。

編成と公示の間でエラーが起きた場合も、タスク入力と編成結果を保持する。

## コンポーネント境界

- ミッション領域のタブ登録と初期選択を変更する。
- 新しい実行タブは、ワークフロー実行タブのレイアウト規則を共有するが、状態や処理はコピーしない。
- 既存のミッション依頼ダイアログで使っているフォーム状態、検証、`amigos:buildTeam`、
  `amigos:post` の呼び出しを再利用可能な関数へ分離する。
- 既存ミッション一覧は「ミッション」タブへそのまま配置し、取得・追跡・成果表示を維持する。
- Renderer から agent-amigos のバスへ直接書き込まない。

## エラー処理

- 必須のタスク内容が無い場合は送信せず、該当欄の近くに説明する。
- チーム編成失敗時は入力を保持し、再試行できるようにする。
- roles の検証失敗は、修正すべき役割と項目を示す。
- ミッション作成失敗時は編成結果を保持する。
- 非同期処理中は主要操作を無効化し、二重作成を防止する。
- 成功・失敗は `role="status"` / `role="alert"` で通知する。

## テスト

- 「ミッション」領域に「実行」「ミッション」がこの順で表示される。
- 領域を開いた初期状態が「実行」になる。
- タスク入力から build-team、post が既存契約どおり呼ばれる。
- 自動編成結果を確認し、許可された役割項目を編集できる。
- 空入力、編成失敗、roles 検証失敗、公示失敗でも入力を失わない。
- 実行中の二重送信を防ぐ。
- 成功後に「ミッション」タブへ移り、作成した対象を表示する。
- 既存ミッション一覧・依頼ダイアログの互換性を維持する。
- 「参加」領域のDOM、候補取得、参加操作が変わらない。
- ワークフロー実行タブと主要なレイアウト規則が揃う。

## 対象外

- 「参加」領域の再設計
- agent-amigos のチーム編成アルゴリズム変更
- 新しい役割定義形式の追加
- ミッション実行エンジンやバス契約の変更
- ワークフローとミッションの統合

## 実装計画

1. 既存のミッション依頼ダイアログとIPCを、実行タブから再利用できる境界へ整理する。
2. 「ミッション」領域へ「実行」「ミッション」タブを登録し、初期選択を「実行」にする。
3. ワークフロー実行タブに合わせたフォーム、チーム概要、役割編集、実行操作を実装する。
4. build-team → 任意編集 → post → ミッション選択の状態遷移を実装する。
5. 単体・UI回帰テストを追加し、既存の「参加」とミッション追跡の非退行を確認する。
6. テスト、型・構文検査、ビルド、必要に応じてElectron画面の操作確認を行う。
