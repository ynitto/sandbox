# 多肢選択方式の再試験（2026-09-22）

> 2026-09-21 に順序依存で不採用にした多肢選択（[調整結果](tuning-report.md)・[独立検証](assessed-validation.md)）を、
> その後に足した回転平均（`judge.rotations`、[実測](../../plans/2026-09-22-judge-rotation-averaging.md)）で
> 引き直した記録。**再び不採用。** 現行の候補ごと独立評価は変えていない。

## 結論

速い設定は順序に引かれ、順序を直すと現行より遅くなる。速度と順序安定を同時に満たす設定は無かった。

| 方式 | 期待一致（通常順） | 期待一致（逆順） | 順序一致 | 1 依頼の中央値 |
|---|---|---|---|---|
| independent（現行・候補ごと隔離） | 10/12 | 10/12 | **12/12** | 8.21s |
| choice r=1（当時の不採用案） | 12/12 | 6/12 | 6/12 | 5.08s |
| choice r=2（選択肢だけ回す） | 10/12 | 6/12 | 8/12 | **3.62s** |
| choice r=4（選択肢だけ回す） | 10/12 | 6/12 | 8/12 | 6.44s |
| choice r=2（状態ごと回す） | 12/12 | 8/12 | 8/12 | 9.11s |
| choice r=4（状態ごと回す） | 6/12 | 6/12 | **12/12** | 10.98s |

順序で選択が変わった依頼:

| 方式 | 変わった依頼 |
|---|---|
| independent | なし |
| choice r=1 | h4 / h5 / h6 / proposal / debug / architecture |
| choice r=2・r=4（選択肢だけ回す） | h4 / h5 / h6 / architecture |
| choice r=2（状態ごと回す） | h4 / debug / proposal / architecture |
| choice r=4（状態ごと回す） | なし |

## 分かったこと

**`judge.rotations` は候補の順序バイアスを消さない。** 回すのは問いの選択肢の行だけで、候補は
状態（`state["candidates"]` と `economics`）にも並んでいる。そちらは回らないので、状態側の順序が
そのまま判定に効く。選択肢だけ回した r=2 / r=4 は、r=1 の 6/12 から 8/12 へ改善したが順序一致に
届かなかった。

**`agreement` はこの偏りを検知できない。** 全ての回転が同じ状態を見ているので、状態側の偏りは
回転の間で一致してしまう。実測でも `agreement` は中央値 1.00 のまま、入力順を変えると答えが
変わった。`agreement` が見ているのは**ラベルの位置**の偏りだけで、材料の並びの偏りではない。

**状態ごと回すと順序は完全に消えるが、答えも消える。** r=4（4 候補すべてを各位置へ 1 回ずつ
置く）は順序一致 12/12 を達成した一方、期待一致が両順とも 6/12 へ落ちた。4 通りの対数平均で
信号が均されている。r=2 は期待一致（通常順 12/12）は良いが、巡回が半分なので順序依存が残る。

**速度の出どころが順序依存そのもの。** choice が速いのは候補を 1 度しか見ないから。1 度しか
見ないことが順序に引かれる原因で、それを直すには複数回読むしかなく、読んだ分だけ遅くなる。
状態ごと回す案は状態が毎回変わるので接頭辞キャッシュにも乗らず、9〜11 秒と現行より遅い。

## 条件

- 依頼 12 件（[ホールドアウト 6 件](independent-holdout-input.json) + `tune.py` の開発 6 件）× 候補順 2 通り
  × 方式 6 通りの 144 試行。判定は gemma4:e4b のローカル judge で、選択された CLI は起動していない。
- 期待する local / cloud はテスト設計上の区分で、実作業の成功を測った正解ではない。
- `choice` の問い文・方針文は当時の `assessed` 変種（`tune.py`）と同一。要求水準の問いは本番の
  `modelfit.REQUIREMENTS` を使った。確度が 0.6 未満か `other` なら本番と同じ `audit_order` へ倒す。
- 1 条件 1 回の便宜標本。確率は校正された成功率ではない。
