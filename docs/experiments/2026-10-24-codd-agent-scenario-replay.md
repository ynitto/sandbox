## 見つけて直した不具合

5周目で、`rollback` が作業ツリーだけを戻し、Gitのステージに中止した変更を残した。
同じリポジトリのコードと文書の両方で、戻した後の `git status --short` が `MM` になった。
この状態では、利用者に「戻しました」と報告した変更を、そのままコミットできてしまう。

変える前の印に、受け持つファイルのステージのモードとblobを保存するようにした。
戻すファイルにはステージだけが変わったものも含め、作業ツリーとステージを別々に復元する。
開始前からステージしていた内容と未ステージの内容が異なっていても、その区別を保つ。

修正後の5周目では、`git diff` と `git diff --cached` のコード・文書の変更がともに空になり、
残る未追跡ファイルは今回の計画の記録だけだった。報告も「利用者がやめた（変えた分は戻した）」になった。
再生した道を `tools/codd-agent/tests/scenarios/monorepo-library.md` の3bに追記した。
その後、同じ依頼を新しく始めて計画検査を通し、確認段階でSTOPする経路もENDまで確認した。
この回の報告は「何も変えていない」となり、前の回の復元状態は混ざらなかった。

## 回帰テスト

`test_codd_agent.py` のrollbackの結合テストを拡張・追加した。3件とも修正前に失敗し、修正後に成功した。

- ステージした更新・追加・削除を、自分と参照先の両側で戻す。
- 開始前のステージ済みの内容と、未ステージの内容をそれぞれ保つ。
- 作業ツリーは同じで、ステージだけを変えたファイルも戻す。

全体の確認は `python -m unittest discover -s tools/codd-agent/tests`。343件すべて成功（181.739秒）。
`git diff --check` も成功。
