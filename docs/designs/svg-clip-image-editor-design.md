# SVG クリップ画像エディタ 設計

SVG に含まれる「クリップされた画像」の見え方（どの部分がクリップ枠に収まるか）を、
マウスまたはタッチで画像を動かして合わせ込む React コンポーネントの設計。

> 状態: サンプル実装あり（[`samples/svg-clip-image-editor/`](../../samples/svg-clip-image-editor/README.md)、0.1.0）。
> サンプルは TypeScript ではなく JavaScript（ESM・JSDoc）で書き、JSX を使わずビルドなしで読み込めるようにした。
> サンプルで未実装: 既存 SVG の取り込み（§1.1）、文脈表示（§3.3 の `context`）。
> 契約を検査する CLI（付録 B）は設計だけで、実装しない。

## 0. 概要

```
            ┌──────────────────────── SvgClipImageEditor ────────────────────────┐
 入力       │                                                                     │  出力
 ─────      │  読み込み ─▶ 描画 ─▶ 操作（ドラッグ・2本指・ホイール・キー・ボタン） │  ─────
 SVG 文字列 ─▶  契約の検査   枠を固定   └▶ ゴム・慣性・ばね ─▶ 確定（履歴）     ─▶ SVG 文字列
 プロップ   ─▶  解析         画像を2枚   覆い制約                             ─▶ コールバック
            │                                                                     │
            └─────────────────────────────────────────────────────────────────────┘
```

- **入力**（§1）: 契約（§1.1）を満たす SVG 文字列と、編集するスロット名・動きの定数などのプロップ。
- **制約**（§2）: 枠と表示範囲は動かない。変えるのは画像の `transform` だけ。枠は画像で覆う。コンポーネントは外の何にも依存しない。
- **処理の流れ**（§3）: 読み込み → 描画 → 操作 → ゴム・慣性・ばね → 確定。
- **出力**（§4）: 元と同じ座標系のまま、画像の `transform` だけを書き換えた SVG と、それを知らせるコールバック。

### 0.1 用語

| 用語 | 意味 |
|---|---|
| スロット | 編集できる画像の単位。`data-clip-slot="名前"` の印を付けた `<g>` と、その唯一の子の `<image>` の組 |
| 枠 | スロットにかかっている `<clipPath>` の形。編集中は動かない |
| 注目領域 | エディタに映す範囲。枠の周りに余白を足した矩形で、編集中は動かない |
| 覆い制約 | 枠の内側に画像のない所を作らない、という制約 |
| ゴム | 画像が枠の端を越えて引っ張られたとき、抵抗しながら少しだけ越えて見せる動き |
| 慣性 | 弾いて離したとき、画像が減速しながら滑り続ける動き |
| ばね | 端を越えた画像が、覆える位置へ戻る動き |
| 確定（commit） | 画像が止まり、その位置を履歴に積んで外に知らせること |

## 1. 入力

### 1.1 SVG（契約）

#### 形

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="vx vy vw vh" width="…" height="…">
  <defs>
    <clipPath id="hero-clip" clipPathUnits="userSpaceOnUse" [transform="…"]>
      <!-- rect / circle / ellipse / polygon / polyline / path の 1 つ以上（和集合） -->
    </clipPath>
  </defs>

  <!-- 飾り（自由） -->

  <g [transform="…"]>                               <!-- 祖先: <g> だけ、任意段数 -->
    <g data-clip-slot="hero"                        <!-- スロット -->
       clip-path="url(#hero-clip)" [transform="…"]>
      <image href="…" x="…" y="…" width="…" height="…"
             preserveAspectRatio="…" [transform="…"]/>  <!-- 唯一の子。出力で書き換わるのは transform だけ -->
    </g>
  </g>

  <!-- 飾り（自由。スロットより後ろの要素はスロットの上に描かれる） -->
</svg>
```

クリップを持つ要素（スロットの `<g>`）と動かす要素（`<image>`）を分けるのが要点。
`userSpaceOnUse` のクリップの座標は、クリップを参照する要素自身の `transform` を含むユーザー空間で解釈される。
同じ要素に `clip-path` と `transform` があると、画像を動かした瞬間に枠も一緒に動いてしまう。

#### 規則

契約はスロットとその周りにだけかける。**ここに挙げていないものはすべて自由**
（飾りの要素の種類・数・順序、テキスト、グラデーション、フィルタ、CSS アニメーション、別のクリップ、
印のない＝編集しないクリップ付き画像、スクリプト。エディタはスクリプトを実行しない）。

| 番号 | 規則 | 理由 |
|---|---|---|
| **スロット** | | |
| S1 | スロットは `data-clip-slot="名前"` を持つ `<g>`。名前は `[a-z0-9][a-z0-9-]*` で文書内で一意 | 対象を構造から推測しない。飾りにクリップ付き画像が増えても対象がずれない |
| S2 | スロットの `<g>` は `clip-path="url(#id)"` を**属性で** 1 つ持つ | `style` や CSS クラス経由のクリップは解析だけでは決まらない |
| S3 | スロットの子は `<image>` ちょうど 1 つ（空白とコメントは除く）。間に `<g>` を挟まない | 動かす対象と座標の対応を 1 通りにする |
| S4 | `<image>` は `x` / `y` / `width` / `height` を単位なしの数値で持つ。`clip-path` / `mask` / CSS の変形を持たない | 描画矩形を解析だけで決める |
| S5 | `<image>` の `href`（または `xlink:href`）は `data:image/*` / `https:` / `http:` / `blob:` / 相対 URL | §2.4 |
| S6 | スロットの `<g>` は `mask` を持たない。`opacity` と `filter` は可（編集画面では再現しない。警告） | マスクは枠の見え方を変え、覆い制約の前提が崩れる |
| **クリップ** | | |
| C1 | 参照先の `<clipPath>` が文書内にあり、`clipPathUnits` は `userSpaceOnUse`（省略も可） | `objectBoundingBox` だと枠が画像の外接矩形に追従して動く |
| C2 | 子は `rect` / `circle` / `ellipse` / `polygon` / `polyline` / `path` だけ。各子の `transform` は可 | 凸包（§2.2）を解析だけで求められる形に限る |
| C3 | `<clipPath>` にも子にも `clip-path` を付けない | 枠の形を 1 段で決める |
| C4 | 同じ `<clipPath>` を複数のスロットや飾りが共有してよい | エディタはクリップを書き換えない |
| **祖先** | | |
| A1 | ルートからスロットまでの祖先は `<g>` だけ（`<svg>` の入れ子・`<symbol>` / `<use>` / `<switch>` / `<a>` / `<foreignObject>` を挟まない） | 座標の変換を `transform` 属性だけで決める |
| A2 | 祖先の `transform` は属性で書き、逆行列を持つ | 同上 |
| A3 | 祖先は `clip-path` / `mask` を持たない | 外側で切られると、エディタの枠と実際に見える範囲がずれる |
| A4 | 祖先の `opacity` / `filter` は可（編集画面では再現しない。警告） | 見え方だけで座標には効かない |
| **文書全体** | | |
| D1 | ルートの `<svg>` は `viewBox` を持つ | 出力の座標系を明示する |
| D2 | `id` は文書内で一意 | クリップの参照を 1 通りにする |
| D3 | `<use>` がスロットとその子孫を参照しない | 参照先の画像が編集で一緒に動いてしまう |
| D4 | CSS（`<style>` と `style` 属性）が、スロット・その `<image>`・祖先に `transform` / `translate` / `rotate` / `scale` / `transform-origin` / `transform-box` / `clip-path` / `mask` を当てない | CSS の変形は属性の `transform` を上書きし、解析した座標とずれる |

D4 は CSS の規則ごとに、セレクタがスロット・画像・祖先のどれかに一致するかを `element.matches(selector)` で確かめる。
飾りに CSS の変形やアニメーションを使うのは自由。

#### 検査

契約は `lintDocument(doc, parseCss): LintIssue[]` で機械的に検査する。コンポーネントは読み込みの最初にこれを呼び、
エラーが 1 つでもあれば編集を始めない。同じ関数を CLI（付録 B、設計のみ）から呼べる形にしておく。

```ts
interface LintIssue {
  rule: string;              // 'S3' など上の表の番号
  severity: 'error' | 'warning';
  slot?: string;             // 関係するスロット名
  path: number[];            // 違反した要素への子インデックス列
  location: string;          // 人が読む位置: '/svg/g[2]/g[1]'
  message: string;
}
```

警告（編集はできる）: S6 / A4 の `opacity` / `filter`、文脈表示（§3.3）で読めない外部 URL の画像。

#### 既存の SVG の取り込み（任意）

契約に合わない既存の SVG は、`adoptClipDocument(svg, { image: 'photo' })` で**描画結果を変えずに**契約の形へ
書き換えてから渡す。コンポーネントは暗黙には書き換えない（どこを書き換えたかを利用者が確かめられるように、別の関数にする）。

| 入力 | 書き換え |
|---|---|
| `<image>` 自身が `clip-path` を持つ | `<g data-clip-slot clip-path="…" transform="元の transform">` で包み、`<image>` から `clip-path` を外して `transform` を恒等にする |
| `<image>` とクリップの `<g>` の間に `<g transform="J">` がある | 中間の `<g>` を外し、`<image transform>` を `J·M` にする（中間の `<g>` が他の子を持つときは取り込めない） |
| `clipPathUnits="objectBoundingBox"` | 読み込み時点の外接矩形で `userSpaceOnUse` に焼き直した**複製**の `<clipPath>`（新しい id）を作り、参照先を差し替える。元は残す |
| ルートに `viewBox` がない | `0 0 width height` を足す（`width` / `height` が px か単位なしのときだけ） |
| スロットの印がない | 指定した `<image>` を含む `<g>` に `data-clip-slot`（既定名 `image-1`, `image-2` …）を付ける |

### 1.2 プロップ

```ts
type Matrix = [a: number, b: number, c: number, d: number, e: number, f: number];
type Rect = { x: number; y: number; width: number; height: number };

interface SvgClipImageEditorProps {
  // ── 何を編集するか ──
  svg: string;                          // 元の SVG 文字列（§1.1 の契約を満たす）
  slot?: string;                        // 編集するスロット名。省略時は文書順で最初。変えると切り替わる（§3.7）

  // ── 見せ方 ──
  focusPadding?: number;                // 注目領域の余白（枠の幅・高さに対する比）。既定 0.25
  outsideOpacity?: number;              // 枠の外の画像の不透明度。既定 0.35
  context?: 'none' | 'layers';          // 飾りを上下に重ねて見せるか。既定 'none'（§3.3）
  contextAboveOpacity?: number;         // 上の飾りの不透明度。既定 0.5
  toolbar?: boolean;                    // 下のボタン列を出すか。既定 true
  labels?: Partial<ToolbarLabels>;      // ボタンの文言（既定は日本語）

  // ── 動き ──
  cover?: boolean;                      // 覆い制約。既定 true（§2.2）
  rotationCover?: 'rubber' | 'grow';    // 回転で覆えなくなったとき。既定 'rubber'（§3.5）
  motion?: Partial<MotionOptions>;      // ゴム・慣性・ばねの定数（下の表）
  minScale?: number;                    // 読み込み時に対する拡大率の下限。既定 0.1
  maxScale?: number;                    // 同上限。既定 20
  rotationSnap?: number;                // 2 本指の回転を 90° の倍数に吸着させる幅（度）。既定 0（なし）

  // ── 値の持ち方 ──
  transforms?: Record<string, Matrix>;  // 制御モード: 親がスロットごとの画像の行列を持つ
  defaultTransforms?: Record<string, Matrix>; // 非制御モードの初期値（既定は SVG に書かれている値）

  // ── 出力の書式 ──
  precision?: number;                   // 出力の平行移動成分の小数桁。既定 3
  outputTransform?: 'matrix' | 'decomposed'; // 既定 'matrix'（§4.1）

  // ── 知らせ ──
  onLoad?: (info: { slots: { name: string; bboxR: Rect }[]; warnings: LintIssue[] }) => void;
  onChange?: (M: Matrix, slot: string) => void;                       // 動いている間、毎フレーム
  onCommit?: (svg: string, edit: { slot: string; M: Matrix }) => void; // 止まって確定したとき
  onError?: (err: { code: string; message: string; issues?: LintIssue[] }) => void;

  className?: string;
  style?: React.CSSProperties;          // CSS 変数（§2.3）で色を変えられる
}
```

#### 動きの定数（`motion`）

すべて外から指定できる。**数値をすべて 0 にすると、画像は端に当たった瞬間に止まり、慣性もアニメーションもない**。

| キー | 既定 | 意味 | 0 のとき |
|---|---|---|---|
| `rubber` | 0.55 | ゴムの抵抗の係数。大きいほど軽く伸びる | 端を越えない（当たったら止まる） |
| `rubberLimit` | 0.25 | 平行移動で越えられる量の上限（枠の短辺に対する比） | 端を越えない |
| `scaleRubberLimit` | 0.5 | 縮めすぎで越えられる量の上限（倍率から 1 を引いた値。0.5 = 1.5 倍分） | 縮めすぎない（覆える最小の大きさで止まる） |
| `friction` | 0.325 | 慣性が減速する時定数（秒）。大きいほど遠くまで滑る | 慣性なし |
| `flingSpeed` | 0.3 | 慣性に入る速さ（注目領域の幅 / 秒） | （`friction` が 0 なら意味なし） |
| `springPeriod` | 0.4 | ばねで戻る速さ（秒。目安として戻りきる時間） | 即座に戻る |
| `snapDuration` | 0.2 | ボタン・キー・スロット切り替えで寄せる時間（秒） | 即座 |
| `wheelSettleDelay` | 0.15 | ホイールが止まってから戻し始めるまで（秒） | ホイールのたびに即座に戻す |

- `rubber` と `rubberLimit` のどちらかが 0 なら、平行移動は端で止まる。`scaleRubberLimit` が 0 なら、縮小は覆える大きさで止まる。
- OS で「視差効果を減らす」（`prefers-reduced-motion: reduce`）が有効なときは、指定に関係なく
  `friction` / `springPeriod` / `snapDuration` を 0 とみなす（ゴムの抵抗は動きの演出ではないので残す）。
- 負の値・数でない値は既定に戻し、`onError` ではなく開発時の警告（`console.warn`）で知らせる。

## 2. 制約

### 2.1 動きの制約

| 制約 | 中身 |
|---|---|
| 枠は動かない | 編集はクリップ空間（§3.2）で画像に左から掛ける変換だけで表す。クリップ形状は書き換えない |
| 注目領域は動かない | 表示範囲（`viewBox`）は、スロットが決まったときに 1 回だけ求める。操作では変えない。ブラウザのピンチズーム・スクロールも止める（§3.4）。変わるのは外から `slot` を切り替えられたときだけ |
| 画像は相似変換だけ | 拡大縮小・回転・平行移動だけを作り、スキューは作らない（元の `transform` にあるスキューは保つ） |
| 拡大率の範囲 | 読み込み時に対して `[minScale, maxScale]`。覆い制約とぶつかるときは覆い制約を優先する |
| 出力で変わるのは 1 属性 | 各スロットの `<image>` の `transform` だけ（§4.1） |

### 2.2 覆い制約（`cover`）

「枠の内側に画像のない所を作らない」。複雑なクリップパス（凹んだ形、穴、曲線、複数の輪郭、`evenodd`）でも
次の性質で正確に扱える。

> 画像の描画矩形 `D` は画像の座標では軸に沿った矩形なので、クリップの座標では平行四辺形（凸）になる。
> 凸な集合が図形 G を含むことと、G の**凸包**を含むことは同値。
> したがって判定と補正には、枠の凸包の頂点だけを使えばよい。凹み・穴・塗りの規則は結果に影響しない。

- 判定は幾何で行う。画像の透明な画素は考えない。
- 枠は動かないので、凸包はスロットを読み込んだときに 1 回だけ求める（§3.2）。
- 判定と補正の計算は凸包の頂点数に比例するだけで、毎フレーム回せる（§3.5）。
- `cover={false}` のときは制約をかけず、覆えていない間は枠の輪郭を警告色にするだけ。

### 2.3 コンポーネントとしての独立性

どのアプリに置いても同じに動くよう、外の何にも依存せず、外にも何も漏らさない。

| 項目 | 決めたこと |
|---|---|
| 依存 | 実行時の依存は `react` / `react-dom`（peer）だけ。状態管理・CSS フレームワーク・アイコンフォントを持ち込まない。アイコンはインライン SVG |
| 分割 | 解析・幾何・出力は React に依存しない `core`（純粋関数）に置き、React 部分はそれを呼ぶだけ。`core` だけでも Node で使える（CLI もこれを使う） |
| スタイル | 自分の要素にだけ当たる CSS を持つ（クラス名は `sce-` 接頭辞、または CSS Modules）。グローバルなセレクタ・リセットを書かない。色・線は CSS 変数（`--clip-editor-frame` `--clip-editor-warn` `--clip-editor-bg` `--clip-editor-button-*`）で上書きでき、既定値を持つ |
| 大きさ | 親の幅いっぱいに広がり、高さは注目領域の縦横比で決まる（`style` で固定もできる）。画面全体の大きさを前提にしない |
| 文言 | ボタンの文言は `labels` で差し替える。画面に説明文を常駐させない |
| 外との通り道 | 入力はプロップ、出力はコールバックと ref だけ。`window` や `document` にグローバルな値を置かない。`localStorage` などに保存しない。通信しない（画像の取得はブラウザが `<image>` で行う） |
| イベント | リスナーは自分の `<svg>` にだけ付け、外れるときに外す。ページのスクロールやズームを止めるのは自分の上で操作している間だけ |
| 複数の設置 | `id` は `useId()` の接頭辞で区切り、同じページに何個置いても衝突しない |
| 切り替え・保存 | スロットの切り替えの入口と保存ボタンは外が持つ（§3.7）。コンポーネントは自分でスロットを変えない |
| SSR | サーバー描画では空の枠だけを出し、解析はブラウザに入ってから行う（`DOMParser` をサーバーで呼ばない） |

### 2.4 安全性

- 元の SVG は `DOMParser` で解析するだけで、文書に差し込まない。スクリプトやイベント属性は実行されない。
- 描画に使う要素は許可リストで組み直す:
  - `<image>`: `href`（S5 の URL のみ。`javascript:` などは拒否）、`x` `y` `width` `height` `preserveAspectRatio`
  - クリップ形状: `rect` `circle` `ellipse` `polygon` `polyline` `path` の幾何属性（`x` `y` `width` `height` `rx` `ry` `cx` `cy` `r` `points` `d` `transform` `clip-rule`）
- 飾りの文脈表示（§3.3）は画像として読み込むので、中のスクリプトは動かない。
- 出力は元の文書を複製して `transform` 属性を書き換えるだけなので、元にあったものは良くも悪くもそのまま残る（サニタイズはこのコンポーネントの責務ではない）。

## 3. 処理の流れ

### 3.1 全体

```
svg 文字列
  │
  ├─ ① 契約の検査 lintDocument ───── エラー → onError、描画面の代わりに 1 行のメッセージ
  │
  ├─ ② 解析 parseClipDocument ─────── スロットごとに 座標の変換・画像・枠の形・凸包 → onLoad
  │
  ├─ ③ 注目領域 focusRect ─────────── slot で選んだスロットの viewBox（固定）
  │
  ├─ ④ 描画 ───────────────────────── 半透過の画像 ＋ 枠で切り抜いた画像 ＋ 枠の輪郭
  │
  ├─ ⑤ 操作 ───────────────────────── 指・マウス・キー → 生の行列 M_raw
  │      │
  │      └─ ⑥ ゴム・慣性・ばね ─────── M_raw → 見せる行列 M_view（毎フレーム）→ onChange
  │
  └─ ⑦ 確定 ───────────────────────── 止まったら履歴に積み、serialize → onCommit
```

### 3.2 読み込み（①〜③）

#### 座標系

行列は SVG の `matrix(a b c d e f)` の 6 要素で表し、点 `p` への適用を `X·p` と書く。

| 記号 | 空間 | 定義 |
|---|---|---|
| R | ルート | ルート `<svg>` の `viewBox` 座標。出力の座標系そのもの |
| C | クリップ空間 | スロットの `<g>` のユーザー空間。枠はここで定義され、動かない |
| I | 画像 | `<image>` の `x` / `y` / `width` / `height` が置かれる空間 |
| S | スクリーン | ブラウザの CSS ピクセル（ポインタの位置） |

```
p_R = K · p_C          K = ルート直下からスロットの <g> 自身までの transform の積
p_C = M · p_I          M = <image> の transform（編集で変わるのはこれだけ）
p_C = Q · T_k · p_枠   Q = <clipPath> の transform、T_k = k 番目の子の transform
p_S = V · p_R          V = エディタの <svg> の getScreenCTM()
```

`K` / `Q` / `T_k` / `M` は `transform` 属性の文字列を解析して求める。契約（A1・A2・D4）によって、属性だけで座標が決まる。
`getCTM()` に頼らないので、解析は Node だけで単体テストできる。

#### 解析の結果

```ts
interface ClipDocModel {
  doc: Document;                 // 元文書（出力の土台。描画には使わない）
  rootViewBox: Rect;
  slots: ClipSlot[];             // 文書順
  warnings: LintIssue[];
}

interface ClipSlot {
  name: string;
  path: number[];                // スロット <g> への子インデックス列
  K: Matrix;
  M0: Matrix;                    // 読み込み時の <image> の transform
  image: { href: string; hrefAttr: 'href' | 'xlink:href';
           x: number; y: number; width: number; height: number; preserveAspectRatio: string };
  clip: { id: string; Q: Matrix; shapes: ClipShape[]; bboxC: Rect; hullC: [number, number][] };
}
```

#### 枠の凸包（`hullC`）

1. 枠の子をすべて「直線と 3 次ベジェ」の列にする。
   - `rect`: 4 辺。`rx` / `ry` があれば角を 1/4 楕円のベジェにする。
   - `circle` / `ellipse`: 1/4 ずつ 4 本のベジェ。
   - `polygon` / `polyline`: 直線（クリップでは `polyline` も閉じた図形として塗られる）。
   - `path`: `d` の全コマンド（`M L H V C S Q T A Z`、相対・絶対）を読む。2 次ベジェは 3 次へ、円弧は 90° 以下ずつ 3 次ベジェへ直す。
2. 各子の `transform` と `Q` を、端点と制御点に掛けて C 空間へ移す。
3. 各ベジェを、制御点と弦の距離が ε 以下になるまで二分割する。集める点は直線の端点と、分割後の**制御点すべて**。
   ベジェ曲線は制御点の凸包の中にあるので、求めた凸包は真の凸包を必ず含み（覆い不足を起こさない）、はみ出しは ε 以下。
   ε は枠の外接矩形の対角線の 0.1%。
4. Andrew の monotone chain で凸包を求める。

#### 注目領域（`viewBox`）

1. 凸包の頂点を `K` で R に写し、その外接矩形 `F` を取る（スロットや祖先が回転していても枠全体が入る）。
2. `F` の各辺に `focusPadding` の余白を足し、`viewBox` にして `preserveAspectRatio="xMidYMid meet"` で表示する。

向きはルート座標のまま（出力と同じ向き）。エディタの表示サイズが変わっても `viewBox` は同じなので、注目領域は動かない。

### 3.3 描画（④）

```tsx
<svg viewBox={focus} preserveAspectRatio="xMidYMid meet" style={{ touchAction: 'none' }}
     role="application" aria-label={labels.region} tabIndex={0}>
  <defs>
    <clipPath id={`${uid}-clip`} clipPathUnits="userSpaceOnUse" transform={Q}>{枠の形}</clipPath>
  </defs>
  {/* 任意: 下の飾り */}
  <g transform={K}>
    <image {...image} transform={M_view} opacity={outsideOpacity} />      {/* ① 画像全体（半透過） */}
    <g clipPath={`url(#${uid}-clip)`}>
      <image {...image} transform={M_view} />                            {/* ② 枠で切り抜いた画像（不透明） */}
    </g>
  </g>
  {/* 任意: 上の飾り（半透過） */}
  <g transform={K}><g transform={Q} fill="none" pointerEvents="none">
    {/* ③ 枠の輪郭。点線、太さは画面上で一定。覆えていない間は警告色 */}
  </g></g>
  <rect {...focus} fill="transparent" />                                  {/* ④ 当たり判定: 全面 */}
</svg>
```

| 領域 | 見え方 |
|---|---|
| 枠の内側 | ② が不透明で重なり、出力と同じ見え方（枠に覆いがない = 透明） |
| 枠の外で画像がある所 | ① だけが `outsideOpacity` で見え、画像全体の位置関係が分かる |
| 画像がない所 | 背景（市松模様、または飾り） |

- ② のクリップは ① と同じ `K` の中に置くので、クリップの座標は元の SVG とまったく同じ意味になる。
- 枠の外を掴んでも画像が動くよう、当たり判定は注目領域の全面に置く。

#### 飾りの文脈表示（`context="layers"`）

作業中のスロットを除いた元の SVG を、**スロットの前と後ろ**に分けて描く（スロットが閉じた部品なので文書順で切り分けられる）。

1. 文書を 2 つ複製し、どちらでも作業中のスロットを取り除く。
2. 下の層: スロットより後ろの要素を（祖先を除いて）取り除く。上の層: スロットより前の要素を取り除く。
3. 資源の要素（`<defs>` の中身、`<clipPath>` / `<mask>` / `<pattern>` / グラデーション / `<filter>` / `<style>` など）は両方に残す。
4. 他のスロットの `<image transform>` は現在の値に差し替える（他の画像の編集結果が見える）。
5. それぞれを `data:image/svg+xml` にして `<image>` として描く。上の層は `contextAboveOpacity` で半透過にする。

画像として読み込んだ SVG は外部の資源を読めない（ブラウザの仕様）ので、飾りの外部 URL の画像は文脈に出ない（警告）。

### 3.4 操作（⑤）

#### 入力と変換

すべての操作は、C 空間で画像に左から掛ける変換 Δ として `M_raw ← Δ · M_raw_start` を作る。
ポインタの位置は `p_C = K⁻¹ · V⁻¹ · p_S` で C 空間に直す。

| 操作 | Δ |
|---|---|
| 1 本指 / 左ドラッグ（a₀ → a₁） | `T(a₁ − a₀)` |
| 2 本指（a₀,b₀ → a₁,b₁） | `T(a₁) · R(θ) · S(s) · T(−a₀)`。`s = |b₁−a₁| / |b₀−a₀|`、θ は 2 本を結ぶ線の角度の差。2 本の指の下の点が指に貼り付いたまま動く |
| ホイール / トラックパッドのピンチ | ポインタ位置 p で `T(p) · S(exp(−deltaY · 0.0015)) · T(−p)` |
| Shift + ホイール | p で `R(deltaY · 0.2°)` |
| 矢印キー | 注目領域の幅の 1%（Shift で 10%）だけ平行移動 |
| `+` / `-` ・ `[` / `]` | 枠の中心で ×1.1 / ÷1.1 ・ −1° / +1°（Shift で 15°） |

ボタン列（`toolbar`）:

| ボタン | 動き |
|---|---|
| 縮小 / 拡大 | 枠の中心で ÷1.1 / ×1.1 |
| 左に 90° / 右に 90° | 枠の中心で回転 |
| 枠に合わせる | 今の回転のまま、枠を覆う最小の大きさにして中央に置く |
| 元に戻す / やり直す | §3.6 |
| リセット | 読み込み時の値に戻す |

#### 状態遷移

```
            1本目が触れる                   2本目が触れる
   idle ────────────────────▶ pan ──────────────────────▶ pinch
    ▲                          │  ▲                          │
    │                          │  └──── 2本→1本（残った指で基準を取り直す）
    │      最後の指が離れる     ▼
    │                   ┌─ 速く弾いた（pan のみ）──▶ momentum ──┐
    │                   │                               │ 端を越えた / 遅くなった
    │                   └─ それ以外 ──────────────────▶ settle ◀┘
    │                                                      │ 止まった
    └──────────────────────── commit（確定）◀──────────────┘

   momentum / settle 中に触れる → アニメーションを止め、見えている位置から pan を始める
```

- 指の本数が変わるたびに基準を取り直す（`M_raw_start ← M_raw`、開始点 ← 現在の指の位置）。指を足し引きしても画像が跳ねない。
- 3 本目以降の指は無視する。`setPointerCapture` で枠の外に出ても追従し、`pointercancel` は慣性なしで離したのと同じに扱う。
- 更新は `requestAnimationFrame` で 1 フレーム 1 回にまとめる。
- ページのズーム・スクロールを止める: `touch-action: none`、`wheel` を `{ passive: false }` で受けて `preventDefault()`、Safari の `gesturestart` も止める。
- 拡大率（`sqrt(|det M|)` の読み込み時との比）を `[minScale, maxScale]` に詰める。
- 2 本指の回転は、`rotationSnap` を与えると 90° の倍数 ± その角度で吸着する。

### 3.5 ゴム・慣性・ばね（⑥）

ジェスチャが動かすのは**生の行列 `M_raw`**（指に正確に追従する値）で、画面に描くのは
**見せる行列 `M_view`**。端の内側では両者は等しく、端を越えた分だけ `M_view` が手前に留まる。
これが、指に対して画像が遅れてついてくる「抵抗」になる。

#### 覆うための補正

`coverCorrection(slot, M) → { k, u }` は、`M` から覆える位置へ移すための最小の補正を返す。
画像の描画矩形を `D = [x₀, x₁] × [y₀, y₁]`（I 空間。`preserveAspectRatio` の `none` / `slice` は矩形そのもの、`meet` は画像の元の大きさから求めた内側の矩形）とする。

1. 凸包の頂点を I 空間に写し（`q_i = M⁻¹ · h_i`）、その外接矩形 `[qx₀, qx₁] × [qy₀, qy₁]` を取る。
   `D` が軸に沿った矩形なので、「全頂点が `D` に入る」は「この外接矩形が `D` に入る」と同じ。
2. 拡大: `k = max(1, (qx₁−qx₀)/(x₁−x₀), (qy₁−qy₀)/(y₁−y₀))`。今の回転のままで覆える最小の拡大率。枠の中心で掛けて 1 をやり直す。
3. 平行移動（I 空間）: `u_x = clamp(0, qx₁ − x₁, qx₀ − x₀)`、`u_y` も同様。今の位置から一番近い、覆える位置。

「枠に合わせる」は同じ手順で、2 の `k` を 1 未満も許し、3 を中央寄せにしたもの。

#### 抵抗（端を越えている間）

ゴムの関数（越えた量 d → 見せる越え量）:

```
rubber(d, L) = L · (1 − 1 / (d · c / L + 1))      c = motion.rubber
               c = 0 または L = 0 のときは 0
```

d が小さいうちはほぼ `c·d`、大きくなるほど L に近づいて止まる。

| 成分 | 越えた量 d | 上限 L | 見せる補正 |
|---|---|---|---|
| 平行移動 | `|u|`（I 空間） | 枠の短辺を I 空間に写した長さ × `rubberLimit` | `u · (1 − rubber(|u|, L) / |u|)` |
| 縮めすぎ | `ln k` | `ln(1 + scaleRubberLimit)` | 枠の中心で `exp(ln k − rubber(ln k, L))` 倍 |

`M_view` は `M_raw` に、拡大 → 平行移動の順で見せる補正をかけたもの。

**越えられないとき（見せる越え量が常に 0）**: 補正を全部かけた `M_view` は端で止まる。このまま `M_raw` が端の外へ
進み続けると、指を戻しても `M_raw` が端の内側に戻るまで画像が動かない（遊びが生じる）。そこで補正が効いた
フレームでは基準を取り直し（`M_raw_start ← M_view`、開始点 ← 今の指の位置）、指を戻した瞬間に画像が動くようにする。

#### 回転で覆えなくなったとき（`rotationCover`）

回転すると、同じ大きさのままでは枠を覆えなくなることがある。その分の拡大をどう見せるかを選べる。

| 値 | 動き |
|---|---|
| `'rubber'`（既定） | 縮めすぎと同じに扱う。回転中は画像が枠の内側に少し欠けて見え（ゴム）、離すとばねで拡大して覆う |
| `'grow'` | 回転中も常に覆う。回転に伴って画像が即座に拡大し、回転を戻すと元の大きさへ戻る |

`'grow'` の計算: ジェスチャ開始時の行列に、今の回転だけを枠の中心で掛けたもの `M_rot` を作り、
`coverCorrection(M_rot).k` を「回転で要る拡大」として `M_raw` に即座に掛ける（ゴムを通さない）。
残り（指で縮めすぎた分・ずらした分）は通常どおりゴムで見せる。回転を戻せば `M_rot` の要る拡大も 1 に戻るので、
大きさは元に戻る。

#### 慣性（momentum）

- 1 本指で離したとき、直近 100ms の指の位置（C 空間）から速度 `v` を求め、`|v|` が `flingSpeed` 以上なら momentum に入る。
  2 本指から離したとき・ホイール・キー・ボタンでは慣性を付けない。`friction = 0` なら入らない。
- 毎フレーム `M_raw ← T(v·dt) · M_raw`、`v ← v · exp(−dt / friction)`。描くのは常に `M_view` なので、端を越えた分はゴムで縮んで見える。
- 端を越えていて `v` が外向き（越え量を増やす向き）になったか、`|v|` が `flingSpeed` の 1/10 を下回ったら settle へ移る。
  端を越えて移るときは、その速度をばねの初速として引き継ぐ（端に当たって跳ね返る見え方になる）。

#### ばね（settle）

- 目標 `M*` は `M_view` に覆うための補正を全部かけたもの（`cover={false}` なら `M_view` そのもの）。
- 平行移動（I 空間の 2 次元）と拡大率（対数）を、それぞれ臨界減衰のばねで目標へ寄せる:
  `x(t) = (x₀ + (v₀ + ω·x₀)·t) · e^(−ω t)`、`ω = 2π / springPeriod`。x は目標からのずれ。`springPeriod = 0` なら即座に目標へ。
- ずれが 0.5 画面 px 未満で速さが十分小さくなったら目標に合わせて止め、確定する。

#### その他の入力

- ホイール: 1 回ごとに `M_raw` を動かし、ゴムも効く。最後のホイールから `wheelSettleDelay` 秒で settle に入る。
- キー・ボタン: 結果に覆うための補正を全部かけ、`snapDuration` 秒で寄せてから確定する（ゴムは使わない）。

#### 割り込み

- momentum / settle 中に触れたら、アニメーションを止め、**見えている位置から**ジェスチャを始める。
  このとき `M_raw` は、今の見せる越え量に `rubber` の逆関数 `L·(1/(1 − r/L) − 1)/c` をかけて「この見え方になる生の位置」に置き直す。掴んだ瞬間に画像が跳ねない。
- `slot` や `svg` が変わったら、アニメーションを目標まで飛ばして確定してから切り替える。

### 3.6 履歴（⑦）

- 確定（画像が止まったとき、ボタン、キー操作の区切り）ごとに `{ before, after }` を**スロットごと**の履歴に積む。上限はスロットごとに 100。
- 元に戻す・やり直すは、作業中のスロットの履歴にだけ効く。コンポーネントが自分でスロットを変えることはない。
- 連続するキー操作は 500ms 以内なら 1 つにまとめる。
- `svg` が変わったら全スロットの履歴を捨てて読み直す。`slot` が変わっても履歴は捨てない。

### 3.7 スロットの切り替え

切り替えの入口（一覧・タブ・サムネイル・図の上でのクリックなど）は**コンポーネントの外**が持つ。
外は `onLoad` で受け取るスロットの一覧（名前と枠のルート座標での外接矩形）を使って入口を作り、選ばれた名前を `slot` に渡す。

```
┌ 外（アプリ）────────────────┐
│ スロットの入口・保存ボタン    │── svg, slot ──────────────▶ SvgClipImageEditor
│                               │◀── onLoad({ slots }) ─────┤
│                               │◀── onCommit(svg, { slot, M }) ─┤
└───────────────────────────────┘
```

`slot` が変わったとき:

1. 動いている慣性・ばねを目標まで飛ばして、前のスロットを確定する。
2. 新しいスロットの注目領域を求め、`viewBox` を `snapDuration` 秒で寄せる。
3. 新しいスロットの値は保持している値（なければ読み込み時の値）、履歴はそのスロットのもの。
4. 文脈表示を出していれば、上下の層を作り直す。

初版で外から切り替えを使わなくても、状態・履歴・コールバックは最初からスロット名をキーにしておく。

### 3.8 エラー

解析は例外を投げず `{ ok: false, code, message, issues? }` を返す。コンポーネントは描画面の代わりに 1 行のメッセージを出し、`onError` を呼ぶ。

| code | 条件 |
|---|---|
| `parse_error` | XML として読めない、ルートが `<svg>` でない |
| `contract_violation` | 契約の検査でエラーがある（`issues` に一覧） |
| `no_slot` | スロットが 1 つもない、または `slot` で指定した名前がない |
| `singular_transform` | 座標の変換が逆行列を持たない（幅 0 の scale など） |
| `empty_clip` | 枠の面積が 0（凸包が 3 点未満） |

## 4. 出力

### 4.1 SVG

`serialize(model, transforms, { precision, outputTransform })`:

1. 元の文書を複製する。
2. 各スロットの `<image>` の `transform` を、そのスロットの現在の値で書き換える（値のないスロットは触らない）。
   - `'matrix'`（既定）: `matrix(a b c d e f)`。`a`〜`d` は小数 6 桁、`e` `f` は `precision` 桁で丸め、末尾の 0 を落とす。
   - `'decomposed'`: スキューがなければ `translate(e f) rotate(θ) scale(s)`。スキューが残る場合は `matrix`。
   - 結果が恒等なら属性を消す。
3. 文字列にする。XML 宣言・DOCTYPE・ルート直前のコメントは元にあれば残す。

**変わらないもの**: ルートの `viewBox` / `width` / `height`、祖先・スロットの `<g>` の `transform`、`<clipPath>`、
`<image>` の `x` / `y` / `width` / `height` / `href` / `preserveAspectRatio`、飾りを含む他のすべての要素。
出力は元と同じ座標系で、変わるのは「画像のどこが枠に入るか」だけ。出力も契約を満たしたままなので、もう一度読み込める。

#### 例

入力:

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 800 600" width="800" height="600">
  <defs>
    <clipPath id="hero-clip" clipPathUnits="userSpaceOnUse">
      <path d="M200 150 H600 V450 H420 Q400 380 380 450 H200 Z"/>  <!-- 下辺に切り欠きのある枠 -->
    </clipPath>
  </defs>
  <rect width="800" height="600" fill="#f4f1ea"/>
  <g data-clip-slot="hero" clip-path="url(#hero-clip)">
    <image href="photo.jpg" x="0" y="0" width="1200" height="800"
           preserveAspectRatio="xMidYMid slice"
           transform="matrix(0.5 0 0 0.5 100 100)"/>
  </g>
  <text x="400" y="540" text-anchor="middle">見出し</text>   <!-- 飾り: 契約の外なので自由 -->
</svg>
```

画像を 1.1 倍にして 15° 回し、少し寄せた後の出力（`<image>` の `transform` だけが変わる）:

```xml
    <image href="photo.jpg" x="0" y="0" width="1200" height="800"
           preserveAspectRatio="xMidYMid slice"
           transform="matrix(0.531259 0.14235 -0.14235 0.531259 168.4 6.912)"/>
```

この枠の凸包は外側の矩形の 4 隅になる（切り欠きは凹みなので凸包に影響しない）。

### 4.2 コールバック

| コールバック | いつ | 渡すもの |
|---|---|---|
| `onLoad` | 読み込みが終わったとき | スロットの一覧（名前・枠のルート座標での外接矩形）、警告 |
| `onChange` | 画像が動いている間、毎フレーム（慣性・ばねの間も） | 見せている行列 `M_view`、スロット名 |
| `onCommit` | 画像が止まって確定したとき（1 つの操作につき 1 回） | 全スロットを反映した SVG 文字列、スロット名と確定した行列 |
| `onError` | 読み込めなかったとき | エラーの種類と、契約違反なら一覧 |

`onCommit` に渡す行列は、`cover` が有効なら必ず覆い制約を満たす。保存はこのコンポーネントの責務ではなく、外が `onCommit` か `getSvg()` で受け取って行う。

## 6. テスト

| 種類 | 内容 |
|---|---|
| 単体（Node + jsdom） | 行列: `transform` の各関数と合成順、逆行列、分解の往復 |
| 単体 | 契約の検査: 規則ごとに守る例と破る例の対。飾りを大量に足した文書（テキスト・CSS アニメーション・印のないクリップ付き画像・別のクリップ）でエラーが出ないこと |
| 単体 | 取り込み: 各書き換えの前後で、画像の 4 隅と枠の凸包のルート座標が一致すること |
| 単体 | パス: 全コマンドの相対・絶対、円弧の退化（半径 0・端点一致）、暗黙の繰り返し |
| 単体 | 凸包: 矩形・円・角丸・凹多角形・穴のある `evenodd`・ベジェ・円弧で、(a) 真の図形の標本点がすべて凸包に入る、(b) 凸包の各頂点が真の図形から ε 以内 |
| 単体 | 覆うための補正: 補正後に凸包の全頂点が D に入ること。覆っているときは変えないこと。拡大率が二分探索で求めた最小値と一致すること |
| 単体 | ゴム・慣性・ばね（偽の時計でフレームを進める）: 越え量 0 で `M_view = M_raw`。見せる越え量が単調に増えて L を超えない。ばねが有限時間で収まり、収まった値が覆い制約を満たす。割り込みで `M_view` が連続。**定数をすべて 0 にすると、端で即座に止まり、指を戻した瞬間に動き、慣性もアニメーションもない** |
| 単体 | `rotationCover='grow'`: 回転中の全フレームで覆い制約を満たし、回転を戻すと拡大率が元に戻ること |
| 単体 | 文脈の切り分け: 下の層に前の要素だけ、上の層に後ろの要素だけが残り、資源の要素は両方に残ること |
| 単体 | 出力: 変更なしなら入力と文字列として同一。`transform` 以外が変わらないこと。出力が再び契約の検査を通ること |
| 部品（Testing Library） | ドラッグ・2 本指・ホイールで `onChange` / `onCommit` が期待の行列を返すこと。`viewBox` が操作で変わらないこと。`slot` を変えると前のスロットが確定され、値と履歴が保たれること |
| 独立性 | 2 つのエディタを同じページに置いて `id` が衝突しないこと。外れた後に `window` / `document` にリスナーが残らないこと。サーバー描画で例外が出ないこと |
| 実機（Playwright） | 例の SVG で操作前後のスクリーンショットを撮る。出力 SVG を別ページで描き、エディタの枠内の画素と一致すること |

## 付録 A. 採らなかった設計

| 案 | 採らなかった理由 |
|---|---|
| クリップ形状を逆向きに動かす（画像を固定して枠を動かす） | 出力でクリップを書き換えることになり、共有された `<clipPath>` を壊す |
| `<canvas>` で描いて合成する | 外部 URL の画像で CORS の制約を受け、SVG のベクタ性も失う。SVG のまま描けば出力と寸分違わず見える |
| 元の SVG 文字列を DOM にそのまま差し込む | スクリプトやイベント属性を実行しうる |
| 対象画像を構造から推測する（「クリップのかかった最初の `<image>`」など） | 飾りにクリップ付き画像が 1 つ増えただけで対象がずれる |
| 枠の外接矩形の 4 隅で覆い制約を判定する | 円や斜めの枠で必要以上に拡大する。凸包なら正確 |
| 切り替えの入口をコンポーネントに持たせる | 入口の形（一覧・タブ・図の上でのクリック）はアプリごとに違う。履歴をスロットごとにして、コンポーネントが自分でスロットを変えないようにした |

## 付録 B. 契約検査 CLI（設計のみ、実装しない）

テンプレートの SVG をリポジトリで管理する場合に、契約違反を作った時点で CI で落とすための CLI。
実装するときは `core` の `lintDocument` をそのまま呼ぶ薄い入口にし、規則の判定を CLI 側に書かない
（ブラウザと CLI で結果が分かれないように）。

```
svg-clip-lint [options] <file|glob>...

  --format text|json      出力の形式（既定 text）
  --strict                警告もエラーとして扱う
  --require-slot <name>   指定した名前のスロットがなければエラー（複数回指定できる）
  --quiet                 エラーだけを出す
```

| 項目 | 決めたこと |
|---|---|
| 実行環境 | Node。文書は jsdom で作り、CSS は css-tree で規則に分けて `lintDocument` に渡す（jsdom は `CSSStyleSheet.replaceSync` を持たないため。ブラウザでは `CSSStyleSheet` を使う） |
| text の出力 | 1 違反 1 行: `<file>:<location> <severity> <rule> <message>`。例: `card.svg:/svg/g[2] error S3 スロット hero の子が <image> 1 つではない（<rect> がある）` |
| json の出力 | `[{ file, issues: LintIssue[] }]` |
| 終了コード | 0 = エラーなし（警告だけは 0）、1 = エラーあり（`--strict` なら警告も）、2 = 引数の誤り・読めないファイル・XML として読めない |
| 対象 | 引数のファイルと glob。ディレクトリは `**/*.svg` として辿る |
| しないこと | 自動修正（取り込みの書き換え）は持たない。取り込みは人が結果を確かめる操作なので、一括にしない |

## 付録 C. モジュール構成

サンプル実装（`samples/svg-clip-image-editor/src/`）の構成。

```
core/                       React に依存しない純粋関数（Node でも動く）
  matrix.js                 行列: 合成・逆・適用・transform の解析と書式
  css.js                    CSS をセレクタとプロパティ名に分ける（D4 用）
  dom.js                    文書を辿る小道具（ブラウザと jsdom の両方で動くものだけ）
  lint.js                   契約の検査 lintDocument(doc, parseCss)
  parse.js                  解析 parseClipDocument → ClipDocModel
  path.js                   パスの解析（直線と 3 次ベジェへ）
  geometry.js               凸包・描画矩形・注目領域
  cover.js                  覆うための補正 coverCorrection
  motion.js                 ゴム・慣性・ばねの 1 ステップ（時刻を引数で受ける）
  serialize.js              出力（元の文字列の <image> 開始タグの transform だけを継ぎ当てる）
react/
  engine.js                 動きと履歴（ジェスチャ・ゴム・慣性・ばね・スロットごとの値）。React にも DOM にも依存しない
  SvgClipImageEditor.js     描画とイベントの受け付け。スタイルはインラインと CSS 変数だけ
```

動き（`engine.js` と `motion.js`）は時刻と `requestAnimationFrame` を外から受け取り、偽の時計で単体テストする。
出力は DOM を `XMLSerializer` で文字列に戻さず、元の文字列を継ぎ当てる（引用符・空白・宣言を元のまま残すため）。
未実装の `adopt`（取り込み）と `context`（文脈の層）は、置くなら `core/` に足す。
