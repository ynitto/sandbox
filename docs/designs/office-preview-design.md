# office-preview 設計

docx / xlsx / pptx / pdf のプレビュー画像を、Electron の main プロセスで外部依存なしに作るモジュール
（`tools/office-preview/`）の設計。使い方と対応範囲は [README](../../tools/office-preview/README.md) にある。

## 1. 方針

| 決めたこと | 理由 |
|---|---|
| Office も LibreOffice も呼ばない | どちらも PC ごとに入っているとは限らない（環境依存）。LibreOffice の同梱は数百 MB |
| ZIP と XML は自前で読む（`zip.js` / `xml.js`） | OOXML に要るのは中央ディレクトリ＋ deflate と、DTD なしの要素・属性・文字だけで、どちらも 200 行に収まる。Node の `zlib` で足りる |
| 文書を HTML に組み直し、Chromium に描かせる | 文字の折り返し・フォントの代替・日本語の組版・SVG・グラデーションを自前で実装しなくてよい。Electron には描画エンジンが最初からある |
| 1 ページ目・1 枚目・1 シートだけを描く | プレビューの用途では十分。自動の改ページを計算しない（後述） |
| 変換（`toHtml`）は Electron なしで動く | 単体テストを node だけで回せる。見た目の確かめは `scripts/render.js` と実機テストで行う |

## 2. 流れ

```
ファイル ─ ZipArchive ─ OoxmlPackage ─┬─ docx.js ─┐
          （目次だけ読む） （部品・関係・テーマ）├─ xlsx.js ─┼─ HTML（CSS px の固定の大きさ）
                                    └─ pptx.js ─┘        │
                                                         ▼
                  一時ファイル ─ 隠しウィンドウ（offscreen, JS 停止, 専用セッション）─ capturePage ─ PNG / JPEG
```

- 種類は `_rels/.rels` の officeDocument が指す部品のルート要素（document / workbook / presentation）で決める。
- 画像は `data:` URI で HTML に埋める。SVG の図は Office 2016 の拡張（`asvg:svgBlip`）に本体があり、
  `a:blip` の `r:embed` は PNG の代わりなので、拡張を先に見る。EMF / WMF は Chromium が描けないので捨てる。
- 出力の大きさは CSS の `zoom` で合わせる（ビットマップを縮めない）。ウィンドウは offscreen にして画面の大きさに縛られないようにする。
- HTML は `data:` URL でなく一時ファイルで渡す。URL は IPC で 2 MB までしか運べず、画像を埋めた HTML はそれを超える。

## 3. 形式ごとの要点

### 3.1 docx

- 書式の優先順位: 文書の既定（docDefaults）→ 表のスタイルの段落書式（表の中だけ）→ 段落スタイル（basedOn を根からたどる）
  → 段落番号の段の書式 → 段落の直接の書式。文字は段落スタイル → 文字スタイル → 直接。
- 段落の前後の間隔は `padding` で表す。`margin` だと CSS で隣の段落と相殺されるが、Word は足し合わせる。
  「同じスタイルの段落の間に間隔を追加しない」（contextualSpacing）は前後の段落のスタイルを見て落とす。
- 行グリッド（`w:docGrid type="lines"`）がある文書は、1 行の高さを行送りの整数倍にする。日本語版 Word の既定で、
  これを無視すると行間が詰まって見える。行の高さは、その段落でいちばん大きい文字で決まる。
- 改ページ（`w:br type="page"`、pageBreakBefore、次ページから始まるセクション区切り）で打ち切る。
  自動の改ページは計算せず、用紙の高さで切り取る。
- ページ基準で位置が決まる浮動の図（anchor の relativeFrom が page / margin）は、本文の流れから外してページに重ねる。
  段落基準のものは位置を計算できないので、行の中に float で置く。
- フィールドは結果（separate〜end）だけを描き、命令（instrText）は描かない。

### 3.2 xlsx

- 列幅の単位は「既定のフォントの数字 1 文字の幅」。Calibri 11pt なら 7 px、游ゴシック 11pt なら 8 px として換算する。
- 表示形式は Excel の書式記号を自前で解釈する（セクション、`[Red]` などの色、`[$¥-411]`、日付・時刻・経過時間、
  桁区切り、%、指数）。1900 年をうるう年とみなす Excel の誤り（シリアル値 60 = 1900/2/29）に合わせる。
- 文字列は右隣のセルが空ならはみ出して描く（td の中の div を `overflow:visible` にする）。数値ははみ出さない。
- 4 MB を超えるシートの XML は、2000 行で切ってから木にする（`</sheetData>` より後ろの結合などは残す）。
  画面に入るのは数十行なので、10 万行のシートでも読むのは先頭だけになる。
- 開くシートは workbookView の activeTab（Excel が開いたときに出るシート）。隠しシートなら最初の見えるシート。

### 3.3 pptx

- 位置（xfrm）・塗り・線・本文の枠（bodyPr）は、スライド → レイアウトの同じプレースホルダー（idx、無ければ type）
  → マスターの同じ type のプレースホルダーの順に引き継ぐ。
- 文字の書式の優先順位: 文字の直接の書式 → 段落 → 図形の lstStyle → レイアウトのプレースホルダー → マスターの
  プレースホルダー → マスターの txStyles（title / body / other）→ presentation の defaultTextStyle。
  図形のスタイルの文字色（`p:style/a:fontRef`）は、図形自身の書式より弱く、マスターより強い。
- 塗り・線をテーマの書式から引く（fillRef / lnRef / bgRef）ときは、その要素の色を phClr に差し込む。
- 描く順: マスターのプレースホルダー以外の図形 → レイアウトの同じもの → スライド。showMasterSp="0" で前の段を飛ばす。
  レイアウトとマスターのプレースホルダーは「枠の見本」なので描かない。
- 表のスタイルは tableStyles.xml にあればそれを使い、無ければ組み込みの「中間スタイル 2」（既定の表のスタイルと
  アクセント違い）だけを持っておく。PowerPoint は組み込みのスタイルをファイルに書かないことが多い。
- グラデーションの線は SVG の `linearGradient` を `userSpaceOnUse` で引く。水平・垂直の線は外接矩形の高さか幅が 0 で、
  `objectBoundingBox` だと何も描かれない。
- SmartArt は PowerPoint が保存した描画結果（diagramDrawing）を、枠の位置へずらして描く。

### 3.4 pdf

PDF の描画（PDFium）を自前で持つのは割に合わないので、Electron に組み込みの PDF ビューアに描かせる。
ビューアは画像を返す API を持たないので、表示した画面を撮ってページを切り出す。

- URL の断片で表示を決める: `#page=N&toolbar=0&navpanes=0&view=Fit`。スクロールバーは消せない。
- 窓はページより十分横長に取る（ページの大きさが読めれば幅 1.5 倍、読めなければ A4 の高さで幅 3 倍）。
  ビューアはページを高さで合わせて中央に置くので、左右に必ず背景が残る。窓の形でビューアの余白の付け方が
  変わり、背景の色の読み取りやページの判定が揺れたため、この配置に固定した。
- ページの切り出し（`findPageBox`）: 背景の色は左端の列でいちばん多い色（ビューアの版で変わりうるので決め打ちしない）。
  背景より最大 20 段ほど暗い無彩色はページの影とみなす。右端 24 px はスクロールバー。背景と違う画素が幅の 15% 以上
  並ぶ行のうち、上から最初のかたまりを 1 ページ目とする（下に次のページが見えていても切り離す）。
- 描き終わりの判定: ビューアは粗い絵を先に出してから細かく描き直すので、続けて撮った 2 枚のページ部分が
  同じになるまで撮り直す。
- 失敗の見分け: パスワードの入力や読み込み失敗は、ビューアが角の丸い案内の箱を出す。ページの四隅は角ばっているので、
  隅が背景の色なら案内とみなし、3 回続いたら止める。ファイルに `/Encrypt` があれば `ENCRYPTED_OR_LEGACY`、
  無ければ `BROKEN`。8 秒たってもページが出なければ同じく止める。
- ページの大きさは最初に見つかった `/MediaBox`（と `/Rotate`）から推す。圧縮されたオブジェクトの中にしかない PDF では
  読めないので、そのときと 2 ページ目以降は大きさを知らないものとして窓を取る。出力の高さは切り出したページの縦横比で決める。

## 4. 安全

文書は信頼できない入力として扱う。

| 脅威 | 対策 |
|---|---|
| 文書の文字列が HTML として解釈される | 本文はすべて `escapeHtml`。色は 6 桁の 16 進（`safeHex`）か、RGB に直して書き直したものだけを CSS に入れる。数値は `Number` を通す。フォント名から引用符などを取り除く |
| 描画中のスクリプト・外部への通信 | `javascript: false`・`sandbox`・Node 統合なし。専用のセッションで、自分が書いた一時ファイル・`data:`・PDF ビューアの部品（`chrome-extension:` / `chrome:`）以外の読み込みを止める。HTML 側にも CSP（`default-src 'none'; img-src data:`）を入れる。PDF のウィンドウはビューアがスクリプトで動くので `javascript` を止められないが、`sandbox` と Node 統合なし・外への通信の遮断は同じ（Chrome で PDF を開くのと同じ水準） |
| ZIP 爆弾 | 部品ごと 64 MB・合計 256 MB を上限に展開する（`inflateRawSync` の `maxOutputLength`） |
| XML の外部実体（XXE） | DTD を読み飛ばし、実体は 5 つの定義済みと数値参照だけを展開する |
| 描画が終わらない | 時間切れでウィンドウを壊す。同時に開くウィンドウは既定 2 つまで |

## 5. 確かめ方

- `test/convert.test.js` は、テストの中で組み立てた最小の docx / xlsx / pptx（`test/helpers.js`）を HTML にして、
  継承・書式・表示形式・打ち切りを確かめる。バイナリのテスト用ファイルはリポジトリに置かない。
- `test/pdf.test.js` は、ビューアの画面を模した画像でページの切り出し（影・スクロールバー・次のページ・黒いページ・
  角の丸い案内）を確かめる。
- `test/electron.test.js` は Electron を起動して 4 形式を同時に PNG にし、大きさと画素の色を確かめる。PDF はテストの中で
  組み立てた 2 ページ（横長の赤・縦長の青）を描き、壊れた PDF が `BROKEN` になることも見る。
  electron のバイナリか画面が無い環境（CI）では飛ばす。
- 見た目は、python-docx / openpyxl / python-pptx で作ったファイルと、リポジトリにある実際のスライド
  （`.github/skills/presenter/references/examples/*.pptx`、49 枚）を、LibreOffice で PDF にしたものと並べて比べた。
