深化前 — private implementation が漏れる

深化後 — 一つの transaction test surface

課題 — CAS の成功条件と再試行が 調停 と DirectStateGit の private implementation に分散し、transaction interface が shallow です。

深化案 — fetch・一時 tree・commit・CAS・反映を一つの deep state-repository transaction module に吸収します。

  • locality: CAS 規則を集約
  • leverage: 5呼び出し元・1 interface
  • テストはローカル Git アダプタを使用

責務境界 — transport と adoption

現状 — adoption は一箇所

確認 — board 公示と receipt 回収は transport、digest・revision・証跡の検算と記録は adoption で、正本設計どおり責務が分かれています。

結論 — 採用規則は settle_from_receipt と _adopt_receipt に集約済みです。追加の統合は行いません。

  • locality: 採用規則は verify.py に集約
  • transport と adoption を分離
  • 共通 receipt contract を使用

深化前 — 順序制約が外へ漏れる

深化後 — 一つの完了 transaction

課題 — _settle_task は12引数で可変 accumulator を受け取りませんが、versioned state の確定・同期と、同期対象外のローカル claim 解放の順序が呼び出し側へ残っています。

深化案 — versioned state を1コミットにまとめて同期し、その後にローカル claim を解放する二段階を task settlement interface の内側へ吸収します。

  • locality: 完了処理を1 interfaceへ
  • Git state とローカル claim を分離
  • 順序を1テストで固定

深化後 — 一つの解決済み値

  • 一つの設定 test surface
